# 2026-09-23 音量线上的点按不住：拖不动、⌥ 点删不掉；偏着抓一个点它会跳

## 症状

PR #63（声音编辑）在真实窗口里用合成鼠标事件冒烟时发现，没有发版。

一条带 5 个点的音量线上：

- 拖线（两点之间那一段）、⌥ 点线加点、普通点击选中这一段，都正常。
- 按在**点的正中间**往左拖 10pt：点原地不动。
- ⌥ 点一个点：删不掉，检查器仍显示「5 个点」。

第一处修好之后，同一轮冒烟又发现一处：

- 按在点上纯竖着往上拖 20pt，点的值对了，时间却从 5 秒变成 4.979 秒（少了 1/48 秒，
  24 pt/s 下正好是 0.5pt）。那 0.5pt 就是按下的位置离圆心的距离。点的小圆半径 7pt，
  抓得越偏，按下后第一拍点跳得越远。

## 根因

### 一、点的正中间是命中区里的一个洞

`VolumeLineHitShape` 的路径是这样拼的：先把折线描边成一条 ±5pt 的窄带
（`strokedPath`），再往**同一条路径**里 `addEllipse` 每个点的小圆。

`contentShape` 按**非零环绕数**判断一个点在不在形状里面（`eoFill` 默认 false）。
描边出来的轮廓和圆在重叠处走向相反，环绕数是 +1 −1 = 0，也就是「在外面」。
而点本来就是折线的折点，**每个圆心都压在线上**。于是每个点最该按的正中间，恰好
是命中区里的一个洞，只有小圆伸出窄带的上下两片月牙按得中。

按在洞里的事件落到了底下的块上。块的拖动要把块往左挪，可块已经在 0 秒，挪不动，
所以看起来「什么都没发生」。⌥ 点落在块上也没有反应。

**为什么一直没发现：**

- 自检测的是 `VolumeCurveLayout.handle(at:)`，它按距离判断「离哪个点最近」。它说
  「你按在点 0 上」，但真实的命中测试根本没把事件交给音量线这一层。**纯几何函数
  对，不等于命中测试对**：命中测试用的那个形状，自检从来没有测过。
- 接线守卫只查了「有 `contentShape(VolumeLineHitShape`」，不查它的填充语义。
- 线段中间没有圆，所以拖线、⌥ 点线加点一直是好的。先测的也正是这几项，测完
  就以为整条线都没问题。

### 二、拖点按的是指针的绝对位置

拖一段线用的是相对量（`start.y − location.y`），拖点却直接把点搬到指针底下：
时间用 `timelineTime(atX: location.x)`，值用 `decibels(forY: location.y)`。
点有 7pt 的抓取半径，偏着抓很常见，于是按下后第一拍点就跳到指针那里；纯竖着拖，
时间也会被带偏那一截。

## 修复

- `VolumeCurveLayout.hitPath(vertices:handles:)`（纯值，`VideoEditVolumeCurve.swift`）：
  窄带用 `CGPath.copy(strokingWithWidth:…)` 描出来，小圆单独放一条路径，再用
  `band.union(circles)` 取真正的并集（CoreGraphics 的布尔运算）。`VolumeLineHitShape`
  只负责把它包成 `Path`。
- `VolumeCurveLayout.dragging(_:point:by:pps:height:lockTime:)`（纯值）：从点**自己起手时
  的位置**出发，加上指针的位移。纯竖着拖或按住 ⇧ 时，时间原样留着，不做
  timeline ↔ source 往返，免得浮点误差把它挪动一丁点。视图里的拖点改走它。

## 教训 / 防回归

1. **拼出来的命中形状必须真正取并集。** 往同一条 `Path` 里 `addPath` / `addEllipse`，
   非零环绕数会在重叠处正负抵消出洞，而重叠的地方往往就是用户最想按的地方。要么
   `CGPath.union`，要么拆成几个各自带 `contentShape` 的视图。长期约束写在
   [音量曲线 §三](../architecture/audio-volume-curve.md) 和
   [拖动手势 §1b](../architecture/timeline-drag-gestures.md)。
2. **命中测试要测它真正用的那个形状**（`hitPath.contains`，填充规则也要一样），不能拿
   「离哪个点最近」这种平行的纯几何函数替它作证。
3. **拖一个小把手要用相对位移**：从把手自己的位置加上指针的位移，不能按指针的绝对
   位置去放。把手的抓取半径越大，这个错越明显。
4. 冒烟时先测的几项都过了，不代表同一个控件的其余部分也没问题。这次的洞只在点上，
   线上一个都没有。
