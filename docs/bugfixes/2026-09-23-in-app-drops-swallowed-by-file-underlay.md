# 2026-09-23 滤镜 / 音频库 / 转场卡片拖进时间线没反应：被文件落点吞了

## 症状

ea746c1（从 Finder 拖文件进轨道）之后，从左栏把**滤镜卡片、音频库素材、转场卡片**
拖到时间线的轨道上：没有落点框，松手什么也不发生。点卡片上的 `+` 照常能加。

## 根因

ea746c1 为了让 Finder 的文件拖得进来，在时间线里每一个 App 内的 `.onDrop`
**里面**垫了一层闭包式的文件落点（`mediaFileDropUnderlay`）：滚动内容上（滤镜 /
音频库之前）、主轨那一行上（转场之前）。它依据的模型是：

> App 内拖动：类型对不上时一层层往外找；外部拖入：最里面那个独占认领、不往外找。

前半句是错的。**App 内拖动也一样：指针底下最里面那个落点独占这次拖放，类型对不上
也不往外找。** 于是最里面那层文件落点把三套卡片的拖入全接住又扔掉。

用一个独立的探针 App 把规则测清楚之后，又翻出两件事：

1. **空类型的落点照样独占。** 转场落点原来挂在**每一条**轨道行上，非主轨传
   `of: []`，注释写着「空类型数组 = 这一行不认这种拖放，代理一次都不会被调到」。
   代理确实一次都不会被调到，但这一行照样把拖入独占掉（探针 R9）。所以**早在
   ea746c1 之前**，滤镜 / 音频库卡片拖到**轨道行**上那一下就已经死了，只有拖到
   滤镜行、字幕行这类非轨道行上才落得下去。
2. **「代理式收不到外部拖入」也是错的。** 单个代理式落点接外部文件拖入，
   `validate` / `entered` / `performDrop` 全都收到，op=1（探针 R2）。上一个案例里
   那三次「零调用」实验，代理式落点每次都被滤镜 / 音频库的落点盖在外面 —— 测到的
   仍然是「里面那个独占」，不是「代理式收不到」。

### 为什么当时的验证没发现

- 上一个案例做过 A/B：「把三处垫层全撤掉，同一次合成拖动的结果一模一样 —— 垫层
  没有改变它们的行为」。但合成事件**驱动不了** SwiftUI 的 `.onDrag`（拖动图像跟着
  指针走，落点一个回调都收不到，本案例在探针上重测确认），改前、改后**都落不下去**。
  一个两边都失败的 A/B 分辨不出任何东西，却被写成了「不受影响」的证据。
- `checks/timeline-drag-wiring.sh` 钉的是「每个 `.onDrop` 里面都要垫一层」——
  把错误的模型钉成了硬约束，错误的结构因此看起来是被验证过的。
- 三套卡片在人工回归清单上，但那份清单要到发版前才跑。

## 修复

一条规则：**整条时间线只许有一个 `.onDrop`。**

- 新增 `TimelineDropRouter`（`VideoEditTimelineDropRouter.swift`）：一个代理认四种
  载荷（`FilterDrag.type`、`AudioLibraryDrag.type`、`TransitionDrag.type`、`.fileURL`），
  按载荷分派给各自原来的代理 —— 那三个代理一行没改。**自定义载荷先认、文件最后认。**
- 挂在 `scrolledContent` 上「填满视口」的 frame 和最后那个 `.contentShape` 之后，
  视口撑出来的空白也接得住文件。
- 原来靠「挂在哪」保证的两条合法性，改由路由器按坐标判：转场只落主轨那一行
  （`mainRow`，藏起来的主轨不接）；滤镜只落 `contentWidth` 以内。
- 文件落点改回代理式（`MediaFileDropDelegate`，直接用 `info.location`）。删掉闭包
  垫层、每 16ms 读一次 `NSEvent.mouseLocation` 的心跳、`isTargeted` 手动归位、
  `TimelineScrollGeometry.contentPoint(fromScreen:)`，以及 `body` 上那一层整栏兜底 ——
  时间线以外的拖入仍归 `VideoEditView` 整页那条 `.onDropOfFiles`，和改动前一样。
- `dropUpdated` 在**确知**一个都用不了（一堆 .pdf）时回 `.cancel`：方案里写的
  「指针当场变成不能放」，闭包式做不到，现在做到了。

修复过程中又踩到一条：**松手之后 SwiftUI 还会补发一拍 `dropUpdated`**（临时日志：
`validate → entered → updated… → PERFORM → updated`，没有 `exited`）。初版文件代理
里有一句「暂存被清掉了就补探一次」，这一拍把落点框按落地**之后**的状态重新画了
出来，挂在时间线上不走（截图实测）。路由器加了 `isLive`（四套各自起手时记的那一笔
还在不在），四套一起挡掉这一拍 —— 另外三套原来也会在这一拍调
`autoScroller.update`：松手点正好在视口边缘时，心跳会被重新拉起，时间线松手之后
自己一路滚到头。

## 验证

**探针**：`scripts/gui-smoke/drop-routing-probe/`（独立的 SwiftUI 小 App，每格只放
一种落点组合，所有回调写日志；外部拖入用 `scripts/gui-smoke/external-file-drag/`
的拖源）。A / B 是两种自定义类型，file 是 `.fileURL`：

| 格 | 结构 | 外部文件拖入 |
| --- | --- | --- |
| R1 | 同一视图：里代理(A)、外闭包(file) | op=0，**两边零回调** |
| R2 | 单个代理(file + A) | op=1，validate / entered / PERFORM 全到 |
| R3 | 同一视图：里闭包(file)、外代理(A)（ea746c1 的垫法） | op=1 |
| R4 | 单个闭包(file + A) | op=1 |
| R9 | 里视图 `.onDrop(of: [])`、外视图闭包(file) | op=0 |
| R10 | 里视图没有落点、外视图代理(file + A) | op=1 |

两条够不着的：合成事件驱动 App 内 `.onDrag`，`onDrag` 闭包被调到、拖动图像跟着
走（中途截图可见），但任何一格都收不到回调；外部拖源改拖自定义类型（不是文件）
来模拟 App 内拖动也不行 —— 连只有一个落点的对照格都是 op=0，SwiftUI 不认外部来的
自定义类型。所以 App 内那一半的判断来自用户实拖：R3 那种垫法，三套卡片全死。

**真实 App**（`SrtFlowDev2`，预置一段 12 秒素材，跨 App 拖源）：

| 落点 | 结果 |
| --- | --- |
| 主轨已被占的位置 | op=1，抬到上方新开一条视频轨；落地后没有残留的框和对齐线 |
| 上层轨已被占的位置 | op=1，再往上开一条；拖动中框缩成 22pt 骑在标尺下那条缝上（截图） |
| 轨道下方空白 | op=1，落主轨，时间按指针 |
| 音频文件拖到空白 | op=1，新开一条音频轨 |
| 内容区右侧、视口撑出来的空白 | op=1 |
| .pdf 拖到主轨 | op=0（指针显示不能放） |

**守卫**：`checks/timeline-drag-wiring.sh` 拖放那一节重写，9 条反向验证全部变红、
恢复后回绿 —— 轨道行上加回空类型转场落点、滚动内容上加回文件垫层、路由器挪到填满
视口之前、`.fileURL` 排到卡片前面、去掉 `isLive`、`isLive` 漏看一套、滤镜不按内容区
拦、文件代理加回补探、`plan` 退回占位暂存。反向验证时还抓到守卫自己的一个坑：
失败文案里 `$flag：` 这种「裸变量紧跟全角标点」会被 bash 当成变量名的一部分，在
`set -u` 下直接崩掉 —— 守卫是红了，但红的原因不对，打出来的也不是那句话
（[shell 陷阱 1](2026-08-06-build-version-and-shell-traps.md)）。

## 教训 / 防回归

1. **一个两边都失败的 A/B 不是证据。** 「改前改后结果一样」只有在改前是成功的
   时候才说明「没影响」。合成事件驱动不了 `.onDrag`，这件事当时就写进了 GUI 冒烟
   文档 —— 同一份报告却拿它证明了「垫层不影响 App 内拖放」。
2. **对照实验先确认被测对象没被别的东西挡着。** 「代理式收不到外部拖入」三次零
   调用，三次代理都被盖在别的落点外面。探针每格只放要测的那一种组合，结论才干净。
   改时间线的 `.onDrop` 结构之前，先在探针上把想法测一遍。
3. **守卫钉的是模型，模型错了守卫就是帮凶。** 「每个 `.onDrop` 里面都要垫一层」
   让错误的结构看起来是被验证过的。
4. **空类型的 `.onDrop(of: [])` 不等于「没有」**，它照样独占拖入。
5. 长期约束：[时间线拖动手势 §5e-2](../architecture/timeline-drag-gestures.md)。

### 人工回归清单（自动化够不着）

发版前、以及动过任何 `.onDrop` / `.onDrag` 之后，实机各拖一次：

- [ ] 滤镜卡片 → 滤镜行、视频轨行、音频轨行、轨道下方空白：都落得下去，落点框和
      落地位置一致；拖到内容区右边撑出来的空白：指针显示不能放。
- [ ] 音频库素材 → 音频轨行（指哪条落哪条）、视频轨行（退回默认音频轨）。
- [ ] 转场卡片 → 主轨两段之间的接缝：出框、松手落下；拖到上层轨 / 音频轨上：不能放。
- [ ] 以上每一种松手之后：时间线上没有残留的框或对齐线；在视口右边缘松手，时间线
      不会自己继续滚。
- [ ] 从 Finder 拖文件：主轨已占处抬一轨；上层轨行、音频轨行、轨道下方空白、右侧
      空白都落得下去；.pdf 显示不能放。
