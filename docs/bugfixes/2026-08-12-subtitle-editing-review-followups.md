# 2026-08-12 字幕编辑入口复审的六条后续

字幕三入口合入前的一轮复审（2 个 P1 + 5 个 P2）。逐条记录，最后一条是**不修**并说明
理由。相关长期约束落到
[subtitle-track-visibility-and-layout.md](../architecture/subtitle-track-visibility-and-layout.md)。

## P1-1 正在输入的字幕会在保存 / 切工程 / 退出时丢掉

**症状**：在字幕表或就地浮层里打字，不按回车，直接 ⌘S / 新建 / 打开 / 退出 ——
存下去的是**旧文本**，刚打的那句没了。

**根因**：草稿存在视图的 `@State` 里，只有失焦或 `onDisappear` 才提交；而保存/切换
那几条路的顺序是「先读 `state` 写盘，再销毁视图」。⌘S 也不会主动结束编辑。
换句话说：**提交时机依赖视图生命周期，而写盘发生在它之前。**

**修复**：把草稿从视图搬到工程上 —— 新增 `SubtitleTextDraft`（
`VideoEditSubtitleDraft.swift`），字段是 cueID / 是否译文 / 文本 / 进入编辑时的基线；
输入框绑 `project.subtitleTextBinding(…)`，焦点变化只负责「开草稿 / 落草稿」。
`endPendingTextEditing()`（`VideoEditProjectDocument.swift`）在
`flushAutosave()`、`saveNow()`、`prepareToCloseDocument()` **三个路口的最前面**
同步落定草稿 —— 注意必须在 `flushAutosave` 的 `hasUnsavedChanges` 判定**之前**，
否则「工程看起来是干净的」会直接 return，把刚打的字扔掉。

**残留（明写出来）**：时间码格子、Inspector 数值框的值仍然活在各自的视图里，
`endPendingTextEditing()` 对它们只能 `makeFirstResponder(nil)` 尽力而为 ——
AppKit 让第一响应者辞职是同步的，但 SwiftUI 把焦点变化转成 `onChange` 可能要等下一拍。
留在 App 里的路径（⌘S、自动保存）晚一拍无所谓，**退出那条路仍有残留窗口**。
这些输入框在本次改动之前就是这样，彻底解决要把它们也改成工程级草稿，属独立一轮。

## P1-2 CAS 基线会跟着父视图重建，可能把更新的值盖回旧的

**症状**：就地浮层里正在编辑（草稿 B），别处（右栏、重译写回）把同一格从 A 改成 C，
浮层收工时 C 被 B 盖掉。

**根因**：基线是普通 `let`，父视图每次重建都重新取一遍模型当前值 —— 而草稿是
`@State`，是持久的。预览那个浮层的父视图**每 0.05 秒随时钟重建一次**，所以基线几乎
一定会被刷成 C，CAS 于是形同虚设（`current == baseline` 成立），旧草稿照样写了进去。

**修复**：基线跟草稿存在一起（`SubtitleTextDraft.baseline`），**只在
`beginSubtitleDraft` 里写一次**，编辑会话内绝不重算。CAS 判定也搬进
`commitSubtitleDraft()`：模型当前值 ≠ 基线就放弃草稿，新结果优先。

## P2-1 原文轨隐藏时 + 仍会改隐藏轨，并复现「焦点失败→按键变快捷键」

合同 7 只往原文轨写，而按钮一直可点；建完还固定把光标放到 `.original(id)`，
那一格在隐藏时并不存在 → 聚焦失败 → 接下来的空格/V/M 落到全局快捷键上
（同 [smoke-fixes 案例](2026-08-12-subtitle-editing-surfaces-smoke-fixes.md) 的第二个坑）。

**修复**：`canEditOriginal` 为假时 + 和空状态的「手写一行」都置灰，`addCue()` 里再拦
一道。理由与「隐藏 = 不可编辑」同一条合同。

## P2-2 非法时间码显示成已接受，模型其实拒绝了

`TimecodeField` 解析成功就把 `parsed` 写回文本框，可绑定有权拒绝 —— 字幕表那两个
格子就拒绝 `start >= end`。于是 1–3 秒的 cue 输入开始时间 4 秒，界面显示 4 秒，
**存盘和导出仍然是 1 秒**，用户毫不知情。

**修复**：`commit()` 写完**回读绑定**再格式化（`SubtitleEditPanel.swift`）——
显示的永远是模型真正采纳的值。烧录页那份文档绑定一律接受，行为不变。

## P2-3 合法的改时间没有重排与重编号

`LinkedSubtitleEditing.setTime` 只改字段。把一条 cue 的时间挪到邻居前面之后，
数组顺序和 `index` 就过期了 —— 而 `cues` 的数组顺序**就是**时间顺序，下游全按顺序
消费（`cue(at:)` 取第一条命中的、序列化按数组写、字幕表按数组显示）。

**修复**：抽出 `normalizeOrder`（稳定排序 + `reindex`）在两轨上各跑一次，与规则 7
（整体平移）共用同一实现。新增 4 条守卫（重排 / 重编号 / 译文轨同步 / 同起点保持
原有先后），并做了反向验证：撤掉 `normalizeOrder` 后 3 条断言变红，恢复后 708 条全绿。

## P2-4 预览输入框在窄窗口 / 竖版素材里被裁

编辑器写了 `minWidth: 240`，而画面框可以窄到一百多点，超出的部分被画面框的
`clipShape` 切掉。

**修复**：共享编辑器不再自带下限，宽度由调用方给；预览侧
`editorWidth` 先服从画面框（`min(220, 可用宽度)` 作下限、可用宽度作上限）。

## 不修：双语就地编辑不是一笔原子事务（并说明）

复审要求「一次 Done 同时写两轨、一步撤销」。**这里保持一格一步，并把文档改成如实
描述。** 理由：原文和译文是两个独立的输入格，提交时机是「失焦即提交」——
用户从原文 Tab 到译文的那一刻，原文已经落定了；要做成一笔事务就得把提交推迟到
Done，等于放弃失焦提交，而失焦提交正是 P1-1 那类丢字问题的第一道防线。
按格撤销也符合其他编辑器的手感（⌘Z 退一格）。因此合同的措辞改为
**「一格 = 一步撤销」**，代码与文档一致。

## 验证

- 核心自检：708 条全绿；`setTime` 那 4 条做过反向验证（红 → 绿）。
- `scripts/check-all.sh`：17 项全过。
- GUI 冒烟：在字幕表里打字**不按回车** → 预览叠层仍是旧文本（草稿没进模型，符合
  预期）→ 用**菜单**切到烧录页再切回来（菜单不改第一响应者，所以不是靠点击失焦）
  → 文本已落进模型，预览叠层与右栏同时更新，没丢字。
- ⌘S / 退出这两条路的 NSSavePanel 无法可靠自动化（见
  [gui-smoke-testing.md](../testing/gui-smoke-testing.md)），已写进人肉回归清单。

## 教训 / 防回归

1. **凡是「视图里的草稿 + 别处读模型写盘」的组合，都要问一句：写盘会不会发生在提交
   之前？** 答案通常是会。草稿要么放在被写盘那一层能同步落定的地方，要么在所有写盘
   路口显式结束编辑。
2. **CAS 基线必须是会话级快照。** 放在会随父视图重建的普通属性里，等于没有 CAS。
3. **绑定有权拒绝写入，UI 就必须回读。** 显示 parsed 而不是回读，是在向用户撒谎。
4. **改「时间」的合同都要顺手保证顺序不变量**：这个仓库里 `cues` 的数组顺序是有语义
   的，任何改 start 的入口都要重排 + 重编号。
