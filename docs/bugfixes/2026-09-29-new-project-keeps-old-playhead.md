# 2026-09-29 新建工程之后播放头停在上一个工程的 36.3 秒，AI 配的旁白从那儿开始

## 症状

用户让另一个窗口里的 AI 驱动测试版 0.17.3 做验收实剪，做完课程推广那条之后新建了一个工程复查配音：

> 新建工程后播放头没有归零，停在上一个工程的 36.3 秒。add_voiceover 没给 start 时，第一句被放到了 36.3 秒。
> 我撤销后用 start: 0 重做，第一次的那三个文件还留在配音文件夹里（撤销不会删文件）。

`add_voiceover`、`set_text` 这些不给时间就放在播放头的工具，在新工程里全都放到了上一个工程的位置。打开另一个工程也一样：
新打开的工程从上一个工程的播放头开始，比它短就停在片尾。（配音文件留在文件夹里是既定规则：撤销不删文件，删文件要先问。）

## 根因

1. **卸片之后播放器的时间回调晚到一拍，把旧位置写了回去。** 新建 / 打开工程先 `closeCurrentDocument()`：停播放、
   `clock.detach()`（换成空条目、播放头放到 0）。可播放器换掉条目之后，周期时间回调还会再来一次，报的是**旧条目**的时间，
   `PlayerClock` 照单全收。拿真的 `PlayerClock` 和一段 60 秒带声音的视频量（2026-09-29）：

   | 卸片前 | 卸片那一刻 | 之后发出来的播放头 |
   | --- | --- | --- |
   | 停在 36.3 | 0 | 0 → **36.30** |
   | 在播（到 36.8） | 0 | 0 → **36.87** |

   打开工程时，重建落地要把播放头放回「原位」（`clock.time`），读到的正是这个晚到的 36.3，于是新打开的工程从那儿开始。
2. **顺带发现（读代码，没有复现）**：`newProject()` 换完时间线不重排预览，而打开工程、补静帧 / 重链接都重排。重排那一下
   顺手作废还在路上的重建；新建漏了，上一个工程刚改完、重建还没落地时就新建，落地时会把旧工程的画面挂进新工程。
3. **为什么自检没抓到**：`check-player-clock.sh` 早就有一条「detach 归零」，但它不挂真条目、卸片之后马上断言，
   异步的那一拍根本来不及到。

## 修复

1. `PlayerClock`：播放器没挂条目时丢掉时间回调（没有条目就没有播放时间）。重建换条目那条路不受影响：它有条目。
2. `newProject()` 换完时间线也 `scheduleRebuild()`，和打开工程一样（空时间线建不出合成，落地时就是卸片，新工程照旧显示空白页）。

## 验证

- `scripts/check-player-clock.sh` 第 11 项：真的播放器、ffmpeg 现做的 60 秒小视频（带声音），先确认播放器真的到了 36.3，
  停着、在播各卸一次片，跑一秒主循环，播放头必须还是 0。修之前两种都红（36.3、36.65），修之后 45 项全过。
- 这一项的第一版素材没有音轨，只有「在播」那种红、「停着」照样绿 —— 没有音轨时停着卸片不出那一拍。补了音轨才两种都红。
- `scripts/check-project-file.sh` 的接线守卫：`newProject` 里必须有 `scheduleRebuild()`。删掉那一行 → 红，恢复 → 绿。
- 探针顺带看了重建（旧条目换新条目、再 seek 回原位）：播放头会先闪一下 0 再到位，最后停在对的地方，这次没动。
- 实机：[工程文件与素材重链接](../architecture/video-edit-project-file.md) 回归清单里「播放头停在工程后半段 → 新建 / 打开另一个工程」那一条。

## 教训 / 防回归

- **平台的回调是异步的**：同步设好的状态（卸片 → 0）会被一个「关于上一个条目」的回调盖掉。换条目时要么按「有没有条目」
  过滤回调，要么先移除观察者。
- **测异步的毛病要让主循环转起来**：动作之后立刻断言，晚到的那一拍永远看不见；素材也要像真的（这次差在有没有音轨）。
- **同一类路径要做同一件事**：换整份时间线的地方（打开、新建、修补）都要重排预览，漏一个就是串味。
- 长期约束写在 [工程文件与素材重链接](../architecture/video-edit-project-file.md)「五、脏标记与自动保存」里切工程那几条。
