# 2026-09-23 从 Finder 拖文件进时间线：标尺以下整片没反应

## 症状

剪辑页，工程里已经有素材之后，从 Finder 拖一个视频进来：

- 指针在工具栏那一行上时有 `+` 号，松手能导入；
- **指针一旦移到标尺以下（整个滚动区），`+` 号消失，松手什么也不发生。**

工程是空的时候（时间线显示「Drag material here and start to create」）拖进去
一切正常 —— 所以看起来像是「第一次没问题，第二次开始就不行」。

这**不是**新功能引入的回归：这条路在 0.12.0 上就是死的。0.12.0 只有整页那条
`.onDropOfFiles` 兜底，空工程时它接得到（所以「第一次好使」），有内容之后同样
接不到 —— 只是那时候没人往有内容的时间线上拖过第二个文件。

## 根因

SwiftUI 的**外部拖入**（从别的 App / Finder 拖进来）和 **App 内拖动**
（自己 `.onDrag` 发起的）走的不是一条路由，两条规则正好相反：

| | 谁收得到 | 类型对不上时 |
| --- | --- | --- |
| App 内拖动 | 代理式、闭包式都行 | 一层层往外找下一个落点区 |
| **外部拖入** | **只有闭包式** `.onDrop(of:isTargeted:perform:)` | **最里面那个独占认领，不往外找** |

时间线的滚动内容上原本叠着两个**代理式**落点（滤镜库、音频库），主轨那一行上
还有一个（转场）。于是从 Finder 拖文件进来时：

1. 最里面那个代理式落点把这次拖入**认领**下来；
2. 它是代理式，**收不到外部拖入的任何回调**（`validateDrop` 都不会被调到），
   于是这次拖放以「没人要」告终（`NSDragOperation` = `.none`）；
3. 挂在更外面的接收者 —— 包括整页那条兜底 —— **一个都轮不到**。

`+` 号消失的分界线正好是滚动内容的上沿，就是这么来的。

### 三次修错了的尝试（这条案例最值钱的部分）

都发生在 2026-09-22，全部靠「读代码 + 让用户实拖」推进，每次都自洽、每次都错：

1. **「命中区没盖在填满视口之后」。** 仓库 2026-09-21 刚栽过一次同形的坑
   （点击 / 框选的死区），所以看到 `.onDrop` 排在 `.frame(minWidth:minHeight:)`
   前面就认定是它，把 `.onDrop` 挪到了后面，还照着写了一条顺序守卫。
   **为什么看起来对**：那条死区教训是真的，改动本身也确实扩大了落点区。
   **为什么没修好**：区域再大也轮不到它 —— 根本问题是它压根收不到回调。
   这条守卫后来还把**正确**的顺序判成了错的，见下面「教训」。

2. **「祖先的兜底把后代盖掉了」。** 日志显示时间线上的拖放全被整页那条
   `.onDropOfFiles` 接走，于是把它的作用域收到上半区 + 工具栏 + 空状态三块。
   **为什么看起来对**：现象完全吻合，而且收完之后时间线上「兜底不再抢食」了。
   **为什么没修好**：因果反了。兜底能接到，是因为**没有别人接**（空工程那条
   分支上滚动内容不存在，也就没有代理式落点）。收完作用域之后，时间线从
   「被兜底接走」变成「彻底没人接」—— 症状更差了。

3. **「代理式收不到外部拖入」。** 这一条是**对的**（三个层级实测零调用），于是
   把代理改写成闭包式、指针改从 `NSEvent.mouseLocation` 现读。
   **为什么还是不行**：只解决了「谁收得到」，没解决「谁先认领」。闭包式那一份
   当时挂在整条时间线上，仍在那两个代理式的**外面**，照样轮不到。

真正定性靠的是第四步：**做了一套可重放的跨 App 拖放装置**（见下），然后才有
了「摘掉滤镜 / 音频库两个落点 → 同一次拖放立刻 `op=1` 并落地」这种一刀两断的
证据。在那之前，每一轮都要用户实拖一次，而实拖只能告诉你「还是不行」。

## 修复

一条规则：**时间线里每一个 App 内的 `.onDrop` 里面，都先垫一层文件落点。**

- 新增 `View.mediaFileDropUnderlay(_:)`（`VideoEditMediaFileDrop.swift`）：
  闭包式 `.onDrop(of: [.fileURL], isTargeted:)`，转交给 `MediaFileDropController`。
- 三处应用：`scrolledContent` 上（排在滤镜 / 音频库两个代理式**之前**）、
  主轨那一行上（排在转场之前）、`VideoEditTimelineView.body` 上
  （盖住内容区以外那片空白，以及空工程那条分支）。
- `MediaFileDropDelegate` 改写成 `MediaFileDropController`（不再是 `DropDelegate`）。
  闭包式不给落点，指针改为现读 `NSEvent.mouseLocation`，屏幕坐标 → 滚动内容坐标
  的换算落在 `TimelineScrollGeometry.contentPoint(fromScreen:)`
  ——**整个时间线只有那个类碰 `NSScrollView`**，这条老规矩没破。
- 落点框 / 时长探测靠 `isTargeted` 起手。三处垫层必须接**同一个** `isTargeted`
  （里面那层一旦独占认领，外面那层就再也收不到「进来了」），而且 `exited()`
  要亲手把它归位 —— SwiftUI 不保证打回 false，不归位的话第二次拖入
  `.task(id:)` 因为 id 没变根本不重跑，整次都没有落点框。

落点算法（`mediaImportLandings` / `importFirstStart`）一个字没改。
`VideoEditView`、`MainWindowView`、`MediaFormatting` 在第 2 次尝试里被改过，
定性之后全部还原 —— 整页那条兜底照旧盖全页，时间线归垫层，互不打架。

## 验证

**可重放的跨 App 拖放装置**（`scripts/gui-smoke/`，见
[GUI 冒烟流程](../testing/gui-smoke-testing.md)）：一个最小的 AppKit 源 App 起
真实 `NSDraggingSession`，用 CGEvent 驱动鼠标把文件拖进被测窗口，两边各自记日志。
源那边的 `draggingSession(_:endedAt:operation:)` 给出的 `op` 就是判据：
`op=0` 没人要、`op=1` 被接受。Finder 本身不吃合成事件，所以才要自己做一个源。

实测（工程里先放一段 12 秒素材）：

| 落点 | 修复前 | 修复后 |
| --- | --- | --- |
| 轨道下方空白 | `op=0`，控制器零调用 | `op=1`，落在指针那一刻的主轨上 |
| 主轨那一行（已被占） | `op=0` | `op=1`，**抬到上方新开一条视频轨** |
| 上层视频轨那一行（已被占） | `op=0` | `op=1`，再抬一轨 |
| 最右边空白 | `op=0` | `op=1` |

拖动过程中截图，落点框（等长占位）画在目标轨上；坐标换算另做过对账：让
`onContinuousHover` 报的 `.local` 坐标和我们从屏幕坐标现读换算的并排打日志，
三次取样**逐点相等**（`582,126` / `182,206` / `581,172`）。

回归面：

- `checks/timeline-drag-wiring.sh` 新增 5 条守卫，**全部反向验证过**
  （改回 `DropDelegate` / 拿掉主轨行的垫层 / 把垫层挪到滤镜落点外面 /
  垫层不接 `isTargeted` / `exited` 不归位 —— 五条各自变红，恢复后回绿）。
- `scripts/check-all.sh` 全绿。
- **App 内拖放（滤镜 / 音频库 / 转场）**：合成事件驱动不了 SwiftUI 的
  `.onDrag`（拖起来了但落不下去），所以装置验不了。做了 A/B：把三处垫层全撤掉，
  同一次合成拖动的结果**一模一样** —— 垫层没有改变它们的行为。真机复核见
  下面的人工清单。

## 教训 / 防回归

1. **外部拖入和 App 内拖动是两套路由，不能互相当反例。** 「滤镜拖放好好的，
   所以这块的 `.onDrop` 没问题」——三次修错里有两次栽在这个推理上。长期约束写进
   [时间线拖动手势](../architecture/timeline-drag-gestures.md)。
2. **同形的旧教训是最贵的假线索。** 第 1 次尝试直接套用了 2026-09-21 的死区结论，
   连守卫都照着写了一条**方向相反**的（要求文件落点排在「填满视口」的 frame
   后面）。正确答案恰恰是排在最里面、也就是那个 frame 前面。守卫写反比没有守卫
   更糟：它会把对的改动判成错的。这条守卫已换成「垫层必须排在滤镜落点之前」。
3. **靠用户实拖来二分是最慢的调试回路。** 三轮下来只换到「还是不行」。真正该做的
   第一件事是**把复现自动化**：做完装置之后，二分到根因只用了四次重放。够不着的
   交互（这里是 Finder 的拖放）值得自己造一个源。
4. 时间线里**新加任何 `.onDrop` 都要先垫一层** `mediaFileDropUnderlay`，
   `checks/timeline-drag-wiring.sh` 钉着。
