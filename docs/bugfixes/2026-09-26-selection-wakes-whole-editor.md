# 2026-09-26 点一下选中一段，整个编辑器跟着重算：工程换成 `@Observable`

## 症状

「播放丝滑」合并之后用户说继续优化。下一个卡点是**点选一段**：南极工程（77 段）上在主轨两段之间来回点 8 次，
进程 CPU 约 1.5 秒，每点一下约 0.19 秒，每点一下 334 次 body（提示修饰器 172、转场卡片 33、检查器数值框 20
外加 20 次 AppKit 控件更新、轨道头 17 行、推子 12、行高把手 11、工具栏图标 11……）。点一下只改了「选中了谁」，
轨道头、推子、工具栏图标这些跟选择毫无关系的东西也全跟着重算。

## 根因

`VideoEditProject` 是一个大 `ObservableObject`，26 个文件里 33 处 `@ObservedObject var project`。点选一段只写了
`selection` 一个 `@Published`，可 `objectWillChange` 不分是哪个属性：33 个订阅者连同各自的子树全部重算 ——
根视图（整条工具栏、提示修饰器）、时间线本体（还要被根视图再带着算一遍，第十一节的「两遍」）、轨道头每一行、
检查器、素材库、预览叠层、文件菜单、工程名下拉。

逐个视图改成「只收值」（像 2026-09-24 改块那样）能省一部分，但 33 处要一处处改、还得一处处防回退；
[预览性能 ratchet](../architecture/preview-perf-ratchet.md) 第十一节把两条路摆给用户，用户选了结构性的那条
（「A 做了」）：换成 Swift 的 Observation，让视图按读到的属性失效。

## 修复

1. **工程换成 `@Observable`**（`VideoEditProject.swift`）：19 个 `@Published` 去掉前缀，照旧被观察；17 个普通的存储
   属性（任务、缓存、代号、书签、连续修改的快照、`undoManager`……）加 `@ObservationIgnored`，被观察的集合和以前
   一模一样。33 处 `@ObservedObject var project` 改成普通引用；用到 `$project.x` 的两处（工具栏三个开关、捏合缩放
   的桥）用 `@Bindable`。
2. **根视图不读选择**：垃圾桶和「分离声音」要看选中了什么，写在根视图的工具栏里，点一下就把整个编辑器叫醒。
   拆进小视图 `SelectionToolbarButtons`（`VideoEditToolbarStateButtons.swift`），点一下只有它俩重算。
3. **换机制后没人顺带刷新的两处**（以前工程一变整个编辑器重算，它们被顺手带着刷新）：
   - **文件 ▸ 最近打开**（`ProjectCommands`）：body 里一个工程属性都没读，换完之后就再也不重算，菜单停在启动时
     那份（启动那一刻系统的最近列表还没读进来，是「没有」）。显式读 `documentURL` —— 开 / 存工程时最近列表变，
     正是它变的时候。
   - **撤销 / 重做**：`NSUndoManager` 不可观察。连续修改（拖滑杆、裁切）是先写 `state`、松手才登记撤销，以前靠
     两秒后自动保存写 `hasUnsavedChanges` 把根视图顺带刷新，现在根视图不读它了。拆进 `UndoRedoToolbarButtons`：
     听撤销栈的三个通知（一组关上了 / 撤销了 / 重做了），再读一下 `state` 管换工程清栈。不听
     `NSUndoManagerCheckpoint`：`canRedo` 自己会发它。
4. **转场卡片的两张帧一起换**（`VideoEditTransitionPicker.swift`）：选中换了一段，素材库那一栏跟着换到那段的缝，
   网格要算三遍（缝一变、尾帧到了、首帧到了），每遍 11 张卡连同小样全部重算，小样还会先换一半。两张取齐了再一起
   写，三遍变两遍。
5. **冒烟的指标跟着换**：以前数 `objectWillChange`（`event:project.willChange`），现在数「哪个属性变了几轮」
   （`event:project.changed.<属性>`，`SmokeProjectChanges.swift`），清单起手时拿 `Mirror` 和工程核对。又加了两个
   步骤：`open`（换工程）、`menu`（读菜单）——上面第 3 条那两处只有换工程时才看得出来。
6. **守卫**（`checks/preview-perf-wiring.sh`、`checks/timeline-drag-wiring.sh`）：
   - 「时间线上的块」那条原来钉的是「没有 `@ObservedObject var project`」，那种写法现在编不过，钉了等于没钉。
     改成「块的 struct 里不读工程的属性」：调方法、写入、`clock` / `meters` 放行，手势回调里现读的两处行尾写明
     「手势里现读」。
   - 「工程上不许有重建开关」从 `@Published` 改成任何写法的 `var isRebuilding` 都不许。
   - 三个开关的默认值去掉 `@Published` 前缀照样钉住。
   - 「时间线本体不许套 `.equatable()`」留着，理由改写：原来的坑（选中高亮只在根视图那一遍更新）已经不在了，
     但套了之后改动时高亮、位置、缩放跟不跟得上没人验过。

长期约束写在 [预览性能 ratchet](../architecture/preview-perf-ratchet.md) 第十三节。

## 验证

- **同一个工程、同一套点选**（南极工程拷贝，1180×860，主轨两段之间来回点 8 次；main 1f3f693 在单独的 worktree 里
  编，和这一版交替各跑三遍）：

  | | main | 这一版 |
  | --- | --- | --- |
  | 进程 CPU（8 次） | 1548 / 1494 / 1519 ms | 1155 / 1118 / 1109 ms（约 −26%） |
  | 每点一下 body | 334 | 120（−64%） |
  | 主线程忙（`sample` 24 次点选里同一段窗口） | 1973 ms | 1467 ms（−26%；SwiftUI 更新那一块 1113 → 655） |

  每点一下根视图、时间线本体、轨道头、推子、工具栏图标、行高把手、工程名下拉、文件菜单一次都不重算；还在算的是
  检查器、素材库那一栏（两遍）、预览上的选中框、高亮变了的两个块。**给用户的估计是「省一半左右」，实测进程 CPU
  和主线程都只省了约四分之一**：剩下的主线程时间约一半是 SwiftUI 按下 / 松开时的命中测试（顺着整棵响应树找），
  它和重算几个视图无关，换之前 596、换之后 653（采样噪声以内）。
- **改动没有变贵**（同一个工程，main 和这一版交替各两遍，每一刀单独量）：裁切 2913 → 2888 次 body、CPU 持平；
  点转场卡片 317 → 310、持平；拖音频段 552 → 367（CPU 约 −8%）；拖文字块 765 → 351（CPU 约 −20%）。
  PR #74 的 CI 上「改几刀」那一段（只报不卡）busy 从 1031 升到约 1120、basic 从 199 降到 176，本地这四刀复现不出
  升高；那一段是程序里直接调 `setVolume` / `perform` / `setTransition` / `updateTextOverlay`，不是这四种手势，
  原因没查清，记在这儿。
- **高亮跟得上**（第十一节那个坑）：点一下时间线本体 body 0 次、`ClipBlockView` 2 次（新选中的和刚取消的）；
  截图上点第二段 → 第二段亮、第一段灭，点空白 → 都灭、检查器回到工程总览，点文字块 → 文字块亮、检查器换成文字。
- **按钮的亮灭**（截图数像素亮度：亮 153、灰 85）：选中剪辑 → 垃圾桶、分离声音都亮；点空白 → 都灰；选中文字 →
  垃圾桶亮、分离声音灰。拖一段音频之后撤销亮；换工程之后撤销灰。
- **最近打开**：换一个工程之后菜单从 `["Edit"]` 变成 `["Edit2", "Edit"]`。**反向验证**：去掉 `ProjectCommands`
  里读 `documentURL` 那一行，菜单从头到尾停在启动时的「No Recent Projects」。
- **功能回归**：上一轮留下的 15 步功能冒烟（点选、拖音频吸附、拖文字换行、框选、裁切、点转场卡片、刀片、拖音量点、
  跨轨、插入缝、拖字幕 cue、⌘A / ⌘⇧A、文字拖到最上面开新行）在 main 和这一版上各跑一遍，15 个检查点的状态
  （每段位置、选择、文字行、cue 时刻）逐项相同，唯一的差别是刀片切出来那一段的 UUID（随机生成）。那份核对脚本
  自己有三条和当前工程对不上（文字吸附点、裁切把手坐标、文字数），main 上一样红，不是这次引入的。
- **守卫反向验证**：块的 body 里读 `project.selectedClipIDs` → 红；去掉音量线那行的「手势里现读」→ 红；工程上加
  `var isRebuilding`（被观察的或 `@ObservationIgnored` 的）→ 各红一次；磁吸默认值改成 true → 红。恢复后全绿。
- 每个 commit 单独编过、`checks/*.sh` 全绿；`scripts/check-project-file.sh`（唯一按文件名钉着这次改过的
  文件的自检）本地跑过，其余 `scripts/` 下的自检和 CI 的性能 ratchet 交给 PR 上的 CI。

## 教训 / 防回归

- **换成 Observation，「谁订阅了谁」从声明变成了读法**：body 里读了哪个属性就订阅哪个，按属性不按值。大视图
  body 里多读一个属性，就是让那个属性一变整个大视图重算 —— 只为一两个按钮读的东西拆成小视图去读。
- **以前「顺带刷新」的地方要一个个找出来**：读不可观察的东西（撤销栈、系统的最近列表、`@ObservationIgnored`
  的属性）的视图，以前被工程的每一次变化顺手带着刷新，换完之后没人叫它。这类问题平时看不出来：最近打开只在
  换工程时露馅、撤销按钮只在松手登记时露馅，所以冒烟要能换工程、能读菜单。
- **给用户的估计要说清楚在估什么**：「少重算多少视图」和「主线程省多少」是两笔账。body 次数降了 64%，
  主线程只降了 26% —— 剩下的一半是命中测试，它不看重算了几个视图。
- **挪代码之后按旧写法把 `scripts/`、`checks/` 找一遍，要按守卫里的写法找**：垃圾桶挪出根视图之后，
  `scripts/check-project-file.sh` 还在根视图里找 `\.disabled\(project\.selection\.isEmpty\)`。第一遍按原文
  `selection.isEmpty` 去 grep 没找着 —— 守卫里存的是转义过的正则（`selection\.isEmpty`），原文对不上；换成
  `grep -F 'selection\.isEmpty'` 才找到（[PR #71 首跑 CI](2026-09-25-pr71-first-ci-run.md) 那条教训的另一种漏法）。
- 冒烟驱动的三个限制（点 AppKit 控件会卡死、合成事件关不上撤销组、菜单快捷键没用）写进了
  [GUI 冒烟流程](../testing/gui-smoke-testing.md)「四之六」第 12–14 条，这次各踩了一回。
