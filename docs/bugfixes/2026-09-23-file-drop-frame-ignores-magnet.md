# 2026-09-23 磁吸开着时，拖文件的落点框画在指针底下、素材却落到主轨末尾

## 症状

打开主轨磁吸，从 Finder 拖一段素材到主轨末尾后面的空白处：落点框（和吸附对齐线）
画在指针底下，松手后素材却接在主轨最后一段后面。框和落点对不上。

顺带一处：只拖一个字幕文件进时间线时，主轨上会一直挂着一条「还在探测」的插入线，
看着像要往主轨里放东西（字幕其实是挂在工程上的，不占轨）。

两处都是在审查 ea746c1 时发现的，没有发版。

## 根因

ea746c1 的守则是「画框和落地共用一个落点函数」（`mediaImportLandings`），这一条
做到了，但落地并不只是这一个函数：`importFiles` 通过 `perform { insertImported }`
落地，而 `perform` 在磁吸开着时收尾还会 `packMain()`。落主轨的段因此被拼到故事线
末尾。框只复现了落点函数，没复现 `perform` 收尾那一步。

仓库里早有同一条长期约束：「主轨磁吸开着时不给对齐线……占位框的位置落地必须调
同一个函数，否则占位框会说谎」（[拖动手势 §4](../architecture/timeline-drag-gestures.md)）。
剪辑拖动遵守了，文件拖入这条新路没有。

字幕那一处：`plan(at:)` 在「探完了、但一段可落的素材都没有」时一律退回探测中的
插入线。只有字幕的一批属于这种情况，于是那条线一直不收。

## 修复

- `TimelineState.landingsAfterMagnet`（`VideoEditMediaImport.swift`，纯值）：在状态
  副本上把落地那两步原样走一遍（同一个 `insertImported`、同一个 `packMain`），读回
  每一段的起点。**不另写一份「磁吸会把它挪到哪」的推算**，各算一份迟早分叉。
- `MediaFileDropDelegate.plan(at:)`：磁吸开着就用它画框；落点被挪走时收掉吸附
  对齐线（它们是按指针处算的）。
- 同一处：探完了、只有字幕时返回 nil，不画插入线（松手照样把字幕挂上）。

## 验证

- `scripts/check-media-import.sh` 新增第 8 节 7 条：磁吸下落点接在主轨末尾、和真的
  `insertImported` + `packMain` 对账一致、不落主轨时原样返回、多段首尾相接。反向
  验证：让 `landingsAfterMagnet` 原样返回输入 → 4 条变红。
- `checks/timeline-drag-wiring.sh` 第 4b 条：`plan(at:)` 必须调 `landingsAfterMagnet`。
  反向验证：去掉调用 → 红。
- 真实 App（`SrtFlowDev2`，主轨 0–12 秒，打开磁吸）：把 5 秒素材拖到 25 秒处，拖动
  中途截图，框在 12–17 秒；松手后素材落在 12–17 秒。

## 教训 / 防回归

1. **「画框和落地共用一个函数」要共用到落地的最后一步。** 落地路径上任何收尾处理
   （这里是 `perform` 里的 `packMain`）都会让框说谎，只共用中间那个落点函数不够。
   剪辑拖动那边早就踩过同一类坑（`applyDrag` 自己把磁吸重排做完，见拖动手势 §3），
   新加一条落地路径时要对着现有约束逐条过一遍。
2. 长期约束仍在[拖动手势 §4](../architecture/timeline-drag-gestures.md)，这次补了一句
   「从 Finder 拖文件进来同理」。
