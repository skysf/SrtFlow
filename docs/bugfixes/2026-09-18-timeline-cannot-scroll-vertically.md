# 2026-09-18 轨道一多，时间线就没法上下滚

## 症状

用户原话：

> 当轨道比较多的时候，不能上下scroll，只能通过放大屏幕才能看到被挡住在下面的轨道。

实测（10 条音轨 + 主轨 + 字幕轨）还有更难看的一半：**工具栏和标尺会被挤出窗口**
—— 时间线区域从预览区底下直接开始画轨道，`+ Add`、刀片、缩放滑块那一整条和
`|00:00 |00:05` 那条刻度全不见了。

## 根因

两个，一个比一个基础。

**1. 时间线只有横向滚动。** `ScrollView(.horizontal)` 里是一个普通 `VStack`，
行高是固定的（视频 54 / 音频 34 / 字幕 22 …）。行总高超过视口就直接被裁掉，
**没有任何纵向滚动的路径**。

**2. 轨道头列在替整条时间线要高度。** 左边那列（轨道色条 + 图标 + 眼睛）在滚动区
**外面**，是个裸 `VStack`，固有高度 = 所有行加起来。十来条轨就是 500pt 往上，
而 `VSplitView` 的下半区给不了这么多 —— 于是 `timelinePane` 那个
`VStack { toolbar; Divider(); 时间线 }` 里的工具栏被挤出了可见区域。

这一条**在拆分之前就存在**，只是要够多的轨道才看得见；它和第 1 条合起来才是用户
看到的完整症状（「下面的轨道被挡住」+「只能放大窗口」）。

## 修复

**双向滚动 + 两处「钉住」。**

- 时间线改成 `ScrollView([.horizontal, .vertical])`。
- **轨道头列**（新文件 `VideoEditTimelineHeaderColumn.swift`）跟着纵向滚动量走：
  `.offset(y: -geometry.offset.y)`。它和轨道行是**同一份 `rows`** 排出来的，所以
  只要减掉同一个数，两边永远对得上，不用各自去量位置。
- **标尺**钉在视口顶上（`TimelinePinnedRuler`）：`.offset(y: +geometry.offset.y)`
  + 一层不透明底（它盖在滚上去的轨道行上面）。轨道多的时候，看下面那几条轨还得
  能看见时间。
- 轨道头列改成画在 `Color.clear` 上的 overlay：`Color.clear` 的固有尺寸是弹性的，
  **这一列于是不再决定时间线的高度**，工具栏和标尺回来了。超出的部分 `.clipped()`，
  并补 `.contentShape(Rectangle())` —— `.clipped()` 只裁绘制不裁命中，少了这条，
  滚出视口的那些眼睛按钮照样点得中。
- **只有这两块订阅** `TimelineScrollGeometry`（`@ObservedObject`）。时间线主体用
  `@State` 持有它、不订阅 —— 订阅了的话滚动的每一帧都会把整棵时间线视图树（所有
  块连同缩略图与波形）重建一遍，就是「拖动中不写 state」那条老约束换了个轴。
- **自动滚动两轴一起**：拖块 / 拉框到视口上下缘也滚（纵向边缘带 26pt，比横向的
  44pt 窄 —— 时间线本来就不高）。四类块的手势因此把**整个指针位置**传上来，
  不再只传 x。
- **框选与跨轨判定补上纵向滚动量**：框的锚点/当前点两个轴都加 `offsetY`；
  `verticalTarget` 按「此刻露出来的是哪几条轨」算（纵向自动滚动期间指针不动、
  内容在滚，差的就是 `offsetY - originScrollOffsetY`）。
- **播放跟随只碰横向**：`ScrollViewProxy.scrollTo(_:anchor:)` 的锚点是双轴的，
  正看着下面几条轨一按播放，画面会被连带拽回最顶上。改成直接推
  `TimelineScrollGeometry.scrollHorizontally(to:animated:)`，`ScrollViewReader`
  和那个占位锚点一起删掉。

### 真窗口实测抓出来的一条

**没在推的那个轴，一个字都不许碰 —— 连夹一下都不行。** 第一版的 `scroll(dx:dy:)`
两轴都跑了一遍 `min(max(...))`。内容比视口窄时 SwiftUI 会把它**居中**（那一轴的
`bounds.origin` 是负的），顺手夹进 `[min, max]` 就把它按回 0：表现是「纵向自动
滚动刚一启动，整条时间线横着跳了 121pt」。

## 验证

**真窗口注入**（10 条音轨 + 主轨 + 字幕轨，`docs/testing/gui-smoke-testing.md`）：

| 验的东西 | 结果 |
| --- | --- |
| 两指竖滚 | 轨道区滚动，残差 0 的逐像素匹配 |
| 轨道头列 | 与轨道行始终对齐（8 行逐行核对） |
| 标尺 | 纵向滚动中位移 0（钉住了） |
| 滚下去之后拉框 | 框的四条边与注入点误差 ≤1.5pt（**两个轴**都补对了） |
| 拖到下边缘 | 纵向自动滚动到底，横向位置不变（就是上面那条修完的） |
| 播放 3 秒 | 纵向位置位移 0，时间码走到 0:02.4 |
| 工具栏 / 标尺 | 10 轨下都在（修复前被挤出窗口） |

**扫描守卫**：`checks/timeline-drag-wiring.sh` 第 10 节，六条逐条反向验证变红
（改回单向滚动 / 轨道头不跟 / 标尺不钉 / 另一轴又被夹 / 框选不补纵向量 /
跨轨判定不补纵向量）。

## 教训 / 防回归

1. **「谁决定容器高度」要想清楚。** 一个裸 `VStack` 摆在分栏里，就是在替整条
   界面要地方。要它随视口走又不影响布局，就画在 `Color.clear` 这种弹性容器上。
2. **`.clipped()` 只裁绘制不裁命中**（第三次栽在这条上了，前两次是缩略图和
   隐藏轨），裁完记得补 `.contentShape`。
3. **推一个轴的时候别顺手夹另一个轴。** 居中的内容的 origin 是负的，夹一下就把
   居中抹了。这类「顺手归一化」在坐标代码里永远是 bug 的温床。
4. **注释里出现的代码片段会让扫描守卫假绿。** 第 10 节反向验证时踩到：文件头的
   说明文字里正好写着那行代码的样子，撤掉真代码后守卫照样绿。守卫统一走
   `grep_code`（只看非注释行）。
5. 长期约束写进
   [docs/architecture/timeline-drag-gestures.md](../architecture/timeline-drag-gestures.md)
   §5c；人工回归清单也补了三条（自动化够不着「滚起来跟不跟手」这种）。
