# 2026-08-12 框选复审的五条后续

## 症状

鼠标框选（`feat(timeline): select a batch by dragging a box`）落地后的复审提出
五条，逐条复现属实：

1. **高** 最终落地仍可能拆散「全组同一 delta」。跨轨拖进**有占位**的目标轨时，
   到岸让位只让被拖的那一个；链接音频停在让位之前的位置 —— A/V 当场错位。
   另一半是磁吸：`perform` 对任何改动都会再 `packMain()` 一次，从形状/非主轨块
   起拖而混选里有主轨块时，主轨块先跟着画了一路、松手被排回原处。
2. **高** 多选时只带上**被拖那一个**的链接组。框选 A、B 两段且各自都有分离出来
   的音频时，拖 A 只会带 A 的音频；B 会动、B 的音频不动。
3. **高** 字幕 cue 根本没有移动手势（只有 `onTapGesture`），`ClipDragSession.Subject`
   也只有 clip/shape。文档写的「拖任意一个被选中的东西，整片跟着走」对 cue 只成立
   一半 —— 只能反过来「拖剪辑时 cue 跟着」。
4. **中** 框选纵向命中的是**整行**。字幕块只有 14pt 高、上下各留 4pt，形状块 20pt、
   上下各留 3pt；框只从留白里扫过、一个像素都没碰到块，照样选中。
5. **低** 权威文档已与实现冲突：字幕架构文档仍写「三类选择互斥」并引用已删除的
   单数属性，AGENTS 索引仍写「四类选择互斥」。

## 根因

前四条是同一个模式的四个面：**「整组同一位移」这个不变量在链路上有四处没收口**。

- 落地那一步（第 1 条）：`applyDrag` 只在磁吸插空那条分支里按实际落点重平伙伴，
  跨轨那条没有。跨轨到岸的让位（`clampedStart`）发生在 `relocateClip` 内部，只认
  被拖的那个 id。
- 名单那一步（第 2 条）：`movingClipIDs` 先把 `linkedClipIDs(of: id)` 并进来、
  再并 `selectedClipIDs` —— 后并进来的那批**没有**再展开各自的链接组。顺序写反了。
- 手势那一步（第 3 条）：三类块里只有两类接了移动手势。
- 命中那一步（第 4 条）：`Row` 只带了行的上下边界，画块时的留白没有进模型。

第 1 条的后半段（磁吸）另有一层：`perform` 是所有改动的必经之路，磁吸开着时它
**总会**再 `packMain()`。而端到端自检只调 `applyDrag`，看不见这一步 —— 于是
「拖动中看到的 = 松手落到的」这条最核心的约束，在最容易违反的场景上假绿。

## 修复

**纯值层**（自检够得着的地方）：

- `TimelineState.draggingClipIDs(seed:linkage:magnetPinsMainTrack:)` 新增，成为
  三个拖动入口（剪辑 / 形状 / cue）唯一的名单来源。先并多选、**再**为每一个成员
  各展开一次链接组；磁吸开着且这一轮拖的不是主轨块时，主轨成员整批剔除。
- `TimelineState.applyDrag` 收尾统一调 `realignCompanions`：按**被拖块的实际落点**
  把伙伴再平一次（按冻结 span 算绝对值，所以幂等）。跨轨让位和磁吸插空这两处
  「落点不等于 `resolution.delta`」的情形因此都收口了。
- `applyDrag` 自己做 `if magnet { packMain() }`，产物即最终状态；`perform` 之后
  那次重排变成幂等的。

**接线层**：

- 字幕 cue 块补上与剪辑/形状**同一套**的移动手势（同一个坐标系、同一个自动滚动、
  `beginCueDrag` 冻结输入、`endClipDrag` 落地），`ClipDragSession.Subject` 加
  `.subtitleCue`，`VideoEditProject.cueDragPlan` 与 `shapeDragPlan` 严格对称。
- `commitShapeDrag` 更名 `commitFreeDrag`（形状和 cue 共用），并如实传全局磁吸开关。
- 框选命中的纵向范围改成**画出来的块**：`TimelineMarquee` 新增
  `cueTopInset` / `cueHeight` / `shapeTopInset` / `shapeHeight`，画块和喂给命中判定
  的行模型共用这批常量。

**文档**：字幕架构文档的「三类选择互斥」重写为「点选互斥 / 框选混选」并更正属性名；
`clip-markers.md` 的「四类互斥」改为「标记对所有其他选择互斥」并说明框选之后为什么
它没松动；AGENTS 两条索引同步；新约束写进 `timeline-drag-gestures.md`。

  剔除且端到端一动不动、多选时每个成员的链接组都展开、框选纵向只认块不认留白。
- **`performDrag` 补上 `perform` 的那次 `packMain()`** —— 这是消除假绿的关键一步。
- `checks/timeline-drag-wiring.sh` 新增：三个入口都必须走 `draggingClipIDs`、
  `applyDrag` 必须有 `realignCompanions` 与磁吸重排、cue 块必须真的接上移动手势、
  `marqueeRows` 必须用那四个纵向常量且画/判各用一次。

  - 撤掉 `realignCompanions` → 6 项红（含跨轨那条「不是停在 6」）。
  - 撤掉磁吸剔除 → 1 项红。
  - 链接组退回「只展开一个」→ 2 项红。

## 教训 / 防回归

1. **不变量要在链路的每一步都收口，不能只在最典型的那条分支上。** 「整组同一
   位移」在四个地方各漏一次，四条复审意见其实是同一个 bug 的四个面。
2. **自检的入口必须和生产的入口一样深。** `applyDrag` 是纯值的、好测，但生产
   路径是 `perform(applyDrag)`；只测前者就会漏掉「后者还会再排一次」。凡是生产
   路径上还有后续步骤的，自检要么走完，要么在用例里显式复刻那一步。
3. **「数个数」的守卫容易假绿。** 计数会把无关的同类结构算进去；按结构定位
   （取函数体、按块型查）才可靠。
4. **画和判必须共用常量，纵向和横向一视同仁。** 横向最小宽度当初已经踩过一次并
   抽了常量，纵向却漏了 —— 同一个教训的另一半。
