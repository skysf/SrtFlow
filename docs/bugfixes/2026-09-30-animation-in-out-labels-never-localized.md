# 2026-09-30 动画行的「In」「Out」、字体目录的「Chinese」「Other」从没进过表

## 症状

剪辑页选中一段，检查器「动画」那一块两行的标签在中文界面里是英文「In」「Out」；文字的
动画那一块一样。给文字挑字体的目录里，两个分组的标题「Chinese」「Other」也是英文。
从这几处写出来那天起就这样（2026-09-17、2026-09-18），一个多月没人报 —— 两个词太短，
混在一堆中文里不扎眼。2026-09-30 做西班牙语时在真窗口里逐面板看才看见。

## 根因

这几条文案都是**经参数转交**的：`animationRow(clip, title: "In", …)`、
`section("Chinese", families: …)`，参数类型是 `LocalizedStringKey`，查表是查的，只是键从没进表。
覆盖守卫 `scripts/check-localization-coverage.sh` 对「经参数转交的文案」靠一份**手抄的清单**：
调用名（`labelledSlider`、`decorationRow`…）和参数标签（`help:`、`label:`），清单外的一律看不见。
`help:` 漏过一轮（2026-08-12）、`label:` 漏过一轮（2026-09-17），`title:` 和位置参数的
`section(_:)` 是第三、第四次 —— 同一个教训撞了四次，说明「靠人往清单里补」这个办法本身是错的。

## 修复

- 守卫不再靠手抄：`checks/LocalizationCoverage/KeyParameters.swift` 扫源码里所有 `func` 声明，
  凡是有 `LocalizedStringKey`（含可选）类型参数的函数，调用点自动纳入 —— 头一个且没标签的
  按「第一个实参就是文案」扫，带标签的只在**这个函数名**的调用里认那个标签（`FalModel(title:)`
  这种收 `String` 的同名标签不会被误报）。原来的清单留着（结构体的成员初始化器扫不到 `func`）。
- 四条键进三张表：`In` / `Out`（入场 / 出场、Entrada / Salida）、`Chinese` / `Other`
  （中文 / 其他、Chino / Otras）。

## 验证

- 新守卫接上、表没补之前跑一遍：12 处红（4 条键 × 3 张表），红的正是这四条，没有别的漏网。
- 补表之后绿。反向验证：从 en 表里删掉 `"In"` → 红，恢复 → 绿；把 `keyParameterPatterns` 那一行
  摘掉再删 `"In"` → 老守卫照样绿（证明是新机制抓到的）。
- 真窗口：中文和西班牙语界面下动画两行、字体目录两个分组都换了语言（进程内冒烟截图）。

## 教训 / 防回归

- **「靠人往清单里补」的守卫，每漏一次都是同一个教训。** 能从声明里推出来的就别手抄：
  参数类型写着 `LocalizedStringKey`，给它传的字面量就一定是键。
- 短词最容易漏：「In」「Out」两个字母夹在中文里没人看见。新写的行加了文案，跑一遍守卫。
- 长期约束写进 [本地化](../architecture/localization.md) 第一节（守卫扫什么）。
