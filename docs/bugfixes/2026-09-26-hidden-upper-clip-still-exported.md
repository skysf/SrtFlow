# 2026-09-26 上层轨上按 V 藏起来的段，成片里画面还在

## 症状

用户原话：「目前已经隐藏的内容，仍然会导出」「有画面，但是预览的时候是不会播放的」。

上层视频轨上选中一段按 V（或右键 Hide Clip）：时间线上它灰了、带斜杠眼睛，预览里这一段也没了；
导出成片里这一段的**画面照旧在**（上层轨默认铺满画布，所以整段盖住主轨）。声音倒是没有。

主轨上按 V、整条轨的眼睛、音频轨、字幕的眼睛这几条都是对的。

## 根因

1. **导出图里叠上层轨的那一圈按轨取段，只滤了藏起来的轨。** `VideoEditExportGraph.plan` 开头算好了
   `overlayVisible`（藏起来的轨、藏起来的段、还在转静帧的都滤掉了），可它只拿去判断「有没有画面」；
   真正往滤镜图里叠上层段的循环、以及逐帧动画段的预渲染那一圈，都是
   `for lane in overlayLanes { for clip in lane.clips … }` —— `overlayLanes` 只滤了轨，段上的 `isHidden`
   没人看。V 是 2026-09-18 加的（`7001b58`），那次把主轨、`isAudioOnly`、静帧检查都换成了
   `ClipVisibility.visible`，这两圈老循环没跟上。
2. **声音为什么没漏**：成片的声音是预览那份合成离线读出来的（`ExportAudioMixdown`），预览合成的上层轨
   走 `ClipVisibility.visible(lane.clips)`，本来就滤掉了。所以只漏画面 —— 这也是用户看到「有画面」的原因。
3. **守卫为什么一直绿**：
   - 扫描守卫只要求 `VideoEditExportGraph.swift` 里**出现过** `ClipVisibility.visible(`，主轨那一行就满足了。
     这是仓库里第 N 次「出现过 ≠ 接上了」（同 [框选复审](2026-08-12-marquee-review-followups.md) 里
     「数个数的守卫也会假绿」）。
   - 真取帧的自检（`check-preview-composition.sh`「藏起来的段所在时刻是黑场」）只测了**预览**、只测了**主轨**；
     真导出的那几份检查（`check-video-fade.sh` 等）里一段藏起来的都没有。

## 修复

- `VideoEditExportGraph.swift`：预渲染那一圈和叠上层轨那一圈都改成只遍历 `overlayVisible` 这一份清单
  （轨按数组顺序、轨内按段的顺序，和原来按轨嵌套遍历的叠放次序一样）。清单只有一份，判断「有没有画面」、
  预渲染、叠画面用的是同一个。

## 验证

- `scripts/check-video-fade.sh` 新增 `checks/VideoFade/HiddenClips.swift`：白色主轨上叠一段黑色上层视频
  （铺满），真跑导出、抽第 3 秒画面中心的像素，四份：
  - 没藏 → 中心是黑（**对照**：证明这个场景里上层段真的盖得住主轨，否则「藏了之后是白」什么也说明不了）；
  - 按 V 藏了 → 中心是主轨的白；
  - 按 V 藏了、还带擦除入场（走预渲染那一圈）→ 白；
  - 整条轨藏了 → 白。
- **反向验证**：把两圈临时改回按轨取段（`overlayLanes.flatMap(\.clips)`），「按 V 藏了」和「带入场」两份
  变红（中心实测 0.0，黑色上层段漏进了成片），其余照绿；恢复修复后 77 项全绿。
- `scripts/check-project-file.sh` 加一条扫描：`VideoEditExportGraph.swift` 的代码行里不许再出现
  `in lane.clips`（旧代码两处都命中，新代码零处）。它只挡「又回到按轨取段」的写法，真正的守卫是上面的真导出。

## 教训 / 防回归

- **「过滤清单」算出来了，就让每一个消费者都走它。** 同一份时间线在一个函数里被「按清单」和「按轨嵌套」
  两种方式遍历，加一种隐藏时只改到其中一种。
- **两条管线都要有真产物的守卫。** 预览取帧钉住了预览，导出这一侧只有字符串扫描；隐藏这种「决定成片里有没有
  这一段」的语义，要在真导出的成品上看一眼。
- 长期约束（两级隐藏的渲染语义、各条链路在哪过滤）见 [段的显隐](../architecture/clip-visibility.md)。
