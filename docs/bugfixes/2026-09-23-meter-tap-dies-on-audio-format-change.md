# 2026-09-23 一条轨上换了音频格式，从那儿起没声音、预览卡住

## 症状

装上修好缩略图的 0.12.0 之后，打开 `AI_Video_SouthPole/Edit.srtflowproj` 播放：

- **预览卡顿，有时干脆播不动**；
- **第二条音频轨（绿色那条）从 `Speak1Voice_Sky` 起往后都没声音**。

时间线上波形都在，导出也正常，只有预览出问题。

## 根因

当天新加的电平表（159cf3f）在**每条合成音轨**上挂了一个 `MTAudioProcessingTap`。

预览合成原来是**一条时间线轨对应一条合成音轨**（主轨是 A/B 两条），上面的段按时间排进去，
不管各段的源音频是什么格式。这个工程里恰好好几条轨都在中途换了格式：

| 轨 | 前面的段 | 换成 |
| --- | --- | --- |
| 音频轨 2（绿） | 48kHz 立体声 mp3（鱼缸气泡、快速水声） | 26.3s 起 44.1kHz 单声道 mp3（Speak1Voice_Sky…） |
| 音频轨 3 | 48kHz 立体声 mp3（企鹅声音…） | 20.8s 起 mp4 里的 AAC（Shot_hold_Baby_A） |
| 主轨 | 48kHz AAC | 63.1s 起 32kHz（Shot4），后面还换了 32kHz、44.1kHz 几次 |

**同一条合成音轨上源格式一变，挂在上面的 tap 就被 AVFoundation 重新 prepare
（prepare → unprepare → prepare → prepare → unprepare），之后再也不被调用**：

- 那条合成音轨从那儿起没有声音。播放器会提前几秒往下读，所以断的地方比换格式的地方还早
  （绿轨在 3.5 秒左右就断了，而格式在 26.3 秒才换）；
- 从换了格式之后的地方起播，而这时候只有这条轨在出声的话，**播放器干脆不走**：时间停在原地，
  `timeControlStatus` 却还是「在播」；
- 离线的 `AVAssetReaderAudioMixOutput` 一样：这条轨后面读出来是静音，或者整个读取卡死。
  用旧的合成去读这份工程（挂着电平表），读到一半就再也不返回。

逐项实验定的性（最小装置：一条合成音轨，两段隔 3 秒，静音的 AVPlayer 起播，看 tap 在哪些秒被调到）：

| 两段 | tap | 结果 |
| --- | --- | --- |
| 48kHz 立体声 mp3 → 同格式另一个文件 | PreEffects | 0–13 秒一直有 |
| 48kHz 立体声 mp3 → 44.1kHz 单声道 mp3 | PreEffects | **只有 0–2 秒** |
| mp3 → AAC（都是 48kHz 立体声） | PreEffects | **只有 0–2 秒**（只换编码也算） |
| 48kHz 立体声 mp3 → 44.1kHz 单声道 mp3 | PostEffects | **只有 0–2 秒**（换 flag 没用） |
| AAC 96k → AAC 256k（只差编码参数 / magic cookie） | PreEffects | 一直有（不算换格式） |
| 同一个文件，第二段 2 倍速（spectral） | PreEffects | 一直有（变速不算） |
| 换格式，从第二段里起播 | PreEffects | **播放头停在 9.00 不动，状态却是「在播」** |
| 换格式，从第二段里起播 | 不挂 tap | 正常播完 |
| 同格式，从第二段里起播 | PreEffects | 正常播完 |

以前为什么没事：电平表是当天才加的；之前的第 8 组自检全用同一个现造素材，一条轨上从来没换过格式。

### 查的过程

1. **先排除数据**：用生产的 `VideoEditCompositionBuilder` 给这份工程建合成，离线读出每条合成
   音轨（不挂 tap）：绿轨 26–36 秒 RMS 0.05–0.065，`audioMix` 的音量也是 1.0。时间线、合成、
   混音参数都没错，问题只在**实时播放**里。
2. **在真 App 里打点**（静音播放，不打扰人）：每条 tap 按秒记收到的峰值。播到 58 秒时，绿轨的
   tap 只记到第 3 秒、第三条音频轨只记到第 17 秒，别的轨一直有；tap 没报过错，也没收到过空缓冲
   —— 就是**不再被调用**了。
3. 对格式：还活着的轨都是清一色一种格式，死掉的两条都在中途换了格式。上面那张表的实验定了性。
4. 顺手排除的：播放时整条时间线的块每一拍都重算 body（调试构建里每秒约 850 次），但缩略图和
   波形的 Canvas **没有**跟着重画，所以不是它。

## 修复

**一条合成音轨只装一种源音频格式**（`Sources/SrtFlow/VideoEditCompositionAudioTracks.swift`）：

- `CompositionAudioTracks` 按「时间线上的哪条轨 × 源音频格式」发放合成音轨。主轨仍按 A/B 槽分
  （转场的两段要叠在两条轨上），每个槽、每条上层视频轨、每条音频轨遇到新格式就另开一条，
  同格式的段接着排在原来那条上。插入游标跟着每条合成轨走。
- 「同一种格式」= 流格式（编码、采样率、声道数……）加声道布局相同，**不比** magic cookie
  —— 实测只差码率的两个 AAC 不会让 tap 重新 prepare，再细分就是白开轨。
- `VideoEditCompositionBuilder` 的主轨、上层视频轨、音频轨三处都改成从它要轨。空轨照旧在收尾时
  删掉，所以不再预先建两条主轨音轨。
- 别的都不用动：`makeAudioMix` 本来就按合成轨一条条铺音量，「提前钉音量」钉在同一条合成轨
  上一段的结尾（分出来的轨之间全是空档，照样成立）；电平表按时间线轨归并，几条合成轨按绝对
  位置相加（和主轨 A/B 同一个办法），表上看不出分了几条。

这份工程从 7 条合成音轨变成 12 条：音频轨 2、3 各两条，主轨五条（A/B 两个槽 × 48kHz / 32kHz，
外加一段 44.1kHz），其余不变。

没选的路：换 PostEffects（实验证明没用）；遇到格式变化就不给那条轨挂 tap（能出声，但那条轨的
表和总表都不完整）；不用 tap、改拿波形数据算表（要推翻当天刚定的电平表架构，总表的真实峰值
也没法从每轨的 min/max 算出来）。

## 验证

- **这份工程，实时**（命令行里用生产的合成 + 生产的电平表，静音 AVPlayer 播放，每秒在播放头处
  读表）：
  - 从 23.2 秒起播（用户截图的位置）：旧的合成下绿轨一直是 0.00；修后在 Speak1Voice_Sky 那几秒
    读到 0.36、0.32、0.11、0.33、0.36。
  - 从 65 秒起播：旧的合成下主轨一直是 0.00（Shot4 是 32kHz，就在这里）；修后是
    0.05 → 0.56 → 0.14，到下一段（静音段）变回 0。
  - 先从 0 播 6 秒、再点到 23.2 秒起播：旧的合成下绿轨照样没声音。
- **这份工程，离线**（挂着电平表读前 60 秒）：旧的合成读到一半卡死，不再返回；修后 60 秒读完，
  每条轨换格式前后表上都有声音（绿轨 Speak1Voice_Sky 峰值 0.462、第三条音频轨的 AAC 段 0.125）。
- **回归守卫** `scripts/check-audio-fade.sh` 第 8b 组：一条音频轨上 48kHz 立体声 → 44.1kHz
  单声道、主轨 A 槽上同样换一次格式，断言（1）每条合成音轨只装一种源格式（结构不变量，不依赖
  AVFoundation 的脾气）；（2）挂着电平表离线读得完（普通线程上的看门狗，60 秒）；（3）换格式
  之后表上、真实混音里都有声音。反向验证（换回旧的合成）：
  - `FAIL 一条合成音轨只装一种源格式（混了格式的合成轨：[5]）`
  - `FAIL 换格式之后表上照样有声音（前 0.091、后 0.0）`
  - `FAIL 换格式之后真实混音里也有这一段（峰值 0.0）`
  - `FAIL 主轨的 A/B 槽也按源格式分开（混了格式的合成轨：[3]）`
  - `FAIL 主轨上换了源格式，挂着电平表离线读 60 秒没读完…`，退出码 1。
  恢复后 135 checks, 0 failures。
- 第一次写这组断言时自己错了一次：电平表的环默认只留约 5.5 秒，10 秒长的用例读 1–3 秒时早被
  6.5–8.5 秒覆盖，量到 0。长用例要自己开大环（`metered(_:ringCapacity:)`）。
- `scripts/check-all.sh` 全绿。

## 教训 / 防回归

1. **往 AVFoundation 的实时管线里挂东西（tap、效果）之前，先想「一条合成轨上的素材不是同一种
   格式」**。合成轨对播放器来说是一条连续的流，素材的格式却是各段各的；AVFoundation 自己能
   处理格式变化，挂上去的东西不一定能。长期约束写进 [推子与电平表](../architecture/audio-mixer.md)
   第三节第 7 条。
2. **自检的素材不能只有一种**。第 8 组所有用例共用一个现造的 48kHz 立体声素材，「一条轨上换了
   格式」这个真实工程里再常见不过的情况从来没出现过。同一类盲区见
   [2026-08-12 渐入开头爆音](2026-08-12-audio-fade-in-pop.md)（场景全落在默认值上）和
   [同一天的波形死锁](2026-09-23-waveform-decode-deadlocks-thread-pool.md)（一次只读一个文件）。
3. **「没声音」先分清是数据错了还是实时管线出了事**：用生产的合成离线读一遍（不挂 tap），
   数据对就只剩实时那一段，范围立刻缩小。
4. 查实时播放可以不出声：静音的 AVPlayer 在命令行里一样跑实时管线，tap 回调照样被调
   （做法写进 [GUI 冒烟流程](../testing/gui-smoke-testing.md)）。
