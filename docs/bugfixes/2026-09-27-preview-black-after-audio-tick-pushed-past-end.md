# 2026-09-27 加了几段音效，预览整个黑屏（标题照样在）

> 用户在测 AI 接口（PR #81）时遇到的，但 bug 在预览合成器里，**正式版 0.16.1 一样**。
> 长期约束写进了 [预览自由变换](../architecture/preview-free-transform.md)「两条渲染管线，一份时间账」。

## 症状

南极工程里，用户让 Claude Code 加了几段音效（`素材A/SrtFlow/音效/*.wav`）。之后预览只剩黑底：
标题「南极之旅」这类文字照样显示，视频画面从头到尾都是黑的；换正式版 SrtFlow 0.16.1 打开同一个
工程也一样。

## 根因

预览合成器（`VideoEditCompositionBuilder`）把时间线上的秒数换成 1/600 秒的格子时用的是
`CMTime(seconds:preferredTimescale:)`，它**向零截断**。音效轨上的第三段从 5.3 秒开始、长 1.4 秒，
算下一段前的游标是 `5.3 + 1.4`，在浮点里是 `6.699999999999999`，截断落在**第 4019 格**，而这一段
自己明明插到了第 4020 格。

接下来要补一段空白、再接后面的音效。`insertEmptyTimeRange` 是「插入」不是「覆盖」：空白从 4019 插进去，
正好切进前一段音效的最后一格，把这一格挤到空白后面；后面每插一段，它就再被往后挤一次，最终落到
**全片最后，25.0 秒之后**。于是这条音轨比画面长 1/600 秒，整个合成变成 25.0017 秒，而视频合成的指令
只铺到 25.0 秒：合成被判无效，播放器不画画面。文字、形状这些叠层是 SwiftUI 画在播放器上面的，
所以照样看得见。

实测证据（用 App 自己的合成代码离线合成这份工程）：

```
track 8 soun 0.0000 → 25.0017 segments 8
    target 3180/600 +839/600 source 0/600 +839/600      ← 被切剩 839 格
    target 4019/600 +7681/600 EMPTY                      ← 空白从 4019 插进去
    ...
    target 15000/600 +1/600 source 839/600 +1/600        ← 那一格被挤到全片最后
video instructions last end 25.0 (15000/600)
  ✗ empty time range 25.0 → 25.001666666666665
videoComposition valid: false
```

排查过程：用进程内冒烟把工程的几种变体逐个打开、量预览区亮度：去掉滤镜照样黑，去掉音效就好；
三条音效轨里只有一条会黑；那条轨上前三段单独、后两段单独都好，**五段放在一起才黑**。
单看任何一段都找不到问题，是「中间一段空白 + 前后都有段 + 最后一段收在全片结尾」这个结构
加上浮点零头一起触发的。

为什么以前没人遇到：手动拖出来的时间一样是任意浮点数，也会碰上；但还得最后一段正好收在全片结尾，
被挤出去的那一格才会越过画面结尾，这两个条件同时满足才会黑屏。AI 喜欢把音效整整齐齐地收在结尾
（`22.6 + 2.4 = 25.0`），一下就撞上了。

## 修复

新的 `CompositionTime`（`Sources/SrtFlow/CompositionTime.swift`）。合成器往合成轨上接素材、空白、定格，
以及声音场景的余音载体，都走它的两条规矩：

1. **只往合成轨真正的末尾后面接**（`pad` / `appendPoint`）：空白从合成轨现有片段的末尾开始补，素材的
   落点不早于这个末尾；不信 Double 算出来的游标，已经插好的内容就不会再被挤走。只比末尾晚一格的也
   直接接在末尾（首尾相接的两段各自截断会差一格），和以前「差不到 0.5 毫秒不补」同一个意思。
2. **合成完把每条合成轨裁到时间线总长**（`trim`）：视频合成的指令只铺到总长，将来不管哪里再多出一格，
   也只会被剪掉，不会让整个预览黑掉。时间线上没有东西会落在总长之后，剪掉的只可能是换算的零头
   （声音场景的余音载体本来就只垫到工程结尾）。

**秒换格子照旧截断，没改成四舍五入。** 第一版修复（a85de19）三层都做了，另外把换算改成了四舍五入。
结果 CI 第 3 组的声音渐变自检卡死：日志停在「运行」，28 分钟没有一行输出，最后被 30 分钟超时掐掉。
同一份代码在本机（macOS 26）40 秒跑完、198 项全过；CI 是 macOS 15。在本机给那一版加打印排查了三个
猜测：首尾相接处多出一格空段、从素材里取的范围超出素材末尾、余音载体插进最后一段里面。在这项自检的
场景里三种情况一次都没出现，确切原因没有找到。截断保证从素材里取的范围永远不超出素材本身，是 CI 上
一直跑得通的老行为，而上面两条规矩已经足够修黑屏，所以换算退回截断。

导出的画面走 ffmpeg，不受影响。导出的声音是离线读这份预览合成（[成片的声音](../architecture/export-audio-mixdown.md)），
以前会在最后多带一格，现在一起修好了。

## 教训 / 防回归

- **`CMTime(seconds:preferredTimescale:)` 会截断。** 两个本该相等的时间，在浮点里差一丝，就会落在相邻的
  两格。不要拿两处各自换算出来的格子去对齐，要拿真实的 CMTime（合成轨的末尾）说话。
- **AVFoundation 的 insert 是「插入」。** 落点早于末尾一格，就会把已有内容挤走，而且不报错。往合成轨上接
  东西，落点以合成轨自己的末尾为准。
- **视频合成的指令和合成的总长必须严丝合缝。** 多一格就判无效，而且症状是「黑屏」，不是报错。在收尾处
  统一对齐（裁到总长），比保证每一处都算对更可靠。
- **修 bug 时别顺手改一个到处都在用的换算。** 四舍五入看起来「更对」，但它同时改了所有从素材里取的范围，
  在另一个系统版本上把一项跟黑屏无关的自检卡死了。修法只动出问题的那一步。
- **会阻塞的自检要带看门狗。** 卡住时一行输出都没有，比红了更难查。
- **二分变体时要一直分到能复现的最小组合为止。** 单看哪一段都没问题，要把「几段 + 空档 + 收在结尾」
  这个组合找出来，根因才露出来。
