# 2026-09-24 预览里想拖文字，一按下去变成旋转

## 症状

用户反馈：「文字和数字在 preview window 里，我有时候想要移动，很容易就变成 rotate，操作很困难。」
截图里是南极那条片子的标题：数字「090」和文字「° SOUTH」并排，数字选中着，选中框很扁、很宽
（左边一直伸出画面外）。

「有时候」是关键：按在字的**正中间**附近是旋转，偏开一点又是移动。黄色的旋转把手本身反倒拖不动。

## 根因

**一、旋转把手的可点范围写在了 `.offset` 之后。**

```swift
Circle()
    .frame(width: 10, height: 10)
    .offset(y: -frame.height / 2 - 22)      // 画面挪到框的上方
    .contentShape(Circle().inset(by: -6))  // ← 按的是没挪过的布局框
    .gesture(rotateGesture)
```

`.offset` 只挪画面、不挪布局框（这条仓库里栽过一次：
[popover 锚在行首](2026-08-12-cue-popover-anchored-at-row-origin.md)）。写在它后面的
`contentShape` 按的是没挪过的那个 10pt 小框 —— 也就是选中框的**正中心**。于是：

- 文字正中心有一个看不见的、直径 22pt 的旋转区，而且选中框整个画在所有字的可点范围**上面**；
- 画出来的黄点底下什么都没有，点它等于点空白。

探针（`Circle` + 同样的修饰器顺序，进程内合成事件，2026-09-24）逐点量：

| 按在哪儿 | 修复前 | 把 `contentShape` 挪到 `.offset` 前面 |
| --- | --- | --- |
| 框的正中心（字上） | 旋转 | 移动 |
| 偏中心 8pt | 旋转 | 移动 |
| 偏中心 14pt / 100pt | 移动 | 移动 |
| 黄色旋转把手 | **没反应** | 旋转 |

**二、可点范围是整个版面框，而版面框默认占画面宽度的 80%。** 「090」这么短的数字也有
80% 宽，和旁边「° SOUTH」的框互相盖着，点在一段字上可能选中另一段 —— 这不是「变成旋转」的
原因，但让「在一堆字里拖准一个」更难。

## 修复

1. `VideoEditTextFrameBox.swift`：旋转把手的 `.contentShape` 挪到 `.offset` 前面。
2. 可点范围改成 `TextHitGeometry`（新文件 `VideoEditTextHitGeometry.swift`，一次排版算出版面框
   和「看得见的那一块」）：
   - 没选中的字：只有看得见的部分能点（墨迹四周外扩 6pt；开着底板时整块底板都算）；
   - 选中的那段：另垫一块整个版面框，框里的空白处也能拖 —— 垫在所有字的可点范围**下面**，
     点在别的字上还是选别的字；
   - 空文字（刚 Add 出来）：整个版面框。
3. `TextOverlayCanvas` 每次 body 只排一次版（以前命中区、选中框、就地编辑框各排一遍）。

长期约束写进 [画面文字](../architecture/text-overlays.md)「把手的可点范围必须写在 `.offset`
之前」与「预览上点得着哪里」。

  写在同一条修饰器链里的 `.offset` / `.rotationEffect` / `.scaleEffect` / `.transformEffect`
  之后就红。全仓只有这一处。**反向验证**：把修复撤回去 → 红，点名

  **反向验证时把 y 轴翻转写反，它照样绿**：单行的墨迹上下都顶满排版框，翻没翻对看不出来。
  补了一个两行 + 2.5 倍行高的样本（上下留白不对称）之后，写反立刻红（99/100），恢复转绿。
- **真窗口**（进程内冒烟，用户的南极工程拷贝，播放头 5 秒，`scripts/gui-smoke/in-process/run.sh`，

  | 操作 | 修复前 | 修复后 |

  | 按住「090」正中间往右下拖 30×15pt | **转了 127.7°**，位置不变 | 移动（centerX 0.323→0.381、centerY 0.374→0.426），角度 0 |

## 教训 / 防回归

1. **`.offset` 只改渲染不改布局框，这条的命中版和 popover 版是同一件事**：写在几何效果之后的
   任何「按布局框算」的修饰器（`contentShape`、`popover`、`background`、`border`）都留在原位。
   这次把它升成了全仓的扫描守卫，而不只是改一处。
2. **自检样本要能区分「对」和「对称的错」**：单行文字的墨迹上下对称，y 轴写反和写对算出同一个框。
   反向验证之所以必须做，就是因为第一版守卫在这里假绿了。
3. **「有时候会这样」往往是空间上的分区**：这次的「有时候」是「按在离中心 11pt 以内」。拿探针逐点
   量一遍，比猜手势优先级快得多。
