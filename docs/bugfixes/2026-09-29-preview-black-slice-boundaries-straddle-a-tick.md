# 2026-09-29 叠化 + 关键帧之后预览全黑，去掉转场、关键帧照样黑

> 用户拿 AI 接口（Claude Code 经 MCP）剪婚礼视频时撞上的，报的是「时间线上有交叉溶解转场时，给几个片段加缩放
> 关键帧，整条时间线预览全部变黑，连没加关键帧的片段也黑；重新打开项目也不恢复；全部用硬切时 9 个片段加关键帧
> 都正常」。bug 在预览合成器里，正式版 0.16.1 一样。长期约束写进了
> [预览自由变换](../architecture/preview-free-transform.md)「一份时间账」③④、
> [主轨转场](../architecture/transition-handles.md)「接缝的零头」、[关键帧动画](../architecture/keyframe-animation.md)「预览切片」。

## 症状

婚礼 B 版（`婚礼_B版_温馨电影感.srtflowproj`，10 段主轨、一首配乐、5 段文字、24 fps）预览从头黑到尾，标题这类叠层
照样在。用户以为是叠化 + 缩放关键帧的组合，于是重做了一版只留 3 个推镜（v2，好的），并把旧 B 版留下来复现。
旧 B 版存盘时转场已经全部去掉，关键帧还在 7 段上 —— 照样黑。

## 根因

用 App 自己的合成代码离线合成这份工程（探针见下），视频合成被判无效，指令表空出两格：

```
  !! instr 6 start 11976 end 13080 layers 2 prevEnd 11975
  ✗ empty time range 11975/600 → 11976/600     ← 第 5 段收在 19.9598、第 6 段从 19.96 起
  ✗ empty time range 19325/600 → 19326/600     ← 最后一段画面收在 32.2097、配乐收在 32.21
videoComposition valid: false
```

`buildVideoComposition` 把所有切片边界（段的起止、渐变的起止和半程、关键帧、推移 / 擦除的窗口）攒成一个
`Set<Double>`，排序后**按秒**切片：相邻两个边界差不到 0.5 毫秒就跳过那一片。可每一片的 `CMTimeRange` 是把两个
边界**各自**用 `CMTime(seconds:)` 截断到 1/600 秒的格子上得来的。19.9598 落在第 11975 格、19.96 落在第 11976 格，
中间那片被「太短不切」跳过，于是前一片收在 11975、后一片从 11976 起，指令表空出一格；AVFoundation 要求指令表
铺满整个合成，空一格就整个判无效，播放器一帧都不画。

零头从哪来：第 5 段（111.MP4）被 AI 设成 0.94 倍速，真正收在 17.98 + 1.861 / 0.94 = 19.9598；`get_timeline`
把它报成三位小数 19.96，AI 就把下一段放在 19.96。最后一段 0.7557 倍速收在 32.2097，配乐整整齐齐收在 32.21。
**和转场、关键帧都没关系**：去掉全部关键帧、全部转场，旧 B 版照样无效。关键帧和转场只是各自多添几个挨得近的
边界（关键帧就打在段的起止上、转场的半程正好落在接缝上），让「两个边界跨了一格」更容易碰上 —— 加上叠化之后
空出的格子从两处变成四处。A 版、C 版、D 版是运气好：所有相邻边界要么正好同一格、要么差超过半毫秒。

用户自己核查后写的报告（`~/Downloads/婚礼素材/SrtFlow/SrtFlow_MCP问题反馈报告_2026-09-29.md`）把这件事拆成了两条：
BUG-01「0.213 毫秒的缝隙」（附最小复现工程 `BUG复现_黑屏_0.2ms缝隙_最小.srtflowproj`：没有关键帧、没有转场）和
BUG-02「叠化 + 某几段的缩放关键帧，工程里没有缝隙，根因未定位」。**两条是同一个根因**：拿 v2（接缝全部连续）按
BUG-02 的对照表给三段加缩放关键帧，修前的合成器在第 10997 / 10998 格之间空出一格（叠化窗口里关键帧的边界和渐变的
半程各自截断落在相邻两格），判无效；修后有效。报告里「A 版 14 段带关键帧一直正常」也是运气。

顺带查出第二件事：指令表接上之后，第 11975 格上 A/B 两条合成轨**都没有画面**（前一段的片段收在 11975、后一段
从 11976 起），24 fps 的第 479 帧正好落在这一格，接缝上闪一帧黑；而成片的分节早就不给 0.01 秒以内的缝补黑场
（`clip.timelineStart > cursor + 0.01` 才补），成片是连着的 —— 两条管线各说各话。

## 修复

1. **切片表先落格子再去重**（新文件 `Sources/SrtFlow/CompositionSlices.swift`）：每个边界先按 `CompositionTime.tick`
   截断到格子上，同一格只留最早的那个边界，相邻两格之间一片；第一片从第 0 格起、最后一片收在总长那一格。片的
   `CMTimeRange` 就是这两个格子，所以指令表按构造首尾相接；求值照旧用边界本身的秒（关键帧、渐变的半程都是精确的
   折点）。`VideoEditCompositionBuilder.buildVideoComposition` 只管每片里谁可见、变换 / 裁切 / 透明度怎么算。
   秒换格子的截断收进 `CompositionTime.tick`，插段和切片表用同一个。
2. **主轨接缝的零头不算空隙**（`TimelineState.mainGapTolerance = 0.01`，在 VideoEditTransitionHandles.swift）：
   合成器的主轨循环记着上一段进了合成的段收在哪，下一段离它不到 0.01 秒就接在它真正的末尾上（画面和声音都是），
   段在指令表里的起止不变；导出图那处 `0.01` 换成同一个常量。
3. 顺手把定格插帧的两个小函数拆成 `CompositionHold.swift`（合成器登记过超标、只许降），接线守卫的针脚跟着改。

  亮度；另编了一份换回 HEAD 合成器的做对照）：旧 B 版原样、旧 B 版每条缝都加回 0.7 秒叠化、用户的最小复现工程、
  v2 + BUG-02 对照表的关键帧 —— 修前全部无效，修后全部有效、逐帧有画面；v2、A / C / D 版修前修后都有效。旧 B 版
  和最小复现工程第 11975 格那一帧从 0.000 变成 0.297（前后帧 0.315 / 0.297）。
- `scripts/check-preview-composition.sh` 新增 `checks/PreviewComposition/SliceTicks.swift`：纯值（边界各自落格、
  同一格留最早的、总长之外的不要、最后一片收在总长）；真合成 ① 24 fps 工程里变速段收在 2.9598、下一段从 2.96 起
  （第 1775 / 1776 格）、后面再接一段，② 只有一段画面收在 2.9598、配乐收在 2.96 —— 断言指令表首尾相接、收在时间线
  总长那一格上、视频合成有效、接缝前后的画面对、**第 1775 格上那一帧是后一段的灰**（容差为零取帧，
  `FrameProbe.swift` 的 `exactBrightness`，拿不到正好那一格的帧就报 -1）。
- **反向验证**：合成器换回 HEAD 的版本（两条修复都没有），7 条红（指令表不接、无效、最后一片收在 1775 而不是 1776，
  取不到帧）；只把 `mainGapTolerance` 改成 0，只有「第 1775 格不许黑」那一条红（实测 0.0）；恢复后 236 项全绿。
- 这条「不许黑」的断言写红了两次才对：① 时刻不落在帧的格子上时（默认 30 fps 工程的 1775 不是），合成器渲的是邻近
  那一帧；② 只有两段时，前一段那条轨到头了，AVFoundation 保持它的最后一帧，洞照样看不见 —— 要像用户的工程那样后面
  再接一段，让前一段那条轨在洞的位置上是空段（而且要有黑底轨：一道渐变就够），洞才是黑的。
- `checks/transition-handles-wiring.sh` 加了一节：合成器和导出图都必须读 `TimelineState.mainGapTolerance`。
- 用户那份工程一个字没改，装上修好的版本打开就应当有画面 —— 等用户实机确认。

## 教训 / 防回归

- **两个本该相等的时间各自换算，就会落在相邻两格。** 09-27 那次是合成轨上的插段（修法：只往真正的末尾接、合成完
  裁到总长），这次是指令表（修法：先落格子再去重）。凡是拿 Double 算出来、再各自换成 CMTime 去对齐的地方，都要
  按格子对齐，别按秒判「差不多」。
- **AI 报给用户的数字会被原样写回来。** `get_timeline` 三位小数，AI 照着放段，就留下不到一毫秒的缝；模型里合法，
  渲染时要当作相接。以后给 AI 开任何带时间的参数，先想它拿到的数字是从哪一位小数报出去的。
- **用户描述的触发条件是线索不是根因。** 「叠化 + 关键帧」是用户看到的相关，去掉两样照样黑；用 App 自己的合成
  代码离线合成用户的工程、打印指令表，几分钟就定性，比在界面上试组合快得多。这个探针值得留着（scratchpad 里那份
  只有 100 行：`VideoEditProjectIO.load` → `build` → 打印段、指令、`isValid(validationDelegate:)`）。
- **接上之后再看一眼接缝那一格。** 指令表有效只是不黑屏，A/B 两条轨之间的一格空洞得用容差为零的取帧才看得见；
  带容差的取帧会拿邻近的帧糊弄过去。
