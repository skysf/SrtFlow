# 拖短转场时，接缝上的遮罩整块往右挪

2026-09-20。用户报的：「遮罩我在调整时长的时候，移动了」。

同一天引入（接缝转场遮罩那一刀）、同一天修掉，**没有发到用户手里的版本里**——
但现象是用户在试用版上报的，按仓库惯例留一份案情。

## 症状

拖遮罩的边改转场时长时，遮罩不是以接缝为心变宽变窄，而是**整块往右滑**。
越往短里拖偏得越厉害。时间线上的片段一帧都没动（磁吸默认关着，`liveApply`
不会重排），纯粹是画错了位置。

## 根因

遮罩的宽度有下限（18pt —— 再窄两条拖动把手就贴到一起，哪条都抓不准），但
**位置没跟着补偿**：左边界钉死在 `window.start`（= 缝 − d/2），下限撑出来的那
几个 pt 全长在右边。

默认缩放下 pps ≈ 30：

| 转场时长 | 真实宽度 | 画出来 | 左边界 | 实际占据 |
|---|---|---|---|---|
| 0.5s | 15pt | 18pt（贴下限） | 缝 − 7.5 | 缝−7.5 … 缝+10.5 |
| 0.1s | 3pt | 18pt（贴下限） | 缝 − 1.5 | 缝−1.5 … **缝+16.5** |

往短里拖的过程中，左边界一路往右挪、右边界因为贴着下限不动 —— 手上的感觉就是
整块在往右滑。

## 修法

画法从视图里的 `.offset` 挪进值层的 `TimelineState.transitionMaskRect`，按
**窗口中心**摆：

```swift
let width = max(minWidth, window.duration * pps)
let center = (window.start + window.duration / 2) * pps
return (center - width / 2, width)
```

宽度怎么被夹都不影响它对准缝。

## 教训

挪进值层不只是为了整洁：原来这段几何是视图里的一行 `.offset`，**检查脚本编译
不到**，所以这类错误没有任何守卫能拦。挪出来之后立刻就能断言了。

凡是「画在哪」的算法，只要它有夹紧、下限、取整这类会让画出来的尺寸偏离真实值
的步骤，就该从视图里拎出来 —— 偏离本身不是 bug，不补偿位置才是。

## 守卫

`checks/VideoFade` 两条，都反向验证过（退回钉左边界的旧画法，第二条立刻报红）：

- 放得够大（pps=200，宽度不碰下限）：左边界 = `window.start × pps`、宽度 = `d × pps`
- 缩到贴下限（pps=6）：宽度取下限，而**中心仍然压在缝上**
