# 2026-09-27 AI 的改动撤一步，整条时间线空了

> 开发中（PR #81，AI 接口第一块）端到端实测抓到的，没到用户手里。长期约束写进了
> [AI 接口（MCP）](../architecture/ai-control-mcp.md) 第四节第 1 条。

## 症状

用脚本扮成 AI 客户端，经 `srtflow-mcp` 驱动测试版：新建工程 → 放 4 段素材 → 转场 → 文字 → 滤镜 →
竖屏 → 裁一段 → 切开 → 加一句字幕，然后调一次 `undo`（`steps: 1`）。期望只退掉最后那句字幕；
实际**整条时间线空了** —— 片段、文字、滤镜全没了，接下来的导出报「V1 是空的」。用户在 SrtFlow
里按 ⌘Z 也会一样：一按全部退光。

## 根因

撤销管理器默认**按事件分组**：登记撤销时自动开一组，**要等下一个用户事件才关上**（GUI 冒烟文档
「四之六」第 13 条早就记过这个现象：合成的鼠标事件关不上撤销组）。AI 的调用从 socket 进来、在主线程
的 Task 里执行，不是事件；App 又在后台，一个事件都收不到 —— 于是 AI 的每一步（每次 `perform` 登记
的撤销）都堆进了同一组，一次 undo 把整组退掉。

**第一版修法错了，而且会让 App 闪退**：在每个工具前后调 `endUndoGrouping()`，手动关掉那个自动开的组。
为它写的自检（命令行里用真的 UndoManager 登记两次、中间手动关一次）当场崩在第二次登记上：

```
NSInternalInconsistencyException: _registerUndoObject:: NSUndoManager ... is in invalid state,
must begin a group before registering undo
```

手动关掉之后，撤销管理器仍记着「这一轮事件的组已经开过了」，不会再自动开；下一次登记（也就是下一个
AI 调用）没有组可进，直接抛异常 —— 在 App 里就是整个闪退（后台的 App 一个事件都没有，正是这个处境）。
这一版没有进过测试版，是自检先崩出来的。

## 修复

**绕开**按事件分组，而不是去关它（`Sources/SrtFlow/AIUndoGrouping.swift`，`step`）：

1. 暂时关掉 `groupsByEvent`，自己 `beginUndoGrouping`，做完 `endUndoGrouping`，再恢复 —— 一个工具就是
   显式的一组，从不碰自动开的那一组，也就不会让它的内部状态错位。
2. 包的那一段必须是**同步的**（没有 await）：中途让出主线程的话，用户这时的操作会落进这一组，⌘Z 还能
   把这一组提前关掉、让后面的 `endUndoGrouping` 失配。所以路由只包 8 个同步的改动工具
   （`AIToolRouter.run`），异步的 `add_clips` 只包它最后那一次 `perform`，「撤销这一轮」包它那一次 `perform`。
3. 进来时已经开着一组（用户刚做完、还没等到下一个事件）：不另开，嵌在里面 —— 两步并成一步，但不崩。
4. 中间有人清空了撤销栈（新建 / 打开工程会 `removeAllActions`，连开着的组一起丢）：结束时只在还有组的
   时候才关，不失配。

## 验证

- `scripts/check-mcp.sh` 新增 `checks/MCP/UndoChecks.swift`，用真的 UndoManager：
  - 前提：不分组时两次登记落在同一组，一次 undo 全退（复现症状）；
  - 修复：两次 `step` 之后一次 undo 只退一步、再一次退前一步；
  - 第一版的崩溃：几次 `step` 之后，按事件的普通登记照样能自动开组，不抛异常；
  - 进来时已有一组：嵌套不崩；中间清空撤销栈：不失配。
- 同一个脚本扫描：8 个同步改动工具都包在 `AIUndoGrouping.step(undo)` 里、`add_clips` 那一次也包了、
  AI 的文件里除了 `AIUndoGrouping.swift` 没人自己调 `endUndoGrouping()`。
- **反向验证**：① 把 `step` 改成不包（直接执行），自检红在「one undo takes back only the latest AI step:
  got 0」—— 正是症状；② 拿掉路由里 `setText` 那一层包装，扫描红在「setText 没包在 AIUndoGrouping.step 里」。
  恢复后 191 项全过。
- 端到端重跑（调试版拼的测试包）：加字幕后撤一步只退掉那句字幕，片段、文字、滤镜都在；再撤一步，刚切开
  的那段合回去；导出成片 10.00 秒、720×1280、30 帧。

## 教训 / 防回归

- **撤销管理器的「按事件分组」只对用户事件成立。** 从 socket、定时器、后台任务来的改动不是事件：要么自己
  显式分组，要么接受它和前后的改动并成一步。以后加任何「不是用户点出来的」改动入口，都先想这一条。
- **别去关别人自动开的组。** 撤销管理器的内部状态和「这一组是谁开的」绑在一起；手动收尾看着对，
  下一次登记就抛异常。能绕开就绕开。
- **「看着修好了」要在最坏的时机再验一次。** 第一版在端到端里是好的，靠的是测试时碰巧有事件进来；
  命令行里一个事件都没有，才暴露它会崩。能在没有事件的环境里复现的东西，就在那里钉住。
