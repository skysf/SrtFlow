# 2026-09-28 一次放两首配乐，第二首点名要新开一条轨，却接在了 A1 后面

## 症状

AI 一次 `add_clips` 放两首音乐库的曲子：第一首没说轨道（默认从 0 开始、落第一条放得下的音频轨 —— 工程里还没有音频轨，
于是新开了 A1），第二首写了 `track: "new_audio"`（说明里写的是「新开一条轨」）。结果第二首落在了 **A1 的 30 秒处**，
没有新开 A2。分开两次调用时第二首正常开了 A2。第一块（PR #81）就有，只在测试版里；第 3 块冒烟时撞上的。

## 根因

`AITimelineEdits.place` 有一条规矩：同一批里两段都要「新开一条轨」时，第二段放进第一段开的那条（不然两段 new_video 会各开一条）。
它用 `openedAudio` 记「这一批开过的音频轨」—— 可只要落地时**新开了轨**就记，不管这一段自己有没有要求新开。第一首只是因为
还没有音频轨才开了 A1，也被记成了「这一批开的新轨」，第二首的 new_audio 于是被改成了「放进 A1」、接在它最后面。

## 修复

只有**自己要了新开**（`plan.target` 是 `.newAudioBottom` / `.newOverlayTop`）的那一段开出来的轨才记下；视频的 new_video 同样改。

## 验证

- `checks/MCP/TimelineChecks.swift`：先放一首不点名轨道的（开出 A1），再放一首 new_audio 的 —— 要有 A2、从 0 开始。
  原来那条「两段都要 new_video 时放进同一条」照过。
- 反向验证：换回「新开了就记」的写法，新加的那条当场红（1/53）；恢复后全过。
- 实机：同一次调用里「默认轨 + new_audio」两首，第二首落在 A2（第 3 块冒烟，见第三块实施报告）。

## 教训 / 防回归

- **「这一批开过的轨」要记的是意图，不是副作用**：落地时新开了轨可能只是因为原来没有轨。规矩写在
  [AI 接口](../architecture/ai-control-mcp.md) 第四节第 2 条。
