# 2026-09-25 老虎机数字 365 → 90 停在「090」上

## 症状

用户截图：数字元件选「Odometer」，From 365、To 90、Roll for 0.7s、Delay 3s、千分位开着。检查器里
To 写的是 90，画面上滚完停在「090」。用户原话：「To 显示是 90，那就应该显示的也是 90，而不是 090」。

现场是南极那条片子的标题：先「365 DAY」，数字滚下来之后接另一段字「° SOUTH」，成片应当是
「90° SOUTH」，实际是「090° SOUTH」。预览和导出一样（两边是同一个渲染函数）。

同一个毛病还有几种样子（拿修之前的代码逐个算过首尾两帧）：

| 滚动 | 以前停在 / 起步是 |
| --- | --- |
| 90 → 365 | 起步「090」 |
| 0 → 4,827 | 起步「0,000」 |
| $1,299 → $999 | 末帧「$0,999」 |
| -5 → 10 | 末帧「-0」 |
| -12 → 345 | 末帧「-45」 |

## 根因

**一、位数少的那一头，多出来的高位被编成了 0。** 老虎机按定版串排版（位数多的那一头），每一位
一条数字带，位槽的 x 全程固定 —— 这本身是对的，滚动时数字才不横着挪。可每条带子的起止数字取的是
`digits(of: value)[place] ?? 0`：终值 90 根本没有百位，`?? 0` 替它编了一个 0，于是百位停在 0 上。
起点那一头同理（0 → 4827 起步「0000」）。千分位逗号、负号是定版串里的静态字符，不管哪一头有没有，
一直画着。

**二、定版串取的是「两个完整显示串里字符多的那个」。** 两头符号不同时会漏位：`-12` 和 `345` 都是
三个字符，取了「-12」，百位根本没有格子，终点画成「-45」。

**三、位槽是整串扫出来的。** `digitPlaces(in:)` 对「前缀 + 数字 + 后缀」一起数：后缀「m2」里的 2
被当成个位，前缀「No.」里的句点被当成小数点，整排位都错开。

**四、自检只测了位数最多的那一头。** 老虎机那一组用的是 0 → 4827，断言「滚动结束时每一位的轮位
取模 10 = 终值那一位」—— 终点恰好四位都在；起点那一头（三位不存在）从没断言过。而且「终值那一位」
也是从同一张 `?? 0` 的表里取的，编出来的 0 和画出来的 0 互相印证，两份结果一起错。

### 这次自己修错的两版（比结论更值得读）

1. **第一版按对齐方式重新摆：居中的还居中。** 不存在的那一位滚成空白、宽度收掉，整行重新居中 ——
   首尾两帧和「直接显示 from / to」逐像素一样，自检全绿。拿用户的真工程（两段字的参数照抄工程文件，
   同一个渲染函数合成 1920×1080）一渲：「90」往左挪了半格，和「° SOUTH」之间空出一截。用户是照着
   「090」的右边摆的「°」—— 数字后面紧跟另一段单位字是最常见的摆法，居中重排恰好把它拆开。
   改成**居中和右对齐右边不动、左对齐左边不动**。
2. **第二版收宽度时，正在滚走的那一位跟着收窄的步进挪。** 逐帧看：百位的「1」只剩上半截时蹭到了
   「3」跟前，单看那一帧像个逗号（「,3」）。改成正在收的字形留在自己原来那一格里滚走，只挪别人。

两次都是自检绿、一渲真东西就露馅：自检比的是「首尾两帧对不对」，这两个毛病一个在「对齐的口径」、
一个在「中间那几帧」。

## 修复

- `NumberOdometer`（新文件 `Sources/SrtFlow/VideoEditTextOdometer.swift`，纯值）：
  - 角色表只从去掉前后缀的那一段（`NumberRoll.settledNumber`）认：哪一位数字、跟着哪一位的千分位逗号、负号；
    按 UTF-16 下标存，和 `TextLayout.Glyph.characterIndex` 同一套。
  - 每一位的数字带（原 `NumberRoll.wheel` 的算法原样搬过来）在**不存在的那一头是一格空白**；两头恰好同一格
    （行程 0，`100 → 5` 的十位）就往滚动方向多走一格。
  - 某一刻每个字符怎么画（`OdometerCell`）：数字带（轮位 + 空白格）、跟着滚的符号（逗号跟左边那一位、
    负号自己滚），以及此刻占几成宽。
- `NumberRoll.settledText` = 前后缀 + `settledNumber`（位数取多的那头、任一头负就带负号）。位数没变、
  符号相同时和以前一字不差。
- `TextTypesetter.layout(widths:)`：在属性串上按比例收掉那几个字符的步进；`placeCollapsing` 管谁不动
  （居中和右对齐右边、左对齐左边）和正在收的字形留在原地。
- `NumberWheelDrawing`：空白格不画，逗号 / 负号在这一行的格子里上下滚。
- 预览和导出都只从 `TextRenderer.render` 出画面，一处改两边都对。

## 教训 / 防回归

- **缺省值替缺失的数据说了话。** `?? 0` 把「这一位在这一头不存在」编成了「这一位是 0」。定版的
  排版只回答「每一格在哪」，「这一格在这一头有没有东西」是另一件事，得单独表达（这里是空白格）。
- **自检的用例要覆盖输入的两头。** 老虎机那一组只用了「终点位数最多」的 0 → 4827，缺的恰好是
  「位数少的那一头」—— 和 [竖屏被缩小](2026-09-24-resolution-cap-shrinks-portrait-video.md) 同一类：
  缺的输入比写错的逻辑更难发现。
- **改布局，先渲用户的真东西看一眼，再逐帧看中间。** 两版错都是自检全绿、一渲就露馅：一个错在
  「谁不动」的口径（得看用户旁边还摆了什么），一个只出现在中间两三帧。
