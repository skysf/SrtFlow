# 2026-08-12 渐入开头「砰」的一下：混音器把 1.0→0 的增益跳变平滑进了渐入

## 症状

给音频段设了渐入之后，**预览播放**时渐入的最开头有一下很短促的大音量，
然后才正常渐入。用户描述：「渐入音频开始那一点点没有 apply 渐入」。

导出的成品没有这个问题。段**从时间线 0 开始**时也没有 —— 这是它躲过首轮
自检的原因。

## 根因

不是渐入没生效，是**多了一条从满音量降到 0 的下坡**贴在渐入最前面。

按毫秒量出来的形状说明了一切（段起点后每毫秒峰值，素材满幅是 0.125）：

```
0:0.121  1:0.113  2:0.106  …  16:0.009  17:0.002  18:0.001 …
```

一条从满音量线性降到 0 的斜坡，长约 17ms，正好是一个音频处理缓冲区。

`AVMutableAudioMixInputParameters` 的语义：**第一条斜坡之前的音量默认是
1.0**。渐入斜坡的起点值是 0，于是在段起点处存在一个 1.0 → 0 的跳变，而
AVFoundation 的混音器不会硬切增益，它会把跳变按一个缓冲区平滑过去
（de-zipper）。结果就是渐入的头 17ms 变成「满音量 → 0」的下坡，听感是
「砰」一下再渐入。

为什么段从 0 开始时没有：那时斜坡起点就是合成的起点，**前面没有可跳变的
区间**，混音器直接从 0 起步。

为什么导出没有：ffmpeg 的 `afade` 是逐样本算增益的，不存在跨缓冲区的
de-zipper。**两条管线在这一点上语义不同 —— 这正是必须两条都真跑一遍的理由。**

### 为什么首轮的守卫没抓到（这条最值得记）

`scripts/check-audio-fade.sh` 首轮就是「真跑两条管线量包络」的检查，
它照样放过了这个 bug，两个原因叠在一起：

1. **所有用例的段都从时间线 0 开始** —— 恰好是唯一不触发跳变的位置。
2. **断言看的是 100ms 窗口的 RMS** —— 2ms 的满幅爆音只把 100ms 的 RMS 抬到
   0.14，17ms 的下坡抬到约 0.17，而阈值是 0.15，**擦着边过**。

「真跑生产路径」不等于「测到位」：**场景选在了默认值上，量纲选得比缺陷粗**，
再真实的管线也照样绿。

## 修复

`VideoEditCompositionBuilder.addVolumeRamps`：在段起点**之前一个平滑窗口**
就把音量钉住，让跳变发生在段起点前的静音空档里。

```swift
let pin = max(previousEnd, clip.timelineStart - gainSmoothingGuard)  // 50ms
params.setVolume(fadeIn == nil ? volume : 0, at: time(min(pin, clip.timelineStart)))
```

三个细节：

- **钉的值分两种**：有渐入的钉 0，没渐入的钉 body 音量本身。一律钉 0 的话，
  所有不从 0 开始的段都会被 de-zipper 加上一个 17ms 的软起音 —— 修一个 bug
  造一个新的。自检里有反例对照钉着这一条。
- **不能越过上一段**：`previousEnd` 是同一条合成轨上上一段的结束点，钉点
  夹在它后面，否则会啃掉上一段的尾巴。三个调用点都要在 `insert` **之前**
  抓游标（插完游标就被推到本段末尾了）。
- 主轨的声音走 A/B 交替两条轨，各有自己的 params 和游标，`previousEnd`
  取的是**同一条轨**上的上一段，不是时间线上的上一段。

## 验证

- `scripts/check-audio-fade.sh` 新增第 4 组：段从 **1.3337s** 起（非 0、
  且不在 600 时基整格上）、看**峰值**而不是 RMS，预览与导出各一条；
  外加「同位置不设渐入」的反例对照（防止修复给所有段加软起音）。53 项通过。
- **反向验证**：把 `params.setVolume(...)` 那行换成 `_ = pin`，新守卫当场变红
  （`head/full=0.96`），恢复后转绿。
- 首轮的三次反向验证（导出 afade、预览斜坡、转场仲裁）重跑仍然有效。
- `scripts/check-all.sh` 全绿。

## 教训 / 防回归

1. **音频瞬态要用峰值量，不能用 RMS。** RMS 的窗口越大，越会把几毫秒的爆音
   摊平到阈值以下。抓 click/pop 一律看窗口内峰值。
2. **自检的场景不能全落在默认值上。** 段起点、素材偏移、变速这些参数，至少
   要有一组**故意选在非零、非整格**的值上。这个 bug 的全部特征就是
   「timelineStart ≠ 0」。
3. **预览（AVFoundation）和导出（ffmpeg）在增益语义上不等价**：前者有跨缓冲区
   的 de-zipper，后者逐样本。任何「设一个增益曲线」的功能，两条管线都得真跑。
4. 长期约束已落到
   [architecture/audio-fades.md](../architecture/audio-fades.md) 的
   「斜坡之前必须先钉音量」一节。
