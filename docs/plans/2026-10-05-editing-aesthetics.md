# 剪辑美感：先把审美写下来，再补零件，最后做画面特效（2026-10-05）

> 用户 2026-10-05：「现在通过 mcp 剪辑，剪辑出来的质感，还有美感，很普通，我们如何能提升剪辑的美感，增加一些特效，
> 增加一些好看的 motions 呢？」先讨论（不改东西），看过分析后：「可以按照你的建议来」。
> 这份记录为什么普通、从 HyperFrames 学了什么、拍了什么板、分几刀。真实做到了哪看代码、检查和实施报告。

## 一、为什么普通（诊断）

1. **风格卡只写了用量，没写品味。** 原来的卡写的是多长、用哪个转场、字号多大；没写「别做什么」、没有标杆、没有美感
   自查，AI 就回到它的默认剪法：镜头一样长、转场全是叠化、字都居中淡入。「电影开头」那张甚至要求静止的镜头都慢推 ——
   这正是 HyperFrames 点名的 AI 通病（「别每一场都做慢推」）。
2. **画面这一层的零件天花板低。** 预览用的是 AVFoundation 默认合成器，只有透明度 / 变换 / 裁切三种斜坡
   （[转场库扩充](2026-08-23-transition-library.md)：表达不了的转场故意不收）。所以转场只有淡、推、擦；关键帧只有 4 条
   缓动，没有回弹和急停；没有运动模糊、光晕、颗粒。
3. **AI 只看得到静帧，也不检查好不好看。** `look` 一次最多 12 帧，看不到运动和节奏；两轮验收（[第五块实施报告](../reports/2026-09-28-mcp-slice5-report.md)）
   的清单查的都是技术项（字号、出框、电平）。
4. **好消息**：文字和形状是 SrtFlow 自己画的（`TextRenderer.render`、`ShapeOutline.drawing`，预览和导出同一个函数），
   不受合成器的限制 —— 动效升级从这一层做最便宜。

## 二、从 HyperFrames 学到的

[MCP 方案](2026-09-27-mcp.md) 第 37 条当时只学了 `frame.md`（一张给 AI 照着做的风格表）。这次把它给 AI 的 21 个技能文件
读了一遍（仓库 Apache 2.0，规则可以注明出处改写），好看的原因主要不在渲染器：

| 学到的 | 它怎么做 | 在它仓库里的位置 |
| --- | --- | --- |
| 审美写成带数字的规则，专治 AI 的坏习惯 | 「You know these rules but you violate them. Stop.」同一场里同一条缓动最多用两次；最慢的一场是最快的 3 倍；第一个动作延后 0.1–0.3 秒；进场比出场长（0.4 对 0.25 秒）；一组错峰总共 ≤ 0.5 秒；起 / 停 / 收 30 / 40 / 30；叠化 = 延续、硬切 = 惊醒；一张「AI 设计通病」清单 | `skills/hyperframes-creative/references/motion-principles.md`、`house-style.md`、`beat-direction.md`、`video-composition.md` |
| 标杆和交片前自查 | 每种调性对一个标杆（Vogue 封面 / A24 片名卡、苹果发布会、Errol Morris、Nike 广告）；海报测试、怯场测试、一眼看主次、和画面有没有关系、留白还是断档，五过四才交 | `skills/embedded-captions/references/reference-bar.md`、`aesthetic-principles.md` |
| 成套的视觉语言 | 十套字幕「DNA」锁死字体、配色逻辑、动效语法，再按每段画面适配（强调色从画面取、力度跟说话的响度走） | `skills/embedded-captions/dna/` |
| 先分镜后动手 | 「每一拍是一个世界，不是一个版面」；每个元素说得出一个动词；文字分镜 → 静态草图 → 动画 | `skills/hyperframes/references/review-loop.md` |
| 零件天花板高、只有一个渲染器 | 浏览器：GSAP 全套缓动、逐字错峰、混合模式、30 多种 CSS 转场 + 14 种 WebGL 转场、人像抠像；预览和成片同一个浏览器渲 | `skills/hyperframes-animation/` |

它的短板：它在素材**上面**包装图形（口播那个技能明说「原片原样播放」），不剪真素材。我们学的是规则和流程，零件按
SrtFlow 自己的路子补（方案第 37 条「不装，学它的长处」不变）。

## 三、拍板（2026-10-05）

| # | 事 | 定了什么 | 理由 |
| --- | --- | --- | --- |
| 1 | 先做哪样 | **先把审美写下来（第一刀），再补零件，画面像素层的特效最后**（用户：「可以按照你的建议来」） | 写规则几乎不花力气、马上见效；而且以后每加一个零件，卡里都得先写清「什么时候用、什么时候别用」，不然 AI 会把新特效铺满全片 |
| 2 | 风格卡写成什么样 | **导演手册**：五张卡各加「标杆 / 品味 / 别这样」三节；共用规矩加「先出分镜表 / 品味（带数字）/ AI 剪片的通病 / 交片前再看一遍 / 从参考片学一种风格」五节；`RecipeChecks` 钉着这几节都在 | 品味只写 SrtFlow 现有零件做得到的事（例：推近 = `split_clip` + 放大；音乐倒着对齐 = 在两个强拍上切、删中间、接上结尾）。卡里的名字照旧逐个对着工具清单查 |
| 3 | 分镜表要不要等用户点头 | **发给用户、接着做**；用户说过「先给我看方案」才等 | 用户一贯「少问」（方案第 34 条）；看得见模式下用户随时能停、能撤销这一轮 |
| 4 | 参考片从哪来 | **只量用户给的文件，不从网上下** | YouTube 的条款不允许下载；免费播放站多是盗版片源；方案第 31 条定了 AI 不下载素材。学的是语法（时长、节奏、转场、字卡、声音），不用它的画面、音乐、logo、片名设计 |
| 5 | 画面像素层的特效（缩放模糊 / 甩镜转场、漏光、运动模糊、字躲到人后面） | **先走 (b)：只把有特效的那零点几秒用 Core Image 渲成一小段文件，预览和成片都播它**；先做缩放穿梭、甩镜、闪白漏光三个探针，看效果再定要不要 (a) | (b) 天然同账、不动预览的合成器；(a) 自定义预览合成器天花板最高，但推翻转场库的边界、性能基线和两条管线的对账都要重来（工程原则 1：要再问用户） |
| 6 | 怎么知道变好了 | **审美回归集**：南极（纪录片 16:9）、课程（带货 9:16）、婚礼三份素材，每次改卡新旧各剪一版，用户不看标签盲选，结果记在第五节 | 美感自动化量不出来；同素材盲选是最便宜的可靠比较，也防止「改了卡反而变差」 |

## 四、分刀

- **第一刀（导演手册）**：五张英文卡 + 共用规矩（`Sources/SrtFlow/Resources/recipe*.md`）、中文稿
  （[配方卡](2026-09-28-mcp-recipes.md) 二之一到二之五、每张卡的标杆 / 品味 / 别这样）、`checks/MCP/RecipeChecks.swift`
  钉几节都在（另把 track 的 `new_video` / `new_audio` 算作认得的名字）。不改工具、不改 App 代码。
- **第二刀起（零件，一个 PR 一件事，顺序按收益）**：
  1. 缓动加回弹（overshoot）、急停（expo）、弹簧：关键帧和文字 / 形状的动画都能选。
  2. 文字动画：逐字 / 逐词错峰（间隔可调）、字距收拢、从遮罩后升起、发光 —— 都在 SrtFlow 自己画的那一层。
  3. 设计好的图形模板：片名卡、姓名条、章节卡、数字强调、金句卡、片尾卡，每种几套外观，AI 只填内容、按节拍编排
     （HyperFrames registry 的思路，用文字 + 形状 + 动画拼）。
  4. 剪辑手法：变速坡（一段里从快到慢）；把视频的声音单独拿出来放到音频轨（J/L cut 的前提，[第五块实施报告](../reports/2026-09-28-mcp-slice5-report.md)
     里 AI 提过）；音乐倒着对齐做成一步（现在卡里教 AI 用 `split_clip` + `delete_items` + 淡入淡出拼）。
  5. 挑镜头的眼睛：Vision 的美学评分（macOS 15 起）、人脸质量、光流（运动量）→ `look shots` 每个镜头带分数。
  6. 参考片的「剪辑 DNA 报告」：`look` 的一个选项，一次量出镜头时长分布、转场类型（硬切 / 叠化 / 黑场 / 闪白）、颜色统计。
- **第三刀（画面像素层特效）**：按第三节第 5 条先做 (b) 的三个探针。

## 六、参考片：Greengrass 式（2026-10-05）

一个爬虫聚合的免费播放站上的页面，不是正版片源：**不下载、不录**（第三节第 4 条）。改按公开资料（剪辑师访谈、镜头时长统计）
