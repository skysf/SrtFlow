# 播放丝滑：播放头的每一跳只叫醒跟着它动的东西（2026-09-25）

## 背景

用户说播放预览时卡，「影响丝滑的体验」。最初的提法是：播放时左边那一栏（转场 / 滤镜）不需要实时
显示，只在不播放的时候才按停在哪儿渲染。

先看了 CI 性能测试的明细：播放器时钟一跳，整个界面重算约 172 次 body，那一栏只占约 6 次；大头是
编辑器根视图、时间线本体、检查器都订阅着时钟，每一跳把整个编辑器过一遍。把这个告诉用户之后，用户说：
「忽略 CPU 那些衡量方式，我现在核心就是要体验丝滑，你按照体验丝滑的方式来优化就行了」。

于是范围从「冻住那一栏」扩到「播放头的每一跳只叫醒跟着它动的东西」。做法、实测和守卫见
[案例](../bugfixes/2026-09-25-playback-wakes-whole-editor.md)，长期约束见
[预览性能 ratchet](../architecture/preview-perf-ratchet.md) 第十二节。

## 拍过的板

| # | 板 | 谁拍的 | 为什么 |
| --- | --- | --- | --- |
| 1 | 播放中左栏（转场 / 滤镜两页）冻住：小样、高亮、提示文字停在开始播放那一刻；暂停后按停下的位置刷新一次 | 用户 | 播放中小样来回换没人看，还拖卡播放 |
| 2 | 左栏只跟真播放头：鼠标在时间线上扫（影子播放头）不算；拖播放头的过程中不刷，松手停稳后刷一次 | 用户（按我的建议） | 扫一下、拖一下就换小样，等人把手挪到左栏时早已不是那一帧 |
| 3 | 播放中点转场卡片，套到面板上显示的那条缝，不是播放头此刻最近的那条 | 用户（按我的建议） | 看到哪条改哪条；想改正在播的那条，先暂停，面板就跳过去 |
| 4 | 不只冻左栏：根视图、时间线本体、检查器、字幕列表都不订阅时钟，跟着播放头动的拆成小视图各自订阅 | 我定（用户授权「按体验丝滑的方式来优化」） | 左栏只占约 3%，冻它解决不了卡 |
| 5 | 检查器播放中也不跟、停下追上一次；停着时照旧实时（拖播放头找关键帧，数值和 ◇ 跟着变） | 我定 | 播放中数字乱跳没人看，十几个数值框带着 AppKit 控件一秒更新二十遍；找关键帧必须实时 |
| 6 | 工具栏五个按钮（分割、定格、标记、删左、删右）和检查器的「分割」，播放中照样实时变灰 / 变亮 | 我定 | 播放中也可能去点分割；冻住的话会出现「亮着点了没反应」或「该能点却灰着」。只让一个小修饰器跟着时钟算一个布尔，便宜 |
| 7 | 预览上的画面（调色）、字幕、文字、形状、变换框，电平表，时间读数照旧实时 | 我定 | 那就是播放时要看的东西。时间读数改成显示的那一格（十分之一秒）变了才重画 |
| 8 | 字幕列表的高亮照旧跟着播放、自动滚到正在说的那句，但只在换句时重算整张表 | 我定 | 高亮正在说的那句是这一列的用途；一句通常好几秒，没必要一秒重算二十遍 |
| 9 | 不拿 CPU 数字验收：看 CI 的「做了几件活」和真窗口里的表现 | 用户 | 用户原话「忽略 CPU 那些衡量方式」 |
| 10 | 不降时钟频率、不降画质 | 沿用 [ratchet 方案](2026-09-24-preview-perf-ratchet.md) 的板 | 「给时钟降频这类都不算优化」 |

## 没做的

- 电平表现在是播放中最大的一块（一跳约一半的 body），它本来就该跟着声音动，这轮不碰。
- 烧字幕页（`BurnInView` / `BurnInPreviewArea` / `SubtitleEditPanel`）用的是另一个时钟，没量过，名单里先放着。
- 根视图仍然订阅整个工程（工程一变整个编辑器 diff 一遍）：那是「点选一段」那条线上的事，
  见 ratchet 文档第十一节，要不要换成 Observation 另外拍板。
