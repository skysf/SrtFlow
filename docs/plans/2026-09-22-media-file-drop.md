# 从 Finder 把文件拖进轨道（以及 ⌘V 粘贴进轨道）

> 2026-09-22 产品决策 + 实施。改「拖文件进时间线」「⌘V 粘贴素材」「导入落点」
> 之前必读。落点算法在 `Sources/SrtFlow/VideoEditMediaImport.swift`（纯值），
> 接线在 `Sources/SrtFlow/VideoEditMediaFileDrop.swift`。

## 在这之前是什么样

拖文件进剪辑页**一直是能用的**（`VideoEditView` 上挂着 `.onDropOfFiles`），
但它只按文件类型分流，**完全不看指针落在哪**：

| 拖的 | 落在哪 |
| --- | --- |
| 视频 / 图片 | 永远接在**主轨末尾** |
| 音频 | 播放头，`place` 自己挑一条音频轨 |
| 字幕 | `attachSubtitle` |

于是「拖进轨道」这件事在界面上根本不成立：拖到第二条视频轨上 → 进主轨末尾；
拖到 30 秒处 → 进主轨末尾。再叠上三件事，观感就是「拖放坏了」：

1. **零视觉反馈**（`isTargeted: nil`，拖着文件在时间线上晃不亮不高亮），而同一个
   界面里转场 / 滤镜 / 音频库三套应用内拖放**全都有**落点框；
2. **落点常在视口外**（主轨末尾往往已经滚出屏幕），松手后画面上什么都没变；
3. **不认识的文件被静默吞掉**，一句提示都没有 —— 于是「不支持这种文件」和
   「支持、但落在你看不见的地方」长得一模一样。

⌘C / ⌘V 粘贴文件则是**完全没有**：`AppDelegate` 的 `paste:` 只认滤镜段，
`validateMenuItem` 里 Paste 的亮灭条件是 `FilterClipboard.read() != nil`，
Finder 复制的文件 URL 一律判 false，菜单项是灰的。

## 用户拍板的四条

> 「用户拖到轨道哪里，就加入到哪里，如果轨道那个位置已经有素材了，就添加到
> 轨道的上方。」

在此之上，四个定法不同、实现差别很大的问题当场问过并定了：

| 问题 | 定法 |
| --- | --- |
| 时长探测是异步的，落点框怎么画 | **进场就探，先线后框**：拖进来那一刻开始探，没出来前画插入线 + 高亮目标轨，出来后换成真实宽度的框 |
| 一次拖多个文件 | **从落点首尾相接铺开**，撞上的那几段各自抬一轨 |
| 类型和行不匹配（mp4 拖到音频轨、拖到字幕行…） | **横向照用指针的 x，纵向退回该类型的默认轨**。永远不会「松手了什么都没发生」 |
| ⌘V 没有指针位置 | **播放头 + 默认轨，撞上就上抬** —— 和拖放共用同一套落点函数 |

## 落点规则

### 梯子

「上方」在这个仓库里有现成的语义：**轨道行的上下顺序就是画面的叠放顺序**
（`VideoEditTimelineView.rows`）。所以往上抬一轨 = 在梯子数组里往后走一格。

- **画面**（`videoImportLadder`，从下往上）：主轨 → 上层轨 0…n-1 → 新开一条（最上面）
- **声音**（`audioImportLadder`）：音频轨 0…n-1 → 新开一条（**最下面**）

**隐藏的轨不上梯子**（同 `TimelineState.place` 跳过 `isHidden`）：往一条看不见的
轨上落素材，用户看到的是「拖进去了，什么都没出现」。主轨整条藏着时同理。

### 三条规则

1. **多段首尾相接**从第一段的起点往后铺，不是全部叠在同一个起点。
2. **画面撞上了就往上抬一轨**：从指针那条轨起沿梯子逐条试，第一条放得下的就是
   落点；都放不下就新开一条在最上面。**横向不动** —— 抬轨只改轨，不改时间。
3. **纵向退回默认轨**：指针指着的行放不了这种素材，横向照用 x，纵向从梯子最底下
   重新找。
4. **拖进拉开的插入缝**（2026-09-24，[插入缝方案](2026-09-24-track-insert-and-reorder.md)）：
   在两条轨之间的缝上停约 0.2 秒，缝拉开；松手时类型和这条缝对得上的文件全部落进缝里
   新开的**一条**轨，首尾相接；对不上的照第 3 条落。认哪类缝看这一批里有什么（视频 /
   图片 → 视频缝，声音 → 音频缝）。标尺、滤镜行、最后一行下面的空白**不算**缝，仍按
   默认轨落。

### 声音的方向是反的，这是刻意的

音频轨**没有叠放语义**（混音是加法），行的上下只是排列，"上方"对它不成立。
所以声音的规则和按 `+`、和音频库拖放（`addLibraryAudio`）保持一致：**指名的那条
放得下就用它，放不下退回从头找**，都放不下在最下面新开一条。

为一个字面上的「上方」去把音频新轨插到数组最前面，代价是所有 `TrackSlot.audio(n)`
的编号一起位移，而换来的是和另外两个入口不一致的行为 —— 不划算。

> 2026-09-24 起，用户**自己指着**两条音频轨之间的缝停一下、缝拉开再松手，新轨就插在
> 数组中间（第 4 条）。梯子本身仍然不会自作主张往中间插。编号位移在那条路上无害：
> 颜色、行高、推子、电平表都按轨道身份记，不按编号。

### 指针对齐素材的左边缘

`proposed = 指针时间`，再过一遍 `TimelineSnap.resolve` 吸附（吸附关掉时候选表为空，
`resolve` 原样返回）。

**2026-09-23 用户拍板从「中点对齐」改过来。** 最初照滤镜卡片的口径用中点，审查时
发现它对长素材不成立：60 秒的视频拖到主轨末尾（12 秒）后面两秒处，起点算出来是
14 − 30，夹到 0，撞上已有素材被抬到新轨上；要落进主轨得把指针拖到末尾右边 30 秒
（默认缩放下约 720pt）开外。落点框本身是诚实的，但「拖到哪落到哪」在长素材上几乎
不成立。剪映、Final Cut、Premiere 都是左边缘对齐指针。

音频库拖放同一口径（整首音乐动辄两三分钟，问题更重）；**滤镜卡片仍按中点**
（默认时长短，而且它是「给这一段调色」，指针落在中间更像「这儿」）。
`checks/timeline-drag-wiring.sh` 第 4c 条钉着文件和音频库两处。

⌘V 没有指针，所以第一段的**起点**就是播放头（同按 `+` 的口径）。两种锚点在
`VideoEditProject.importFirstStart` 里收口，之后是同一条路。

### 磁吸开着时

主轨落点会被 `packMain()` 拼紧凑 —— 和拖动现有块完全一致，**不为导入开特例**。

但**落点框要画在拼完之后的位置**：落地走 `perform`，`perform` 收尾才 `packMain()`，
所以落主轨的段最后接在故事线末尾，不在指针底下。框照 `mediaImportLandings` 原样画
的话就是「框在这儿、素材落到那儿」（2026-09-23 审查发现）。`TimelineState.landingsAfterMagnet`
在副本上把落地那两步（`insertImported` + `packMain`）原样走一遍、读回起点，画框用它；
被挪走时吸附参考线一起收掉（那是按指针处算的）。

## 两个导入入口的分工

| | 有落点（本次新增） | 没有落点（原有） |
| --- | --- | --- |
| 谁 | 拖进**时间线**、⌘V | 工具栏按钮、拖到预览区 / 检查器 / 库栏、`SRTFLOW_SMOKE_VIDEO` |
| 入口 | `VideoEditProject.importFiles` | `VideoEditProject.addMedia` |
| 第一段从哪开始 | 指针 / 播放头 | 主轨末尾（画面）、播放头（声音） |
| 允许落哪条轨 | 梯子，撞上往上抬 | 主轨 / `place` |
| 插进时间线 | 都走 `TimelineState.insertImported` | ← 同 |

`.onDropOfFiles` 那条**兜底必须留着**：SwiftUI 里子视图的 onDrop 优先，所以落在
时间线上归新代理、落在别处归兜底。删掉它的话，拖到预览区就彻底没反应了
（守卫钉着）。

## 载荷类型：只有时间线这一处认 `.fileURL`

转场 / 滤镜 / 音频库三套应用内拖放**一律不许**用 `.fileURL`，它们各有自己的
自定义类型。它们要是也认 file-url，一次文件拖入就有四个候选接收者，谁接到全看
视图树顺序。这条原来只钉着转场，本次扩到三套
（`checks/timeline-drag-wiring.sh`）。

## 接法：整条时间线只有一个落点

**首测三次没修好，第四次修好了文件、却把 App 内三套卡片拖放弄死了**，两个案例：
[文件拖不进来](../bugfixes/2026-09-23-timeline-file-drop-claimed-by-inner-drop-region.md)、
[卡片被文件落点吞了](../bugfixes/2026-09-23-in-app-drops-swallowed-by-file-underlay.md)。
长期约束在[拖动手势 §5e-2](../architecture/timeline-drag-gestures.md)，一句话：
SwiftUI 把一次拖放交给指针底下**最里面**那个落点，类型对不上也不往外找（空类型的
`.onDrop(of: [])` 也一样），外部拖入和 App 内拖动都是这样。

所以时间线上只挂**一个** `.onDrop`：`scrolledContent` 上的 `TimelineDropRouter`，
认四种载荷（三种卡片的自定义类型 + `.fileURL`），按类型分派给各自的代理；文件这一份
是 `MediaFileDropDelegate`，直接用 `DropInfo.location`（滚动内容坐标，和 `rowLayouts`
同一套）。挂在「填满视口」之后，撑出来的空白也接得住文件。

整页那条 `.onDropOfFiles` 兜底**原样不动**：它是祖先，时间线滚动区归路由器，拖到
预览区 / 检查器 / 库栏 / 轨道头列 / 空工程上仍归它（接主轨末尾）。

## 时长探测：一条落地路径，两种画法

视频和音频的时长要 `probeVideo` / `audioDuration` 才知道（图片不用探，固定 5 秒），
而**落点框的宽度和「撞不撞得上」都依赖它**。

- 拖进来那一刻（`dropEntered`）就开始探。两个探测都按 URL 缓存，本地文件
  通常几十毫秒。
- 没探完：只画**插入线 + 目标轨描边**。这时候画一个宽度是假的框就是说谎。
- 探完了：换成真实宽度的落点框，**复用剪辑拖动那个虚线框**（`dropPlaceholder`）——
  落下去就是普通的剪辑块，没道理让用户学第二种落点语言。
- 探完那一刻用户可能正好没动鼠标 —— `dropUpdated` 未必马上再来一拍，所以探测任务
  按 `MediaFileDrag.lastLocation` 自己补画一次，不赌那一拍。
- **每次进场都重新探**，不看上一笔还在不在：`dropExited` 没被调到（拖放被取消、
  焦点被抢走）时，上一批文件会一直挂着，下一次拖进来的框说的就是**上一批**素材
  的长度。重探一次几乎不要钱（按 URL 缓存）。

**松手那一下不分两条路**：`performDrop` 只把「指针时间 + 目标轨」定死，时长探完
之后照样喂给同一个 `mediaImportLandings`。所以「探完了再松手」和「没探完就松手」
落在同一个地方。

探测结果带 `token`：用户拖出去又拖回来时回来的是**另一批**文件，旧探测落到新一批
身上就是凭空多出几段素材（同 `documentGeneration` 那条守卫的道理）。

### 落到新轨上时，框是缩略的

落到「新开一条轨」上时，框画在它将来长出来的位置。**那儿画不下一整条轨高的框**：
最上面那条轨行和标尺之间只有几个点（标尺到 28、主轨从 33 起），按 54pt 的视频行高
去画，框会整个跑到视口外面 —— 而「主轨占着、往上开一条新轨」恰恰是最常见的那一种
落点。

跨轨拖动早就遇到过同一件事，答案照抄它：**缩到 22pt、骑在插入线上**，上下各露一半。
几何在 `TimelineDropPlaceholder.newLaneY` 上 —— 各写一份字面量会慢慢分叉（守卫数调用点）。

2026-09-24 起，指针选的新轨都落在**拉开的插入缝**里：框画在缝正中（`TimelineSeams.ghostY`，
和拖素材块同一份几何）。`newLaneY` 只剩梯子自己开新轨的两处（撞上就抬到最上面、音频都
放不下时最下面新开）—— 那两种不是指针选的位置，没有缝可开。

## 提示

不认识的文件**不能不吭声**（这正是改之前最大的观感问题）。两条路都补上了：

- 一个都认不出来 → `Could not use %@ as a clip.` / `Could not use %d of the dropped files as clips.`
- 认出来几个报几个：三个视频里有一个坏的，另外两个照样进去，只报那一个。
- 拖动中就知道一个都不认识时，`DropProposal(.cancel)` 让指针当场变成「不能放」——
  比松手之后再弹提示诚实。
- 静帧引擎没就绪时**一个图片占位块都别放**（放了立刻又撤掉，用户看到的是块闪一下
  就没了），改成一条「引擎还没就绪」。

## 顺手做掉的一处去重

图片占位块 → 静帧循环视频那段转换（含「转换期间换了工程」「占位块被撤销掉了」
两道守卫）原来只在 `addImages` 里，现在抽成 `VideoEditProject.convertStillClip`，
两个入口共用。复制第二份的话，那两道守卫迟早有一边会忘。

## 没做的

- **不落占位块**。图片那套 `needsStillConversion` 不外扩到视频/音频：那要给
  `EditClip` 再加一个「正在探测」的状态，而它会渗进预览、导出、存盘每一条路径，
  为了几十毫秒不划算（同音频库 plan 里「不先落占位块再无感替换」的同一条账）。
- **落地后不自动选中新素材**。用户没提，不扩范围。
- **拖进来不改工具栏按钮的语义**：`Add Media…` 仍接主轨末尾、
  `Add to Upper Track…` 仍落播放头。那是按钮该有的行为，不是拖放。
- **⌘C 复制时间线上的剪辑块**仍然没有（剪贴板体系目前只为滤镜段而生）。
  本次只做「把**文件**粘进来」。
