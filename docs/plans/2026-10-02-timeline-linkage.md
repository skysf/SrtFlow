# 联动：主轨块挪到哪、删没删，压在它上面的东西跟着走

> 2026-10-02 用户提的：「linkage 的功能，应该要和剪映一样打开了以后，只要和主轨上的块在一个范围内的，任何东西都会
> 链接在一起，删除也是一起删除，移动也是一起移动」。我列了八条疑问（范围怎么判、哪些类型、哪些操作、和现有「链接」的
> 关系与默认值、单向、撞上了怎么办、AI 走不走开关、拖动中怎么画），用户拍板：「用户体验第一，全部你来抉择，然后开始」。
> 本文记每一条是怎么定的、为什么；**当前状态以 [联动](../architecture/timeline-linkage.md) 和代码为准**。
> 相关：[拖动手势](../architecture/timeline-drag-gestures.md)、[剪辑页上记住的开关](../architecture/editor-remembered-toggles.md)、
> [AI 接口（MCP）](../architecture/ai-control-mcp.md)。

## 一、现状和目标

| | 2026-10-02 之前 | 目标 |
| --- | --- | --- |
| 「链接」开关管什么 | 只认显式的组号：视频 + 它分离出来的音频、录屏画面 + 麦克风（`linkGroup`） | 显式配对照旧，**再加上**：压在主轨块上的任何东西（上层轨、音频轨、文字、形状、滤镜段、字幕句）跟着那块主轨走 |
| 删一段主轨 | 磁吸开着后面的主轨块合拢，别的轨一概不动 → 字幕、音效、文字全错位 | 压在它上面的一起删；后面合拢时，后面块上压着的东西跟着合拢 |
| 拖一段主轨去别处 | 只有它和显式配对的音频动 | 压在它上面的东西跟着去 |
| 变速 / 定格 / 转场 / 裁尾巴让后面的主轨块挪了 | 后面的字幕、文字留在原地 | 跟着挪 |
| 默认 | 关 | **开**（剪映默认开；没有它，剪掉一段之后字幕全错位是这个用户当天就撞上的事） |

剪映专业版的「联动」：非主轨道的素材（音效、音频、文本、字幕、贴纸、特效、滤镜、画中画）和主轨道的素材同步移动、删除，
时间轴右上角一个开关，另有「联动设置」按类型勾选（[剪映专业版自定义联动设置](https://www.sohu.com/a/873275339_120142897)、
[时间线工具：主轨磁吸、自动吸附、联动](https://blog.csdn.net/qq_41506166/article/details/137922543)）。公开资料没写清「在范围内」
怎么判、跨两段的怎么处理，下面按用户体验自己定。

## 二、拍的板（我定的，按用户体验）

| # | 板 | 为什么 |
| --- | --- | --- |
| 1 | **跟着内容走，不是跟着块的编号走。** 每样非主轨的东西看它底下压着主轨的哪些**画面**（哪个素材的第几秒）；这些画面挪到哪，它就挪到哪；画面没了，它才没了 | 只认「块 id」的做法在分割、`cut_speech`（切开再删中间）、定格插入上全错：右半段是新 id，压在上面的字幕不知道该跟谁。按画面认，这些操作一个都不用特判，用户看到的永远是「字幕贴着它说的那句话」 |
| 2 | **完全落在一段主轨块里的**，跟那块走：删它就删、挪它就挪（含磁吸合拢、拖去别处、变速、裁头之后画面前移） | 这就是剪映的「在范围内」 |
| 3 | **跨两段的**（一条配乐横跨整片、一句字幕跨过接缝）：底下压着的画面**全部**挪同一个量才跟着挪，否则不动；只有压着的画面**全没了**才删 | 配乐从头铺到尾，删第一段不能把配乐删掉、把第一段拖到最后也不能把配乐拖到最后（FCP 的 connected clip 就有这个坑）；跨接缝的字幕在前面删掉一段之后要跟着后面那段一起前移，不然就和它说的话错开 |
| 4 | **裁切不删东西。** 裁头 / 裁尾 / 变速只会让压在上面的东西跟着画面挪；画面被裁掉的那几句留在原地不动，由用户自己删 | 裁切是边拖边看的探索动作，拖过去一句字幕就没了太吓人；留在原地的一眼能看见、按 ⌫ 就删。只有**真删**（⌫、AI 的 delete_items、cut_speech 剪掉的那几块）才连带删 |
| 5 | **哪些算「任何东西」**：上层视频轨、音频轨（含分离出来的音频）、文字、形状（含模糊 / 马赛克）、滤镜段、字幕句（原文 / 译文两条轨各按自己的时间判）。标尺标记不算（它钉在时间线上，不属于任何块）；段上的标记、转场、关键帧本来就长在段上 | 用户说的「任何东西」；标尺标记是 2026-09-30 拍板「锚在时间线的绝对时刻、不跟任何块走」 |
| 6 | **不做「联动设置」按类型勾选**，先一个开关、全类型 | 轻量化优先；真有人要再加 |
| 7 | **单向**：主轨带别的，别的不带主轨。拖一句字幕、一段音乐不会把主轨拖走 | 和剪映一样；主轨磁吸下主轨块的位置只由合拢决定（[拖动手势 §3](../architecture/timeline-drag-gestures.md)） |
| 8 | **撞上了**：跟着挪的上层轨 / 音频轨的段撞上同轨别的段，就换一条放得下的轨（画面往上抬、声音另找一条，都放不下新开一条，同拖文件 / 粘贴）；文字往上找空行、滤镜往上找空层；字幕句和形状允许重叠 | 同一条轨上两段重叠会让预览合成插错位（AVFoundation 的 insert 会把已有内容挤走），所以必须让开；行 / 层的规矩沿用现成的 |
| 9 | **和现有「链接」是同一个开关**，语义扩大；显式配对（分离音频、录屏麦克风）照旧、而且更强：拉开了也跟。中文名改成「联动」（英文仍叫 Linkage） | 剪映只有一个开关；两个开关没人分得清 |
| 10 | **默认开。** 以前默认关的理由「分离音频就是为了单独动它」在联动下仍然成立：拖音频本身永远只动音频（第 7 条），受影响的只是拖视频时音频跟着 —— 这正是要的 | 剪映默认开；没有它，剪掉一段之后字幕、音效全错位 |
| 11 | **AI 的工具按这个开关走**，和手动一个口径；`cut_speech` 剪掉的那几块永远连带删（它本来就不管开关带着链接的声音剪）。`delete_items` / `freeze_frame` 的说明里写明开关开着时别的轨跟着动；结果里带 `linkage`（挪了几样、删了几样） | AI 剪完口播之后字幕还贴着说的话，是这个功能最大的用处之一 |
| 12 | **拖动中**：被拖的主轨块压着的东西实时跟着走（它们是这一轮拖动的成员，没有障碍、不挡拖动）；磁吸下别的主轨块合拢在松手时发生，它们压着的东西也在松手时跟 | 和现在主轨块自己的表现一致（拖动中邻居不动、松手才归位） |
| 13 | **复制 / 粘贴 / 复制一份不带压在上面的东西**；分割本身什么都不挪 | 剪映也不带；要一起复制就框选 |
| 14 | **实现只有一处**：每次改时间线（`perform` / `liveApply`）结束时，拿改之前和改之后的主轨比一遍，按第 1–4 条把没被这次操作动过的东西挪 / 删（`TimelineLinkage.follow`）。不存任何状态、不抬工程格式、老工程不用迁移 | 展开链接的调用点有 23 处，逐处补迟早漏一处（「复刻合同的副本，合同一改就漏」是这个仓库反复撞的坑）；一处收口之后，拖文件插进主轨、粘贴、AI 的 ripple、磁吸拨开合拢，全都自动对 |

## 三、几个具体场景（也是自检的用例）

| 场景 | 结果 |
| --- | --- |
| 磁吸开，删主轨第 2 段，它上面有两句字幕、一段音效 | 两句字幕和音效一起删；第 3 段起的主轨块前移，它们上面的字幕 / 文字 / 音效跟着前移同样多 |
| 一句字幕跨过第 1、2 段的接缝，删第 1 段 | 字幕不删，跟着第 2 段前移 |
| 配乐从 0 铺到尾，删中间一段 | 配乐不动、不删（底下的画面没有一起挪） |
| 配乐从 0 铺到尾，把第 1 段拖到最后 | 配乐不动（第 1 段去了最后、其余前移，不是同一个量） |
| 磁吸开，拖第 3 段到第 1 段前面 | 第 3 段上的字幕跟着去前面；第 1、2 段后移，它们上面的东西跟着后移 |
| `cut_speech` 剪掉一段里的三处停顿 | 停顿上的东西删掉，停顿之后的字幕 / 文字跟着画面前移 |
| 磁吸开，裁掉第 1 段的头 2 秒 | 第 1 段里的字幕跟着画面前移 2 秒；被裁掉那 2 秒上的字幕留在原地（不删） |
| 定格插入 | 定格点之后的字幕 / 文字跟着后移一个定格时长（2026-08-23「定格只动它所在的那一条轨」在联动关着时照旧） |
| 分割一段 | 什么都不挪 |
| 开关关着 | 以上一样都不发生（只有显式配对） |

## 四、怎么验

- 纯值自检：`scripts/check-timeline-snap.sh` 新一组（`checks/TimelineSnap/Linkage.swift`）按上表逐条钉；反向验证（撤掉跟内容走 / 跨段的规则）各红过。
- 接线守卫：`checks/timeline-drag-wiring/linkage.sh`（`perform` / `liveApply` 收尾调 `TimelineLinkage.follow`、真删的入口传 `deletesContent`、拖动计划带上压着的东西、默认值）。
- 人工：真窗口里拖一段带字幕的主轨块看字幕实时跟；磁吸开着删一段看后面合拢；关掉开关再做一遍都不跟（清单在架构文档）。
