# 让 AI 调用 SrtFlow 剪视频：MCP 方案

> 2026-09-27 访谈后拍的板，**尚未实施**。这里记目标、查清的事实、每一条拍板和理由；
> 实施后已生效的规则写进 `docs/architecture/`，真实进度写进 `docs/reports/`，不要回头把这里当现状。

## 用户的原话

> 现在这个软件，我想做一个 MCP 出来，这样无论我是用 ChatGPT，还是 Claude，还是 DeepSeek，还是 Qwen 等任何 AI，
> 都可以直接调用这个软件进行剪辑视频内容，可以调用软件里的全部功能。……我希望对于用户设置起来是非常简单的。

## 先查清楚的事实（2026-09-27）

- **MCP 是「客户端」说的话，不是模型说的。** 能不能调 SrtFlow 取决于在哪个软件里聊天，不取决于背后是哪家模型。
  - Claude 桌面版、Claude Code、Codex、Cursor、Cherry Studio、腾讯 WorkBuddy 能在本机直接启动一个 stdio MCP 程序。
  - ChatGPT 聊天框只连「网上的地址」。OpenAI 官方的 Secure MCP Tunnel 要开发者平台组织账号 + 管理员授予隧道权限 +
    开发者模式 + 另装 `tunnel-client`，个人用户基本走不通；cloudflared 临时隧道的网址每次重启都变。**Codex 能直连本机，模型一样是 GPT。**
  - DeepSeek、千问自家 App 的 MCP 支持说法不一（有的只是前瞻文章），要实测才能承诺。
- **macOS 没有现成的「App 自动变成 MCP」可用。** macOS 26.1 测试版里出现过 App Intents 接 MCP 的痕迹，但 WWDC26 只给 Xcode 开了 MCP，
  普通 App 没有。MCP 这一层得自己做。
- **协议本身定好了三样东西，我们不设计它们：** JSON-RPC 是信封（方法名固定：`tools/list`、`tools/call`、`resources/read`、`prompts/get`），
  不会给每个功能新造一个 method；每个工具的 `inputSchema`（JSON Schema）才是设计的重头戏；Resource 各家客户端支持参差
  （Claude 桌面版要用户手动附进对话，ChatGPT 基本只认工具），所以**读数据也做成工具**，资源最多镜像一份。
  Prompts（预置模板，客户端里显示成斜杠命令）正好用来装「剪辑套路」（2026-09-28 第 39 条：套路改成 AI 自己挑、用工具读，Prompts 不用了）。
- **仓库里已有的地基：**
  - 所有编辑都经过 `VideoEditProject.perform`（一次改动 = 一步撤销 + 磁吸排列 + 重建预览），AI 的工具直接调这些动作，不模拟点鼠标。
  - 进程内冒烟驱动（`SmokeDriver`）证明了「从外面驱动 App 干活」可行；`SmokeStateDump` 已经能把选择、每段位置、字幕起止写成 JSON，
    「把状态读回来给 AI」可以从它长出来。
  - `Quarantine.swift` 已解决「ad-hoc 签名的包里嵌的程序被系统 SIGKILL」，把 MCP 小程序放进 App 包里走得通。
- **两份测试素材**（`~/Downloads/剪辑测试素材/`，只读看过）：
  - `素材A`：50 个视频共约 571 秒（`Shots/` 下 47 个镜头名字直白，如「企鹅」「船侧面撞击冰」，但混着「丛林熊过河」「红毛猩猩」
    「特斯拉变铁盒」这类和南极无关的），另有 20 多张截图、照片、透明 PNG、一个 gif；样本是竖屏 496×864。**AI 要自己挑出相关的。**
  - `素材B课程`：13 节课共约 65 分钟，全是竖屏 1440×2560，每节 1.5–14.5 分钟；两节文件名带 `WaterMark`；文件夹里没有卖点 / 价格 / 链接的文稿。

## 架构（我定，理由见下）

```
AI 客户端 ──(MCP，stdio，协议固定)──▶ srtflow-mcp 小程序 ──(本机 Unix socket)──▶ SrtFlow 本体
                                                                            （perform / 导出 / 字幕生成 / 分析）
```

1. **真正干活的只有 SrtFlow 本体。** `srtflow-mcp` 只传话，放在 App 包里；App 没开就把它拉起来。后台模式 = 同一个 SrtFlow 不开窗口跑，
   **不另写一套逻辑**（同一规则只有一处实现）。同一份工程在窗口里开着时，后台任务也改走窗口那条路。
2. **协议自己写，不引第三方 SDK**（轻量化优先）；socket 只允许同一个登录用户连，不开网络端口。
3. **工具按领域分**，不是上百个（多了 AI 挑错，而且每次对话都要把全部说明塞进上下文）。起初定的是 25～40 个；2026-09-28 第三块做完到了 40 个，用户改成**不按个数卡、守三条**（第 33 条）：不许有两个长得像的工具、只读的和写文件的不放进同一个工具、说明总长度有上限。说明文字用英文写（模型读英文最准），
   AI 回用户时用用户的语言。初步分组（实施时再定）：工程、素材与文件、读时间线、剪辑（挪 / 裁 / 删 / 分割 / 复制粘贴）、文字与形状、
   转场与滤镜、声音、字幕、分析数据、智能剪、导出与任务、生成（fal / 配音）、会话（模式 / 这一轮 / 停止）。
4. **每个改动工具都返回改完之后的状态摘要**，AI 下一步拿到的永远是最新的样子；用户中途改了、AI 要改的那段不在了就报错重来，不会改错地方。
5. **长任务（导出、生成字幕、画面识别、fal 生成）先返回任务号**，AI 再查进度；停止按钮能取消。
6. **配置里写一个固定位置的小程序**，App 挪了位置也不断（小程序按 bundle id 找 App）。
7. **工具带 MCP 的只读 / 破坏性标注**，客户端据此决定要不要弹权限。注意：Claude 桌面版、Codex 自己也会弹权限（第一次调用某个工具时），
   和我们的「动硬盘才问」是两层，文档里要跟用户说清。

## 分块（第一期）

**提交方式（用户定）：** 第一期**一个分支、一个 PR**，每块、每一步各自是 commit，推到同一个 PR 上让 GitHub CI 跑；
全部做完**一次合并**（`--merge`）。本机装着 Claude 桌面版、Claude Code、Codex（还有 Cursor、ChatGPT），第一期的三个客户端都能在本机实测。

每一块都按仓库规矩：自检进 `check-all`（用一个模拟的 AI 客户端按协议真调工具，素材用合成的，不用用户 Downloads 里的私人素材），
界面部分按 GUI 冒烟流程实机看，bug 照写案例。

1. **最小的路**：连上 Claude 桌面版 / Claude Code / Codex（SrtFlow 里点一下 + 粘一段话）；看得见模式（定位高亮、提示条、停止）；
   开 / 建工程，从开着的工程或点名文件夹导入；读时间线；挪、裁、删、分割；文字；转场；滤镜；字幕（生成、翻译、编辑）；导出；
   ⌘Z + 撤销这一轮；动硬盘才问。
2. **先补 AI 的手和眼**（第 31 条，2026-09-27 实测后提前，放在这一块最前面）：`edit_clip` 开放裁切、位置、缩放；
   自动找黑边（本机抽几帧、Core Image 算黑边给出裁切值）；转竖屏对准主体（Vision 人脸 / 主体位置，原在第 4 块）；

## 已知的风险

- **成片好不好看取决于模型。** 同一套路，不同模型剪出来差别会很大；套路写得越具体，差别越小。
- **ad-hoc 签名**：每次新版本 TCC 可能重新弹权限（读 Downloads、控制访达），发布给别人前要在别人的机器上实测。
- **fal 的单价会变**：每日上限是估算，不是 fal 账单；换模型要重新登记单价。
- **「一轮」按时间判断**：AI 想得久（超过约 30 秒）会被切成两轮。
