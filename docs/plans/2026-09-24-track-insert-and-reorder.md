# 插进两条轨之间 + 整条轨换位置

长期约束（插入缝的几何、停顿门槛、拖动中不写模型、整轨换位的动画豁免）写在
[拖动手势](../architecture/timeline-drag-gestures.md) §5h / §5i 和
[视频轨对等化](../architecture/video-tracks.md)「轨道头这一列」；本文记目标和拍过的板。

## 一、目标（用户原话）

> 这些轨道允许移动的时候，插入，比如你拖拽一个轨道文件，移动到两条轨道之间的时候，
> 就可以插入进来，也有一个插入的动画，上下两边的轨道会拉开，留出空位，如果不松鼠标移走，
> 那么间隙又消失。

讨论中又加了一条：

> 我说的是素材块，但是我现在也希望整条轨换位置也加进来。

在这之前：

- 跨轨拖动只认**现有的行**（竖着拖出 18pt 后，找离块中心最近的同类行），另外只有两个
  「新开一条轨」的入口：视频拖出最上面 = 顶上新开一条，音频拖出最下面 = 底下新开一条。
  **中间插不进去。**
- 新开轨的提示是一条 3pt 的线 + 一个缩到 22pt、骑在线上的框 —— 那儿没地方画整条轨高的框。
- 轨道的上下顺序只能靠「把素材一段段挪过去」来改；在轨道头上下拖是调行高。

## 二、拍过的板（2026-09-24）

先讨论、列问题带推荐，用户逐条回复。推翻前先读理由。

### 插进两条轨之间

| 决定 | 口径 | 理由 |
| --- | --- | --- |
| 哪些拖动会拉开空位 | **三种都会**：拖时间线上的素材块、从 Finder 拖文件、从音频库拖素材 | 用户选的（1:B）。落点只有一种画法，没道理让用户学第二种落点语言 |
| 停顿门槛 | 指针在缝上**停约 0.2 秒**才拉开；最顶上、最底下新开一条轨也一样 | 用户选的（2:B）。把块挪到隔壁轨时指针一定会经过两条轨之间的缝：碰到就拉开的话，每次挪到隔壁轨都要开合一下，隔壁轨还会先被推远一个身位 |
| 没等拉开就松手 | 按原来的规则落到高亮的那条轨上 | 看到什么落什么：缝还没开，框就画在那条轨上 |
| 空位多高 | **窄缝**：缝从 5pt 拉到 28pt，刚好放下原来那个 22pt 的小落点框和一条插入线 | 用户选的（3:B，我推荐的是整条轨高）：下面的轨只挪二十来个点，新开轨的样子和以前一样，只是终于有了自己的位置 |
| 主轨下面 | **不开缝** | 用户同意（4）。主轨永远是最底层画面，磁吸、转场、0 号色都绑在它身上 |
| 视频块的缝 | 上层轨之间、最上面那条上层轨的上方、最下面那条上层轨的下方 | 新轨长在哪、缝就开在哪 |
| 音频块的缝 | 音频轨之间、第一条音频轨上方、最后一条下方 | 同上 |
| 文字行 / 形状行夹在上层轨和主轨之间时 | 「新的最低一层上层轨」那条缝开在它们**上面**，不开在主轨正上方 | 新轨实际出现在那儿（行的顺序：上层轨、文字、形状、主轨），缝开在别处就是框说谎 |
| 多选拖动 | 只有被拖的那一段进新轨，其余成员在各自轨上横着跟过去 | 和现在的跨轨一致（`relocateClip` 只搬被拖的那个） |
| 原轨只剩这一段 | 它上下紧挨着的两条缝**不开** | 那等于原地换一条新轨，还会丢掉这条轨调过的行高 |
| 算「在缝上」的范围 | 缝本身 5pt，再往上下两条轨里各伸 8pt；已经拉开的缝再多给 4pt 才合上 | 行的中间大部分区域仍然是「放进这条轨」；多给的 4pt 防止指针停在边上时一开一合 |
| Finder 一次拖进视频 + 音频 | 类型和这条缝对得上的文件进新轨（首尾相接），其余按原来的规则落（时间照用指针、轨道退回该类型的默认轨） | 用户同意的默认 |
| 标尺 / 滤镜行上方 | 拖**素材块**时，指针在最上面那条视频缝以上都算这条缝（原来就是「拖出最上面 = 顶上新开一条」）；拖**文件 / 音频库**时只认缝本身，标尺和滤镜行仍按默认轨落 | 两边都保持原来的行为，不借这次改掉别的落点 |
| 撤销 | 一步 | 落地仍是一次 `perform` |

### 整条轨换位置

| 决定 | 口径 | 理由 |
| --- | --- | --- |
| 抓哪里 | **学 Logic**：按住轨道头拖 = 挪整条轨；调行高改成拖轨道头的**下边缘**（悬停时光标变成上下箭头）；点一下仍是选中这一行的素材 | 用户选的（6:A）。抓的面积大，也和音频那边已经学 Logic 的做法一致。代价写在明处：「在轨道头哪儿拖都能调行高」这个习惯要改 |
| 拖的过程中 | 被拖的整条轨（轨道头连同这一行的素材块）跟着指针走，其余轨实时滑开让位；**不用停顿** | 用户选的（7:A）。挪上层视频轨会改变画面叠放顺序，提前看到最终顺序最不容易出错；这里没有「挪去隔壁轨」这个要让路的动作 |
| 能挪什么 | 上层视频轨在上层视频轨之间挪，音频轨在音频轨之间挪；主轨固定在最底下、它的轨道头拖不动；滤镜 / 文字 / 形状 / 字幕行不能挪 | 同第 4 条；滤镜层的上下顺序决定调色的叠加顺序，也能做，但那是另一件事 |
| 跟着轨走的 | 颜色、行高、推子、隐藏状态 | 它们本来就绑在轨道身份上（`EditLane`、`TimelineRowHeightKey`） |
| 挪完 | 上层视频轨的叠放顺序立刻变，预览重建；音频轨只改排列，声音不变；⌘Z 一步撤回 | |
| 其余 | 拖到视口上下边缘自动滚动；隐藏的轨也能挪；挪轨不改变选择；不加右键菜单的「上移 / 下移」 | 用户同意的默认 |

## 三、实现上定下来的几条

- **缝开没开是视图状态**，拖动过程中一个字都不写 `TimelineState`（同 §0）。行的位置只有一个
  纯值函数（`TimelineSeams.layout`）：轨道头列和轨道行按它加同一段 padding，落点框和
  命中判定按它算，所以三者永远对得上。
- **跨轨拖动的纵向判定改成按指针算**（视口 y + 现读的纵向滚动量），不再按「起手那一行的
  中线 + dy」。缝一拉开，指针底下的行会被推走，按起手时的行去推算就会把指针算错一个缝宽。
  纵向自动滚动那一拍也重算目标行（以前只重算横向）。
- **停顿计时是一个共用的对象**（`TimelineSeamDwell`），三种拖动都走它：指针不动时 SwiftUI
  不会再来一拍，停够时间要靠它自己回调。
- **性能 ratchet 只许降**：轨道头的行在时钟每跳一下时**不重算**（2026-09-24 CI 实测），靠的是它的
  输入每次都「相等」。所以换位的手势直接写在 `TimelineHeaderRow` 的 body 里，不新增修饰器，
  也不往它的输入里塞闭包；拉开缝、换位时的位移全用 `.padding` / `.offset` 这类不计数的原语。

## 四、分刀（一个 PR，多个 commit）

1. 本方案文档。
2. 拖素材块：插进两条轨之间（纯值的缝几何与落地、停顿计时、拉开动画、守卫与自检）。
3. 从 Finder 拖文件、从音频库拖素材：同一套缝。
4. 整条轨换位置：轨道头拖动换位，调行高挪到下边缘。

## 五、验收

自动检查：`scripts/check-timeline-snap.sh`（缝的几何与命中、插进新轨的落地与占位框对账、
换位的目标与位移、`moveLane`）、`scripts/check-media-import.sh`（插进缝的导入落点）、
`checks/timeline-drag-wiring.sh`（接线）、`checks/hover-pointer-style.sh`（换位的抓手光标）。
手感部分按 [拖动手势](../architecture/timeline-drag-gestures.md) 和
[视频轨对等化](../architecture/video-tracks.md) 的人工回归清单实机走一遍。
