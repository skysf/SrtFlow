# 视频 upscale：轨道上的片段一键送 fal 放大，比过再换

> 2026-10-02 用户提的：有了 fal 的 Key，想在检查器和右键菜单里给视频片段加一个 upscale 入口，只做轨道上用到的那一段、
> 明确显示到各分辨率的实际成本、做完先对比（分割线 / 并排、同步播放）再决定替换 / 不替换 / 换模型重做、文件存在原片旁边、
> 替换过的能换回原片。用户点名四个模型，让我再挑两家；我列了十四条疑问，用户逐条拍板；然后在南极工程上真跑了 19 条、

## 二、实测定下来的事实（细节见实施报告）

- **声音**：都带回来了，但只有 FLUX 逐采样和原片相同；Topaz 把声音裁到画面长度，字节重采样到 44.1 kHz，Bria 重编码且短 0.1 秒。
- **帧数**：Topaz precision / generative、字节一帧不差；FLUX 多一帧或少一帧；Topaz creative 少 3 帧。替换时按帧数核对。
- **分辨率**：倍数可以是小数（1344×768 传 1.40625 正好 1890×1080）；FLUX 最小 1.5 倍；Topaz creative 这次听了倍数没出 4K。
- **钱**：字节 units = 输出秒数、分毫不差；FLUX 按输出百万像素·秒线性（precise $0.0715、creative $0.1001）；Topaz 按 unit $0.01，
  precision 实收约网页价一半、台阶规则没公开；账户没有折扣（`percent_discount` 0）。实际扣费能按 `request_id` 从账单明细接口查到（要 ADMIN 权限的 Key）。
- **上传**：`storage_type=fal-cdn-v3`，旧的 `gcs` 已被拒。
- **速度**（19 条同时提交、含排队）：Topaz precision 50–85 秒，generative 193 秒，creative 627 秒，FLUX 91–200 秒，字节 standard 121–165 秒、pro 324 秒。

## 三、分刀

| 刀 | 做什么 | 状态 |
| --- | --- | --- |
| 1 地基 | `FalClient.upload`（initiate + PUT）、`billingEvents`（账单明细）、六个档位的表 `FalUpscaleTiers`（请求体、倍数夹、估价规律）、四个端点的接口定义快照、`refresh.py` 扫 upscale 表、自检第七 / 八组 | 已合并（PR #137） |
| 2 模型 | 片段上记 upscale 来源（`EditClip`，格式 v29）、单片段换源 + 源时间平移（关键帧 / 标记 / 音量曲线）、换回原片、旧文件留在素材表里、分割要抄新字段 | 已合并（PR #138） |
| 3 任务 | 算范围（这一处 / 最长的那处 / 整个文件 + 余料）、裁出 H.264 中间件（AVAssetWriter，`MediaReadQueue`）、上传、排队、下载、封回原声（App 自带 ffmpeg：画面复制、声音精确裁后重编 AAC）、命名落盘、对账实际扣费、进度与取消 | 本 PR |
| 4 界面 | 检查器一节、右键菜单、Upscale 面板、对比窗口、导出提示、块角标、三张语言表、人工回归清单、架构文档 | 待做 |
