## 一、目标（用户原话）

> 目前音频轨道，哪怕我 zoom in 到最大，还是不够，然后音频轨道的文件我不希望是柱状图，
> 我希望像 logic pro 里显示的一样，然后 zoom in 足够大了，还可以调整声音的音量，这个
> 音量可以直接在音轨上调整曲线，和 logic pro 一样。
>
> 然后每个带声音的文件，是纯音频，还是视频，在（轨道头）这一列增加这个音量（推子 +
> 电平条），会显示有没有爆音。

「放到最大还不够」有两个根因，得一起修：

1. 缩放上限 120pt/秒 —— 24fps 下一帧才 5pt。
2. 波形**每段固定读成 240 根柱子**（8kHz 单声道），和缩放无关：60 秒的段放多大都是这
   240 根，放大只是把每根拉宽。光放开上限没用。

## 二、拍过的板（2026-09-23）

用户授权：「你按照用户体验最丝滑的方式来做选择」。下面每一条都按这个标准定，
理由写在旁边，推翻前先读理由。

| 决定 | 口径 | 理由 |
| --- | --- | --- |
| 缩放深度 | 上限 **4800pt/秒**（原来的 40 倍，24fps 下一帧约 200pt），不做到采样级 | 预览合成的时间刻度是 1/600 秒（≈1.7ms），到这儿剪点已经不能更细；再深只剩「看」没有「剪」 |
| 缩放滑杆 | 改成**对数刻度** | 线性滑杆上原来的整个区间会挤在最左 2% |
| 波形外观 | 以中线**上下对称**的连续填充（真实 min/max，不是柱子），放大后自然变成一条线 | Logic 的样子 |
| 波形数据 | 每个**文件**读一次，存多级峰值（Logic 的 overview） | 放多大都不再读 PCM；裁切/分割/挪位置不重读 |
| 立体声 | 行矮时合成一条；波形区够高（≥40pt）时拆成 L / R 两条 | Logic 是拆开的，但默认 34pt 的音频行拆开就两条细线 |
| 波形高度 | 继续画「**听到的声音**」：段音量 / 曲线 / 渐入渐出 / **轨道推子**都乘进去 | 这是已有的产品口径（audio-fades.md）；也是「不播放就能看出爆音」的前提。与 Logic 不同，写在明处 |
| 曲线归属 | 曲线**属于段**（点锚在源时间上，同关键帧），**推子属于轨** | 挪动、分割、裁切、变速都跟着那段声音走；Logic 的轨道自动化会留在原地，剪视频时反直觉 |
| 曲线插值 | **dB 线性**（屏幕上的直线 = 听到的那条线），纵轴是 −∞…+6dB 的 dB 刻度 | 与检查器滑杆、推子同一个刻度 |
| 曲线与 `volume` | 有点时**曲线取代 `volume`**；加点取当前线上的值（加点本身不改声音）；删掉最后一个点把值固化回 `volume` | 同关键帧那一套，老工程零迁移 |
| 曲线交互 | **常显 + 贴着线操作**（Final Cut 式）：靠近线光标变 ↕，拖线 = 这一段上下；⌥ 点线加点；拖点改时间和值；⌥ 点点删掉 | 不用切模式；新增的只是贴着线的一条窄命中区，现有拖动 / 裁切 / 框选合同原样不动 |
| 检查器音量滑杆 | 有曲线时**整条曲线一起抬 / 压**（形状不变），显示播放头处的值 | 「这段整体太响」是最常见的需求，逐点拖太累 |
| 视频自带的声音 | 也能画曲线：视频块底部的波形带随行高变高，曲线画在那一带；视频行高上限放到 200pt | 录屏、口播的人声就在视频块里 |
| 推子 | 每条能出声的轨（主轨、上层视频轨、音频轨）一个横向推子，−∞…+6dB，⌥ 点 / 双击回 0dB | Logic 轨道头的样子 |
| 总推子 + 总电平表 | 放在轨道头列最上面那一格（标尺行，原来是空的） | 导出是各轨直接相加（`amix normalize=0`，不压不限），「每条轨都没爆、加起来爆了」只有总表看得见，而成片里的爆音恰恰多是这一种 |
| 电平表 | 推子里嵌立体声电平条，绿 → 黄（−12dB）→ 红（0dBFS），红灯**一直亮到点掉** | Logic 的行为 |
| 不播放也看得见爆音 | 波形上超过 0dBFS 的地方直接标红 | 有了新的波形数据，几乎白送 |
| 轨道头宽度 | 54pt → 约 136pt | 放得下推子 |
| M / S（静音 / 独奏） | **这一轮不做** | 用户没要；推子拉到底就是静音；独奏会让预览和成片不一致，要另拍板 |

## 三、实测地基（2026-09-23 三个探针）

脚本和原始数据在当时的临时目录里，结论如下（长期约束已抄进对应的架构文档）。

**ffmpeg 8.1（随包那份）逐样本增益：用 `aeval` + 平衡 if 树。**
- 精度到 float32（增益误差 1.2e-7），N=4000 个折点时 48 秒立体声多花 0.85 秒。
- `if` 是惰性求值，平衡树的代价随 log N 涨；写成「各段相加」是线性的，N=1000 要多花几分钟。
- **必须放在 `adelay` 之前**：`adelay` 垫的静音没有时间戳，`aeval` 在那里读到 NaN。
- 表达式嵌套超过约 100 层直接被拒；数字要全精度（三位小数量到 0.02–0.04 的增益误差）。
- 整条命令行（含环境变量）共享 1MB 的 ARG_MAX，大图改走 `-/filter_complex <文件>`。

**SwiftUI 超宽内容：纯色 / 描边 / 位图安全，Canvas 的绘制代码要自己按可见范围裁。**
- `Shape.fill`、全宽 `Path` 描边、位图缩略图在 1000 万点宽照样正常，几乎不占内存。
- Canvas 只光栅化可见条带（视口 ±128pt），**但闭包拿到的是整宽**、每滚 128pt 重跑一次；
  全宽画的话 10M 宽时一次 370ms、内存只涨不退（270 → 1080MB）。
- `context.clipBoundingRect` **就是那条可见条带**（Canvas 自己的局部坐标，嵌在带
  `.offset` 的块里也对）；滚动时闭包会被自动重调，不需要任何状态。只画这一段：
  像素逐点一致，内存平，10M 宽滚动 733ms（理想 667ms）。
- SF Symbol 随宽度放大的图在 1M 以上直接空白（不涉及我们的缩略图，那是位图）。

**AVFoundation 音频 tap（电平表）：拿到的是乘音量之前的采样。**
- `PreEffects` / `PostEffects` 两种 tap 都看不到 audioMix 的音量；`PostEffects` 的时间
  标签还不准。所以用 `PreEffects`，**增益自己乘**（折线表就在手里）。
- **每次换 audioMix 就新建 tap 的话，播放会卡住约 0.6 秒**（静默，不报错）；复用同一批
  tap 对象则完全平滑 —— tap 必须跟着合成活，快路径换 mix 时挂回同一个。
- 实时播放时 tap 比播放头提前约 280ms 渲染；两条轨的回调**不对齐**（时间网格差几百帧），
  总表只能按**绝对采样位置**把各轨加起来。
- 暂停后 tap 仍每 ~93ms 空转一次（时长 0），要按时长过滤。
- 离线 `AVAssetReaderAudioMixOutput` 同样会调 tap，自检够得着。

## 四、分刀（一个 PR，多个 commit）

1. 本文档。
2. 模型：段的音量曲线、轨道推子、总推子，格式 v19，分割 / 分离音频 / 选段导出带着走。
3. 两条管线：预览 `setVolumeRamp` 折线 + 推子；导出 `aeval` + 推子；真实包络对账。
4. Logic 式波形：多级峰值、只画可见的那一段、立体声拆分、爆音标红。
5. 深度缩放：上限 4800、对数滑杆、标尺到帧、缩略图按可见范围铺。
6. 在块上画曲线、检查器整条平移。
7. 轨道头推子 + 总推子。
8. 电平表与爆音红灯。
