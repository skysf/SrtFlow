# 时间线拖动手势：坐标系与刷新约束

> 改剪辑块的移动/裁切手势、或给时间线加新把手（转场把手、淡入淡出把手等）
> 之前必读。案例背景见
> [2026-08-03-trim-flicker-halved.md](../bugfixes/2026-08-03-trim-flicker-halved.md)
> 与
> [2026-08-09-timeline-clip-drag-lag-and-alignment.md](../bugfixes/2026-08-09-timeline-clip-drag-lag-and-alignment.md)。
>
> 下面第 0、1 节各配了守卫：纯值部分在 `scripts/check-timeline-snap.sh`，
> 自检编不动的 SwiftUI 接线在 `checks/timeline-drag-wiring.sh`。**改这块代码
> 前先看一眼那两个文件在钉什么**，别把守卫绕过去。

## 0. 拖动**过程**中不写 `TimelineState`（最重要的一条）

块在拖动期间画在哪，只由视图状态 `ClipDragSession.offset` 决定；模型只在**松手**
那一下改一次（`VideoEditProject.commitDrag` / `commitFreeDrag` → 纯值的
`TimelineState.applyDrag`，包在**一次** `perform` 里，一步撤销一次预览重建）。
三类块（剪辑 / 形状 / 字幕 cue）各有自己的移动手势，但只有这两个落地入口：
剪辑走 `commitDrag`（要跨轨、要插空），形状和 cue 走 `commitFreeDrag`。

理由不是"省几次重绘"：`state` 是 `@Published`，每一拍写它会连带整个编辑器视图树
（预览区、检查器、所有剪辑块连同缩略图与波形）重建，还要重挂一次自动保存。
单拍处理越久 `mouseDragged` 队列积压越多，**落后量随拖动时间累积**，表现就是
「光标到最右、块还在中间」。

推论：拖动中要让**跟随块**（链接的音频、多选的伙伴）跟着动，靠的也是给它们同一个
渲染偏移，不是去改它们的 `timelineStart`。

## 1. 布局模型与坐标系

`ClipBlockView` 在轨道行里的**布局**位置固定在行首（ZStack topLeading），
横向位置全靠 `.offset(x: timelineStart * pps)` 渲染偏移。

- 挂在块**边缘**的 overlay 把手（裁切把手；`alignment: .leading/.trailing`）
  的布局位置**随块宽变化而移动**。手势一边报 translation、一边让把手自己
  挪窝，`.local` 坐标下就是反馈回路：`d(n+1) = T - d(n)` 振荡（闪烁），
  时间平均半速（裁切量 = 鼠标位移的一半）。→ 用 `.global`。
- 块**本体**的移动手势：块自己会在手指底下挪窝（`.offset`），拖到边缘时
  自动滚动还会把整块内容抽走 —— 两者都会污染以块自身为参照的 translation。
  → 钉在**滚动视口**的命名坐标系 `VideoEditTimelineView.scrollSpace` 上。
  顺带一个好处：`value.location.x` 直接就是指针在视口里的 x，自动滚动判边界
  拿来就用。

**规则：手势视图自己会动（布局或渲染）的，DragGesture 一律显式指定一个不会动的
参照坐标系** —— 有稳定的祖先容器就用命名坐标系，没有才退到 `.global`。

## 1b. 块内装饰不吃事件（命中区 ≠ 画出来的区域）

`.clipped()` / `.clipShape` **只裁绘制，不裁命中**：`scaledToFill` 溢出到 frame
之外的部分照样参与 hit test，而块的点选/拖动/悬停挂在 `ClipBlockView` 整棵
子树上，命中区域是子视图的**并集**。竖版图的缩略图 tile 放大后溢出可达几百 pt，
曾把块上方的整条标尺变成「点哪都是选中图片」（见
[2026-08-16-clipped-thumbnail-hit-area-covers-ruler.md](../bugfixes/2026-08-16-clipped-thumbnail-hit-area-covers-ruler.md)）。

规则：**块内一切装饰性内容（缩略图条、波形、关键帧菱形，以及将来的同类）一律
`allowsHitTesting(false)`**；交互统一由 `ClipBlockView` 层的手势 + 底色矩形
命中面承担。守卫在 `checks/timeline-drag-wiring.sh` 第 8 节。新增会溢出绘制的
内容（`scaledToFill`、`fixedSize`、负 offset）时，先想清楚它的命中高度是不是
真的等于画出来的高度。

## 2. 连续拖动中的刷新约束

1. **动画豁免正在被拖的元素**：`.animation(_, value: timelineStart)` 是给
   磁吸重排的邻居的；被拖/被裁的块自己必须即时跟手（`isTrimming` /
   `dragOffset` 两个都要判），否则 0.12s 动画每 tick 重定向，画出来的是
   「低通滤波后的鼠标」，手越快落后越多。
   `.animation(_:value:)` 会把该视图**所有**可动画属性一起 animate，不只是
   你盯着的那个 —— 2026-08-09 那次就是只豁免了裁切、漏了移动。
2. **异步内容（缩略图/波形）去抖**：`.task(id:)` 的 id 含
   `sourceStart/sourceDuration` 这类拖动中连续变化的量，任务体开头
   `Task.sleep(200ms)` 去抖 + 落地前 `Task.isCancelled` 检查缺一不可——
   取消不拦落地的话，旧结果会乱序盖掉新结果（闪图）。串行 actor 里的
   逐帧解码循环内也要查取消，别磨废帧堵新请求。
3. **预览 seek 防洪**：拖动路径上的 `clock.seek(precise: false)` 走
   `PlayerClock` 的链式 seek（QA1820），调用方不要自己按秒数节流（见
   [2026-08-03-scrub-preview-keyframe-snap.md](../bugfixes/2026-08-03-scrub-preview-keyframe-snap.md)）。

## 主轨数组顺序 = 时间顺序（不变量）

`mainClips` 的下游全按数组顺序消费：A/B 合成轨的游标式插入（乱序会被
`insertTimeRange` 挤歪 → 黑屏）、转场按数组相邻配对、auto 画布取数组第一段。
磁吸开着由 `packMain()` 维持；磁吸关掉的移动/跨轨落主轨必须在收尾调
`sortMainClipsByStart()`（`TimelineState.applyDrag`、`relocateClip` 已接）。打开工程时
`VideoEditProjectIO.load` 归一治旧文件，`CompositionBuilder.build` /
`ExportGraph.plan` 入口再各防御一次。**新加任何改 `timelineStart` 或往
`mainClips` 里插段的入口，都要么保序要么收尾排一次**；来龙去脉见
[2026-08-08-main-track-array-order-black-frame.md](../bugfixes/2026-08-08-main-track-array-order-black-frame.md)。

## 3. 落点只有一份算法（`ClipDragPlan.resolve`）

一次拖动有两条消费路径：**拖动中渲染**和**松手落地**。它们各自算一遍位置，
就一定会分叉 —— 历史上落地那步偷偷多跑一遍 `clampedStart`，于是拖动中显示
9s、松手弹到 5s。

规则：手势开始时冻结 `ClipDragPlan`（成员、各自轨上**不动的**块、吸附候选、
磁吸模式），之后每一拍只喂 `desiredDelta`，`resolve` 出来的那一份
`DragResolution` **同时**用于渲染和 `TimelineState.applyDrag`。落地那一层
不许再解析任何位置。

配套的三条：

- **整组一个 delta，绝不逐块夹取。** 逐块跑 `clampedStart` 会把同组伙伴当成
  障碍：同轨 A、B 一起选中拖 A，A 会被**旧位置的 B** 顶回原地，整组一动不动。
  碰撞只看不跟着动的块。落点语义（2026-08-23 起）是「**就近落进合法间隙**」
  （`ClipDragPlan.fittedDelta`）：指针没越过障碍时停在这一侧的接触面（老手感
  不变），越过了就落到另一侧 —— 同轨就能把块直接拖过邻居进间隙，不用再
  「先挪去画中画再挪回来」。块画在哪儿，松手就落在哪儿。
- **装不下的间隙 = 塞进去 + 右侧让位**（同日，用户反馈）：指针中心悬在一个
  比素材短的真间隙上时，落点是间隙起点，本轨间隙右侧的不动内容整体右移
  「素材时长 − 间隙宽度」（`DragResolution.sameTrackPush`，只推被拖块自己的
  轨，与定格插入同款范围；跨轨落地时忽略）。不然主轨排满时块彻底动弹不得，
  用户只能借道画中画、还会落成重叠。只在「组里其余成员都没有障碍」时提供 ——
  让位帮不了别的轨上的成员。
- **跟随块只做水平平移，且和跨轨搬运在同一次 `perform` 里。** 分两次提交
  = 两步撤销 + 视频换轨了而链接音频留在旧时刻（A/V 错位）。
- **磁吸模式下跟随块按被拖块的实际最终落点平移**，哪怕落点被别的块占着也不
  挤开 —— 声画同步优先于顺手避免重叠。

`clampedStart` 现在只剩一个合法用途：**跨轨落地到岸后的让位**（目标轨上的
障碍在手势开始时还不知道，那时候还不知道会落到哪条轨）。同轨移动碰它就是 bug。

## 3.5 框选（`TimelineMarquee`）

轨道**空白处**按下拖动 = 拉框选。手势挂在滚动内容的容器上，不是各行上：
SwiftUI 里子视图的手势优先，所以块本体的移动、标尺的 scrub、把手的裁切
都照旧归它们自己，只有谁都不认领的空白才落到框选。刀片模式下整条停掉
（`including: .subviews`）——只 guard 回调的话，4pt 的手抖会把本该落下的
那一刀吃成一次框选。

- **拖框中一个字都不写 `project`**（同第 0 节，理由一模一样）。命中集合只在
  视图层的 `TimelineMarquee.Session.hit` 里，块的高亮走
  `isSelected(clip:)/(shape:)/(cue:)` 这三个「看框不看模型」的助手，松手才
  `applyBoxSelection` 落一次。每一拍写 `@Published` 的选择会连带预览区、
  检查器、所有块连同缩略图与波形重建，还要重挂一次自动保存。
- **锚点存滚动内容坐标**（起手时的视口 x + 当时的滚动量）。存视口坐标的话，
  拖到边缘自动滚动会把内容从框底下抽走，框住的东西莫名其妙地变。
- **那个「当时的滚动量」必须现读**（§5b）：框选是全时间线唯一用绝对坐标的手势，
  读到一个滞后的值，框就整体偏出一个滚动量 —— 而且命中判定用的是同一个矩形，
  框中的块也跟着错。
- **相交即选中**，不是「完全框住」。放大之后选一段长素材本来要把框拖出好几屏；
  横着扫一条细线就能选一排，才是这个手势该有的手感。
- **判定用的矩形必须等于画出来的矩形 —— 宽和高都是。**
  - 宽：0.05 秒的碎块按真实时长只有 1 个点宽，按真实时长判定的话，用户明明
    框过了那个可见的小方块却什么都没选中。三个最小宽度常量
    （剪辑 6 / 形状 24 / cue 2）在 `TimelineMarquee` 里。
  - 高：**按块，不按整行**。字幕行高 22 而 cue 块只有 14（上下各留 4）、形状
    行高 26 而块只有 20（上下各留 3）；按整行判的话，框只从这些留白里扫过、
    一个像素都没碰到块，也会把它选中。留白与块高同样是 `TimelineMarquee` 的
    常量（`cueTopInset` / `cueHeight` / `shapeTopInset` / `shapeHeight`）。
    剪辑块铺满整行，没有对应常量，直接用行高。
  - 这几个常量画和判**共用**，别在任何一边再写字面量 —— 接线守卫要求它们在
    视图里各出现至少两处（一处画、一处喂给命中判定）。
- **隐藏轨整轨跳过**：看不见的东西被框走、跟着一起被拖被删是纯粹的惊吓。
- ⌘/⇧ 拖框 = 在原有选择上加选，起手时定死，中途松开修饰键不改语义。

### 混选与「预览上最多一套框」

框能一次选中**剪辑 + 形状 + 字幕 cue**。老的四类互斥（`EditSelection`）不是
消失了，是换了地方守：

- **点选仍然互斥**，混选只能从 `EditSelection.selectBox` 这一个入口进来。
- 预览上的框只认 `sole*` —— 三类加起来只选中一个时才有主角，多选或混选一律
  不画框（和以前「多选剪辑时不画框」一致）。所以「同时挂两套框、把手互相压住」
  在类型层面仍然不可能。
- **标记对所有人互斥**，框选无条件清掉它（空框也清）。它的互斥从来不是为了
  画框，是为了 ⌫ —— 留着标记的话删除键会走进标记分支。
- ⌫ 一次删掉选中的三类（收在同一次 `perform`，一步撤销）。按分支顺序只删一类
  的话，用户框了一片按删除，会看到「删了一半」。

### 整组一起移动

拖任意一个被选中的东西，整片跟着走：三类改的字段不同（剪辑/形状改
`timelineStart`，cue 要两轨同步走 `LinkedSubtitleEditing.setStarts`），
但**位移只有一个**，统一在 `TimelineState.move(_:by:)` 里。

**「拖任意一个」要求三类都真的有移动手势**：cue 曾经只有点选手势，于是这句话
对它只成立一半（只能「拖剪辑时 cue 跟着」，不能从 cue 起手）。
`checks/timeline-drag-wiring.sh` 现在按块型逐个钉住，别再靠数手势个数 ——
容器上还挂着拉框手势，数出来的绿是假绿。

- **落点按「冻结的 span + delta」算绝对值**，不是在当前值上叠加。磁吸主轨那条
  分支会拿实际落点把非主轨成员再平一次，叠加式的接口在那里就是双倍位移。
- **最终落点可能不等于 `resolution.delta`**，两处会改写它：磁吸插空把被拖块
  挤到缝的位置，跨轨到岸被 `clampedStart` 让开目标轨上的占位。所以 `applyDrag`
  收尾统一调 `realignCompanions`，按**被拖块的实际落点**把伙伴再平一次
  （幂等，因为算的是绝对值）。少了它，「拖进有占位的轨」会把整组拆散、链接
  音频当场 A/V 错位。
- **链接组要为每一个多选成员各展开一次**（`TimelineState.draggingClipIDs`）。
  只展开被拖的那个的话，框选 A、B 两段、各自都带分离音频时，B 会动、B 的音频
  不动。
- **磁吸开着时主轨块不参与整组平移**：它们的位置只由 `packMain` 决定，跟着平移
  在拖动中画出来了、松手 `perform` 那次重排又排回去，等于骗了用户一路。所以
  拖的**不是**主轨块时，主轨成员在冻结计划那一步就被剔除（拖动中就看得出它们
  不动）。想让主轨块跟着走，关掉磁吸。
  > 代价写在明处：磁吸下拖主轨块分离出来的音频，画面不会跟着走 —— 磁吸本来
  > 也不允许主轨块自由平移。要保持声画同步就关磁吸再拖。
- **声画同步高于「整组同一位移」。** 两者冲突时以同步为准：被 `packMain` 排过
  的主轨成员，它的**链接伙伴按它自己的实际位移走**，不是按整组的 delta 走。
  从主轨把一段拖去别的轨时必然撞上这条 —— 磁吸会让剩下的主轨块合拢，那些块
  自己挪了位置，它们分离出来的音频若还跟着手势走就是错开一整段。
  （冻结计划只按**起手轨**判断磁吸模式，而拖动途中可以改成跨轨落地，所以
  「从主轨起手必然走插空」这个假设不成立 —— 落地那一步必须自己兜住。）
- **跨轨到岸的让位不许把整组顶过下界。** `clampedStart` 往左躲一旦越过
  `plan.groupLowerDelta`（整组里起点最小的那个成员决定），伙伴就会各自被
  `max(0, …)` 单独夹住，相对错位当场压扁；越界时改往占位右侧落。
  下界**不能**拿 `allowedDeltaRange().lower`：那里面还叠着**源轨**的障碍，
  而块已经换轨了。
- **`applyDrag` 自己把磁吸重排做完**（`if magnet { packMain() }`），产物即最终
  状态。以前只靠 `perform` 之后那次重排，自检在纯值层看到的就不是真实落点 ——
  端到端用例因此假绿了一轮。自检里的 `performDrag` 也要跟着补上那一步。
- 形状和 cue 挂进 `ClipDragPlan.members`（`adding(shapes:cues:)`），所以
  `allowedDeltaRange` 的下界自动把它们算进去：整组一起停在 0 秒，而不是剪辑
  还能往左、字幕已经各自夹在 0 上，相对错位当场压扁。
- cue 挪完必须**重排 + reindex**：`cues` 的数组顺序就是时间顺序，下游按顺序
  消费，挪过头不重排会让导出的 .srt 序号和时间对不上。

## 4. 吸附与对齐线（`TimelineSnap`，纯值函数）

- **两条边都参与吸附**：块的起点和终点各自去够每个候选，所有配对里取位移最小的
  那一种。只比起点的话「右边缘贴上别人的左边缘」永远没反应。
- **候选在手势开始时算一次就冻住**（`ClipDragSession.candidates`）。拖动中重算会
  把**跟着一起动的伙伴**（链接音频、多选的其他块）算成候选 —— 它们上一拍刚被挪到
  手指底下，这一拍就把块吸回上一帧的位置，手感是「拖不动」，而且鼠标越慢越粘。
- **「谁在动」只有一份名单**：`VideoEditProject.movingClipIDs(draggedID:)`，
  候选、渲染偏移、落地三处共用。三处各算一份迟早分叉。
- **落点先夹再算线**：参考线按夹完（`minimumStart`）的位置算，否则线在一处、
  块在另一处。
- **主轨磁吸开着时不给对齐线**：落点由插空决定、松手一律被 `packMain` 覆盖，
  亮线是骗人的。那种情况下改画**与素材等长的青色占位框**（能一眼看出这 6 秒
  会占到哪里），位置和宽度都由 `TimelineSnap.mainInsertion` 给 —— **落地必须
  调同一个函数**，否则占位框会说谎。
- **跨轨拖动在目标行也画等长占位框**：位置由 `TimelineState.crossTrackLandingSpan`
  给，它和落地的 `relocateClip` 共用同一份核心（`avoidingOverlap` /
  `mainInsertion`）。改挤开/插空的任何一边，另一边必须跟着改 —— 框指哪儿，
  松手就得落哪儿（守卫在 `checks/TimelineSnap` §26）。
- **插入时刻必须在「插入之后的最终数组」上算。** 插进来的块会改变相邻关系，
  转场能叠掉的量按两边任一段的 45% 收紧、跟着就变：A(10s，其后 2s 转场) + B(10s)
  之间插一段 1s 的 M，按插入**前**的数组算是 8s，实际 A→M 只能叠 0.45s，
  M 落在 9.55s。共享 `transitionOverlap` 还不够 —— 指示线和 `packMain` 要共用
  完整的布局函数 `TimelineState.packedStarts`。
- **磁吸模式下插空判定用未夹的中心**：块顶到时间线左端后位置就不动了，中心恰好
  压在第一段的中点上，`center < mid` 永远为假 —— 用户往左拖到底也插不到最前面。

## 4.5 工具栏三个开关的默认值（2026-09-18 用户拍板）

**默认只开「吸附」**，磁吸和链接默认关：

| 开关 | 默认 | 为什么 |
| --- | --- | --- |
| 磁吸 `magnetEnabled` | **关** | 它会自动合拢主轨的空档，而这个用户的剪法就是**留着间隙**（2026-08-23 已记的产品口径）。默认开着等于每次落地都把他留的缝吃掉。 |
| 吸附 `snappingEnabled` | **开** | 只在拖到边缘附近时帮忙对齐，不改变任何自动行为，留着纯赚。 |
| 链接 `linkageEnabled` | **关** | 它会把分离出来的音频一起拖走。分离音频本来就是为了单独动它。 |

三个都**不进工程文件、也不写 UserDefaults** —— 每次启动回到代码里的字面量，
所以那三行就是产品口径本身，顺手「改回 true」会静默改掉整个剪辑手感。
守卫在 `checks/timeline-drag-wiring.sh` 第 11 节。

## 5. 视口与缩放

- **弹性尾部只给自由落点的轨道**（画中画/音频/磁吸关掉的主轨/形状）：拖到右缘
  时内容宽度按投影落点临时长出去，松手由新的 `project.duration` 接管。磁吸主轨
  不给 —— 它只能插进现有故事线的某条缝，扩太远只会把插入指示线滚出视野。
- **缩放只有 `VideoEditProject.setPixelsPerSecond` 一个入口**，夹进
  `zoomRange`（4…120）。`pps` 掉到 1 以下时位移换算会被 `max(pps, 1)` 兜底，
  1:1 跟手当场坏掉（鼠标走 100 点、块只走 50 点）。捏合、工具栏按钮、滑块共用它。
- **自动滚动的心跳要有多条退路**：正常松手 `stop()`、视图消失 `onDisappear`、
  视图树被拆 `dismantleNSView`、对象被回收 `deinit`，外加 tick 里自查滚动视图
  还在不在。少一条就可能在 RunLoop 上留一个 60Hz 的空转 timer。

### 5b. 滚动量的唯一真相：`TimelineScrollGeometry`（现读，不缓存）

手势要用的横向滚动量，一律从 `NSScrollView` **现读**
（`TimelineScrollGeometry.offsetX` → `contentView.bounds.origin.x`），
**不许**再经 `GeometryReader` → preference → `@State` 这条链路缓存一份。

理由：那条链路是**异步观察**，语义是「过一会儿会一致」，而手势回调要的是
「这一拍就得对」。2026-09-18 之前框选的锚点读的就是那个缓存值，结果框整体画到
指针左边、偏差正好等于当时的滚动量（实测滚 667pt 偏 669pt，滚得远一点框直接跑
出视口 = 用户看到的「框选没反应」），见
[2026-09-18-marquee-anchored-at-stale-scroll-offset.md](../bugfixes/2026-09-18-marquee-anchored-at-stale-scroll-offset.md)。

- **只有框选会露馅**：别的手势吃的是 `translation`（相对量）和
  `scrollOffset - originScrollOffset`（差值），同一个错误在它们身上自己抵消。
  所以这条只能靠守卫钉住（`checks/timeline-drag-wiring.sh` 第 9 节），不能指望
  手感测试发现。
- **推滚动也归它**（`scrollHorizontally(by:)`）：`TimelineAutoScroller` 只剩
  「什么时候推、推多快」的心跳，回调不传滚动量 —— 传了就等于又多一个来源。
- 捏合缩放那条是独立路径（事件监视器里拿不到视图树，只能按坐标 hitTest 现找
  滚动视图），暂时豁免；它自己不消费滚动量做坐标换算。
- **推一个轴的时候，另一个轴一个字都不许碰 —— 连夹一下都不行。** 内容比视口窄时
  SwiftUI 会把它居中（那一轴的 `bounds.origin` 是负的），顺手夹进 `[min, max]`
  会把它按回 0：实测表现是「纵向自动滚动刚一启动，整条时间线横着跳了 121pt」。

### 5c. 纵向滚动与「钉住」的两块（2026-09-18）

轨道多到一屏放不下时，时间线**双向滚动**（`ScrollView([.horizontal, .vertical])`）。
在那之前只有横向，下面的轨道被整条裁掉，用户只能靠放大窗口去看
（[2026-09-18-timeline-cannot-scroll-vertically.md](../bugfixes/2026-09-18-timeline-cannot-scroll-vertically.md)）。

- **轨道头列和标尺钉住不动**，各自减/加**同一个**纵向滚动量（轨道头 `-offsetY`、
  标尺 `+offsetY`）。两边是同一份 `rows` 排出来的，所以只要是同一个数就永远对得
  上，不用各自去量位置。标尺必须自带**不透明底**：它盖在滚上去的轨道行上面。
- **只有这两块订阅 `TimelineScrollGeometry`**（`@ObservedObject`）。时间线主体用
  `@State` 持有它、**不订阅** —— 订阅了的话滚动的每一帧都会把整棵时间线视图树
  （所有块连同缩略图与波形）重建一遍，就是第 0 节那条老约束在另一个轴上重演。
- **轨道头列不许决定时间线的高度。** 它的固有高度是所有行加起来（十来条轨 500pt
  往上），裸摆在 `HStack` 里就会让整条时间线按这个高度要地方，`VSplitView` 给不了，
  **工具栏和标尺当场被挤出窗口**。所以它画在 `Color.clear` 的 overlay 上（弹性
  固有尺寸），超出部分 `.clipped()` + `.contentShape`（只裁绘制不裁命中，见 §1b）。
- **纵向的坐标换算与横向对称**：内容 y = 视口 y + `offsetY`。框选的锚点/当前点、
  跨轨拖动的目标行判定都要补这一项 —— 漏了的表现和 §5b 那个 bug 一模一样，
  只是换成纵向。
- **自动滚动两轴一起**：拖块/拉框到视口上下缘同样要滚，不然纵向滚出来的新轨道
  够不着。纵向边缘带（26pt）比横向（44pt）窄 —— 时间线本来就不高。
- **播放跟随只碰横向**。`ScrollViewProxy.scrollTo(_:anchor:)` 的锚点是双轴的，
  正在看下面几条轨时一按播放，画面会被连带拽回顶上。改走
  `TimelineScrollGeometry.scrollHorizontally(to:animated:)`。
- **播放头的把手画在标尺里**（`TimelinePinnedRuler`），竖线才留在滚动内容里。
  标尺是不透明的（要盖住滚上来的轨道行），把手画在内容顶部的话，纵向滚下去之后
  就藏到标尺后面了 —— 竖线还在，抓手没了。两边都按同一个 `clock.time * pps`
  画，所以永远在同一条 x 上。

## 回归清单（改这些代码后过一遍）

- 拖右把手 238pt（10s 的量，默认缩放）→ 时长正好少 10s，不是 5s。
- 拖动中块边缘连续跟手，无跳变；缩略图/波形不闪，松手 ~200ms 后刷新。
- 磁吸开着时移动块，**邻居不动**（松手才归位），青色占位框（宽度 = 被拖素材
  落地后的长度）跟着中心走；松手后块正好落在框里。
- 磁吸关掉在同一条轨上把块拖**过**邻居：指针越过后块落进另一侧的间隙，
  不用再借道画中画。
- 磁吸关掉把 6 秒的块对准一个 5 秒的间隙（块中心悬在间隙上）：块落在间隙
  起点，右侧内容松手时自动让位 1 秒；间隙左边的一动不动；⌘Z 一步全回来。
- 跨轨拖动：目标行出现等长的虚线占位框，松手后块正好落在框里 —— 目标轨上
  有占位被挤开时，框要提前画在挤开后的位置（不许框在一处、落在另一处）。
- 块移动手势 1:1 跟手：快速甩一趟，块中心始终在光标下（注入验证做法见
  gui-smoke-testing.md，误差应在 1 像素级）。
- 画中画轨的块左右拖，边缘对上主轨块的边缘时出现通高黄线，且块**吸在线上**；
  起点对起点、终点对终点、起点对终点四种配对都要试。
- 拖到视口左右缘停住：时间线自动横向滚动，块继续跟着光标（内容要够长，
  先放大到内容宽于视口）。
- 磁吸关掉把块拖成乱序再回放：预览各时刻画面都在（守卫在
  check-preview-composition / check-project-file 里）。
- 多选两块一起拖：松手后**两块都在新位置**（别被组内伙伴顶回原地），
  相对错位不变，⌘Z 一次全退回。
- 轨道空白处拉框扫过几块：拖框中被扫到的块**当场**描白框（松手前就有反馈），
  松手后正好选中它们；⌘ 拖框是在原有选择上加选。
- **先把时间线横向滚出去一大段（放大后滚到最右），再拉框**：框必须正正画在光标
  底下（误差 1 像素级），框中的也是光标扫过的那几块。滚动量一旦从缓存里读，
  这一条就会整体偏出一个滚动量。
- 拉框拖到视口左右缘停住：时间线自动横向滚动，框跟着内容继续长，选中集合
  跟着变（内容要够长，先放大到内容宽于视口）。
- 隐藏一条轨（眼睛）再拉框扫过它：那条轨上的块**一个都不许**被选中。
- 加到十来条轨（一屏放不下）：**两指竖滚能上下走**；轨道头列和轨道行始终对齐；
  标尺钉在顶上不动；工具栏和标尺都还在（别被轨道头列挤出窗口）。
- 滚下去之后再拉框：框正正画在光标底下（**两个轴**都要对），框中的是光标扫过的
  那几块。
- 拖块/拉框到视口**下边缘**停住：纵向自动滚动，新露出来的轨道能选中/能落；
  这期间**横向位置一动不动**。
- 滚到下面几条轨时按播放：画面不许被拽回最顶上（纵向位置不动，横向该跟才跟）。
- 框选一片（含形状块和字幕 cue）再拖任意一个：三类同时挪同一个位移，
  相对错位不变；译文轨的字幕跟原文轨走到同一时刻；⌘Z 一次全退回。
- 框住一片按 ⌫：剪辑、形状、字幕**一起**消失（不是只删一类），⌘Z 一次全回来。
- 刀片模式（B）下在空白处拖：不出框，点在块上照常落刀。
- 视频 + 链接音频一起换轨：音频跟到同一时刻（拖完点播放听一句，别只看轨道）。
- 形状块拖动：亮线、吸附、松手不跳，与剪辑手感一致。
- 把块拖到工程末尾之外：自由落点的轨允许（内容跟着长），磁吸主轨不允许。
- 插一张**竖版**图片进主轨，放大到它横贯视口：在它正上方点标尺，播放头必须
  落到点击处（不许变成选中图片）；点块身仍是选中。横向死区探针：右键，
