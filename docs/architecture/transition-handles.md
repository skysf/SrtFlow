# 主轨转场：借余料与首尾帧定格补足

> 改转场的容量、可用判定、`expandingTransitionHandles`、或者两条渲染管线里主轨段的
> 截取方式之前必读。代码在 `Sources/SrtFlow/VideoEditTransitionHandles.swift`。
> 来历：[2026-09-20 转场预览有、成片没有](../bugfixes/2026-09-20-transition-preview-export-divergence.md)
> 定下了「借余料」；2026-09-23 用户拍板「余料不够用首尾帧定格补足」。

## 两条不变的前提

1. **不挪用户摆好的片段**（2026-09-20 用户拍板）。位置是用户的意图，转场不能靠
   把后一段往前拉来制造重叠。
2. **两条渲染管线看同一份时间线**。预览合成（`VideoEditCompositionBuilder.build`）
   和导出图（`VideoEditExportGraph.plan`）都在入口调 `expandingTransitionHandles()`，
   之后看到的都是「两段真的相叠 d」的渲染副本，原有那套按相叠写的 xfade 链和淡变
   逻辑一行不用改。**渲染副本不写回用户的工程。**

## 三种几何

判据是两段当下的相对位置（`seamTolerance` = 0.02s 以内算相接）：

| 几何 | 怎么做 | 容量（最长能放多久） |
| --- | --- | --- |
| 中间有空隙 | 不是一条缝，不替用户合拢 | `.notAdjacent` |
| 已相叠（磁吸排的） | 转场就发生在重叠区上，不借料、不展开 | 较短那段 × 0.45，且 ≤ 2s |
| **首尾相接**（磁吸关着，默认） | 借余料 + 不够的定格补足，展开成相叠 | 较短那段 × 0.4，且 ≤ 2s；短于 0.125s 放不下（`.tooShort`） |

首尾相接时的长度上限为什么是 `0.4 × min(a, b)`：展开之后 `transitionOverlap` 那条
45% 的护栏会按**展开后**的长度再夹一次，夹到了成片就会比时间线长出一截；推导见
2026-09-20 那篇案例。定格补出来的那一截和借来的素材一样算进展开后的长度，这笔账
不变。

## 首尾相接：先借余料，不够的定格补足

`TimelineState.transitionExtension(outgoing:incoming:duration:)` 决定两侧各向外延伸
多少、其中多少是定格。两侧之和恒等于转场时长 d，所以展开之后正好相叠 d，片段位置
和总时长都不变。

- **余料够**（出场段尾料 + 进场段头料 ≥ d）：照旧先吃出场段的尾料、不够再借进场段
  的头料（`borrowSplit`），**一帧都不定格** —— 有真素材就不用静止画面。
- **余料不够**：两边的余料全用上，差额用**首尾帧定格**补（Premiere 的 repeated
  frames、达芬奇的 freeze 同一个做法）。差额优先把窗口摆成「缝 ± d/2」，和时间线上
  的遮罩一致：出场段一侧先补到 d/2，剩下的归进场段。
  - 零余料时就是两边各定格 d/2：接缝前半程 A 照常播、B 的首帧定住淡入；后半程 B
    照常播、A 的尾帧定住淡出。

**压黑是例外**：首尾相接的缝上它走「原地斜坡」—— 两段各自一道 alpha 渐变，底下
垫的就是黑底（`rendersAsDipInPlace`），不借料、不定格、不相叠。所以片段极短（叠化
这类放不下）时压黑仍然能用，那是容量里唯一还「与种类有关」的地方。

2026-09-23 之前，余料不够就拒绝：零余料的缝上只有压黑能用，别的卡片一律灰掉，
提示「把其中一段裁短一点」。用户的反馈是「按别的剪辑软件，只要两段贴在一起就可以
应用转场」，于是改成现在这样。

## 定格在两条管线里怎么做

定格只在渲染副本里存在：`EditClip.renderHoldHead` / `renderHoldTail`（时间线秒）。
渲染副本的 `sourceStart` / `sourceDuration` 已经把定格那两截算进去了（`timelineDuration`
因此是整段长度、源时间 ↔ 时间线时间的换算照旧是线性的），真正从素材里取的那一段
是 `renderSourceStart` / `renderSourceDuration`。

| | 画面 | 声音 |
| --- | --- | --- |
| 预览合成 | 按真素材范围插；两头各插**一帧**再 `scaleTimeRange` 拉长成定格（`insertHold`） | 定格那两截留空段 |
| 导出图 | 按真素材范围 `trim`，变速和 `fps` 之后接 `tpad=start_mode=clone` / `stop_mode=clone` | `adelay` 垫在前、`apad` 补在后 |
| 预渲染中间片 | 走预览合成那一套，定格自然带进中间片 | 声音不走中间片 |

两条硬约束（`checks/transition-handles-wiring.sh` 中段钉着）：

1. **定格字段只许 `expandingTransitionHandles` 写。** 用户的工程里它恒为 0。别处一写，
   它就会跟着工程、撤销栈、剪贴板到处走，而存盘又不存它 —— 预览和成片各说各话。
2. **两条管线都要消费它。** 漏一条，那条管线里定格那一截就是黑的。

## 已知未对齐

余料够、但只从一边借（例如只有出场段有尾料）时，渲染出来的转场窗口整个落在接缝
的一侧（`borrowSplit` 先吃尾料），而时间线遮罩画的是「缝 ± d/2」。两者最多差 d/2：
遮罩说转场从缝前开始，成片里它从缝上才开始。这是 2026-09-20 就有的行为，这次没动
（改成对称借料会让一部分原本不用定格的缝开始定格）。要修的话，改 `borrowSplit` 的
分配，同时核对 4b / 4b-2 两组断言。

## 守卫

| 守什么 | 在哪 |
| --- | --- |
| 容量、展开的纯值规则（零余料可用、太短放不下、余料够时不定格、定格两边各 d/2、总长不变） | `scripts/check-video-fade.sh` 4b–4c |
| 成片里定格那一截真的有画面（白→黑、黑→白两组抽帧），总长不变 | `scripts/check-video-fade.sh` 4b-5 |
| 预览里同一场景、同一时刻、同一个数 | `scripts/check-preview-composition.sh` 定格那一组 |
| 拖转场卡片的落点（零余料能落、太短不能落、按正在拖的那张卡算） | `scripts/check-timeline-snap.sh` §28 / §30 |
| 两条管线都在入口展开、定格字段只有展开函数写、两条管线都消费定格 | `checks/transition-handles-wiring.sh` |

### 人工回归清单（发版前实机）

- [ ] 两段**没裁过**的素材首尾相接：叠化、推移、擦除、闪白的卡片都是亮的，拖到接缝
      上能落；预览和导出的成片里，接缝两侧各有一小截静止画面（首帧 / 尾帧），总时长
      不变。
- [ ] 裁过、两头有余料的两段：转场期间没有静止画面。
- [ ] 很短的段（< 0.125s）两侧：只有黑场过渡可用，提示「这两段太短」。
