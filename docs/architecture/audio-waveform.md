# 波形与深度缩放

> 2026-09-23 落地。改 `VideoEditWaveformData.swift`、`VideoEditWaveformDetail.swift`、
> `VideoEditTimelineWaveform.swift`、时间线的缩放上限 / 标尺 / 缩略图之前必读。
> 方案与产品决策见 [声音编辑方案](../plans/2026-09-23-audio-mixing.md)。

## 一、为什么以前「放到最大还是不够」

两个根因，缺一不可：缩放上限只有 120pt/秒（24fps 下一帧 5pt）；波形**每段固定读成
240 根柱子**（8kHz 单声道），和缩放无关 —— 60 秒的段放多大都是那 240 根，放大只是把
每根拉宽。只放开上限是没用的。

## 二、数据：一个文件读一次，三层精度

| 层 | 在哪 | 精度 | 什么时候用 |
| --- | --- | --- | --- |
| 多级峰值 | `WaveformStore` / `WaveformPeaks` | 第 0 级 64 个采样一个桶，往上每级 4 并 1，共 8 级 | 一个像素盖得住一个桶（48kHz、Retina 下约 375pt/秒以下） |
| 原始采样块 | `WaveformDetailCache` | 真实采样，1 秒一块，按需读、最多留 48 块 | 放大到一个像素盖不满一个桶 |
| （没读到时） | — | 先拿第 0 级的桶顶着 | 原始块读回来之前的那一两帧 |

- **按文件读，不按段读**：裁切、分割、挪位置、缩放都不重读 PCM；同一个文件被几段引用只读一次。
- **原生采样率、最多两个声道**：更多声道读的时候让 AVAssetReader 混成立体声（要给它
  `AVChannelLayoutKey`）。
- **粗的几级是 min/max 合并，不是平均**：单采样的尖峰在每一级都看得见（`check-waveform.sh`
  逐级钉着；反向验证：合并改成只取第一个桶 → 第 1–7 级全红）。
- **按块存（每块 16384 个桶，48kHz 约 22 秒），写完即不可变**：解码途中把已写完的块交给界面
  先画（长录屏从左往右长出来），交出去的只是一串引用，不整份拷贝。
- 原始采样块的起点**按读出来的时间戳算**，不按请求算：压缩音频从包边界起读，可能早一点。
- 缓存有上限：多级峰值按估算字节 LRU（400MB），原始块 48 块 LRU。

## 三、画：Logic 的样子，只画看得见的那一段

- **以中线上下对称的连续填充**：上沿是每个像素列的最大值、下沿是最小值（真实 min/max），
  不是柱子。放到原始采样那一层时，每个像素取真实采样的 min/max —— 正弦画出来就是一条正弦
  （2026-09-23 离屏渲染：用 64 采样的桶画 4800pt/秒，220Hz 正弦成了乱跳的折线，这正是要
  原始采样块的原因）。
- 纵向刻度：幅度开 0.7 次方再画（小信号抬一点，满幅仍是满幅）。
- **立体声**：波形区 ≥ 40pt 时拆成 L / R 两条，矮于此合成一条（默认 34pt 的音频行拆开就是
  两条细线）。
- **画的是「听到的声音」**：段音量 / 音量曲线、渐入渐出、**轨道推子**都乘进去
  （`EditClip.heardGain`）。乘完超过 0 dBFS 的列**涂红** —— 不播放也看得出哪儿会爆。
  总推子不乘（它不属于哪条轨，总的爆音看总电平表，见 [推子与电平表](audio-mixer.md)）。
  这一点与 Logic 不同（Logic 的波形不随自动化变），是有意的。
- **波形铺满块宽、不留左右边距**：它的 x 直接就是「离段起点多少秒 × pps」，放大到一帧 200pt
  之后，2pt 的边距就是一段看得见的错位。
- **只画 `context.clipBoundingRect` 那一段（硬约束）。** 块在放大后能有几百万点宽。
  2026-09-23 探针实测：
  - Canvas 只光栅化可见条带（视口外扩到 128pt 的格子），但**闭包拿到的是整宽**，每滚 128pt
    重跑一次；整宽画的话 10M 宽时一次 370ms、内存只涨不退（270 → 1080MB），滚动卡成幻灯片。
  - `clipBoundingRect` 就是那条可见条带，**用的是 Canvas 自己的局部坐标**（嵌在带 `.offset`
    的块里也对），滚动时闭包会被自动重调，不需要任何状态。只画这一段：像素逐点一致，内存平，
    10M 宽滚动 733ms（理想 667ms）。
  - 所以**不许为了「知道看得见哪儿」去订阅滚动量**（那会让滚动的每一帧重建整棵时间线视图树，
    见 [拖动手势](timeline-drag-gestures.md) §5c）。
  - 纯色 / 描边 / 位图（块底色、选中框、缩略图）在 1000 万点宽照样正常，不用裁；
    SF Symbol 这种随宽度放大的矢量图在 1M 以上会整块空白，别让它随块宽缩放。
  - 守卫：`checks/timeline-drag-wiring.sh`「波形只画可见条带且走多级峰值」。
- 块内装饰不吃事件（`allowsHitTesting(false)`），同 [拖动手势](timeline-drag-gestures.md) §1b。

## 四、深度缩放的另外三样：上限、标尺、缩略图

- **上限 4800pt/秒**（原来 120，24fps 下一帧约 200pt），常量与理由在 `VideoEditZoom`：
  再往上没意义，预览合成的时间刻度是 1/600 秒，剪点不能更细。**滑杆是对数刻度**（线性的
  话原来的整个区间挤在最左 2%），工具栏按钮每下 ×1.5，⌘− / ⌘= 同一个动作。
- **标尺**（`RulerScale`，纯值）：按缩放挑最细、但两个标签至少隔 76pt 的一档；一秒以下
  **按帧**分档（1 / 2 / 5 / 10 帧、半秒），标签写 `mm:ss:ff`。先换成整帧再拆，差一点点到
  60 秒的刻度不许截成 `00:59:23`。Canvas 同样只画可见条带。
- **缩略图**（`ThumbnailPainter` + `ThumbnailTileCache`）：以前整段均分成至多 24 张，放大 40
  倍之后一张图被拉到一万多点宽、只剩中间一条横缝。现在：
  - 每格宽 = 行高 × 画面比例，**只取、只画看得见的格子**；
  - 每格取哪一帧按网格对齐（`ThumbnailGrid`）：比一帧细按帧，比一帧粗按 2 的整数次幂秒
    —— 缩放时网格只在翻倍 / 减半时才变，捏合的每一拍不用把整屏重取一遍；
  - 新图回来之前拿缓存里**时间最近的一张**顶着（不闪黑）；请求后到的先取（此刻看得见的
    那几格），排队超过 96 张就扔掉最老的（早滚出视野了）。

## 五、回归

| 检查 | 守什么 |
| --- | --- |
| `scripts/check-waveform.sh` | 用 ffmpeg 现造的「每个采样都知道该是多少」的素材：声道不串、静音是 0、单采样尖峰在 8 级里都在、跨块接缝不丢峰值、5.1 混成立体声、原始采样块的起点与内容逐采样对得上、读不了的文件照样结束流 |
| `checks/timeline-drag-wiring.sh` | 波形、标尺、缩略图按 `clipBoundingRect` 裁；波形走 `WaveformStore`；装饰仍 `allowsHitTesting(false)` |
| `scripts/check-timeline-snap.sh`（深度缩放一节） | 缩放区间 4…4800（外部真值）、标尺分档（默认 5 秒、最大一帧、30fps 下 5 帧）、`mm:ss:ff` 标签不截错、缩略图网格按帧 / 2 的幂、网格在同一个 2 的幂区间里不变 |

**人工回归**（自动化够不着，发版前实机验证）：

- [ ] 默认缩放下音频块是一条上下对称的连续波形，不是柱子；把音频轨拉高过 40pt 左右，
      立体声素材拆成上下两条。
- [ ] 放大到最大：人声 / 音乐看得见一个个周期（一条起伏的线），滚动流畅，没有「先糊后清」
      之外的闪烁。
- [ ] 把段音量或曲线推到让峰值过 0 dB：那几段波形涂红；拉回来红就消失。
- [ ] 拖轨道推子：松手后那条轨上所有块的波形一起变高 / 变矮。
- [ ] 一小时的长录屏：波形从左往右长出来，界面不卡。
- [ ] 捏合 / ⌘= 放到最大：标尺按帧标 `mm:ss:ff`，缩略图一帧一格清清楚楚，不是一张拉长
      的横缝；捏合过程中缩略图不闪黑。滑杆从左拖到右是均匀的放大。
