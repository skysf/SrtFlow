# 视频轨：主轨与上层轨是对等的（画中画的取消）

> 2026-09-17 产品决策。改轨道模型、时间线行结构、轨道配色或预览点选之前必读。

## 决策

**取消「画中画」这个概念。** 上层视频轨不再是叠在角上的小窗，它就是**另一条
和主轨对等的视频轨** —— 内容一样铺满画面，差别只有叠放次序。

用户原话：「我希望也不要有画中画这个概念，就当作是另外一个类似于主轨道就行了。
然后内容也应该像主轨道那样是铺满屏幕的。」

## 已经对齐的

| 方面 | 现在 |
| --- | --- |
| 默认摆放 | 等比 contain 铺满画布、居中，与主轨**同一份账**（`defaultPlacement`，不再有 `isOverlay` 分叉） |
| 留空处 | 不补黑，露出下面那一层（导出侧不许给上层轨加 `pad`） |
| 行高 | 主轨和上层轨共用 `videoRowHeight`，轨道头上下拖一起动 |
| 图标 | 都是 `film`。上下叠放次序由行的位置表达，不需要第二种图标 |
| 颜色 | **一轨一色**（下节） |
| 画面渐变 | 任何轨都能设（`docs/architecture/video-fades.md`） |
| 菜单 | `Add to Upper Track…`（原 `Add Picture-in-Picture…`），落点仍是播放头 |

## 还没对齐的（第二步，尚未实施）

1. **轨内转场**：`setTransition` 只写 `state.mainClips`，导出只给主轨拼 xfade
   段，预览的接缝分派也只跑主轨。上层轨两段之间目前加不了转场，跨轨拖动会
   静默清掉 `transitionAfter`（`VideoEditTimelineEdits.relocateClip`、
   `VideoEditProject.toggleOverlay`）。
   技术前提已验证：`xfade` 在 rgba 上行为正确，alpha 走干净的线性斜坡
   （实测 255→204→127→76→0）。真正的工作量在于整条上层轨要改成「分节 →
   透明补隙（`color=black@0`）→ concat/xfade → 一次性 overlay」，音频同构。
2. **磁吸**：`packMain()` 只排主轨。已定口径是**每轨各自 pack**，磁吸开着时
   不保证轨间对齐。

> 单段的渐入渐出是**第一步就做掉**的折中：它解决了「上层轨满幅之后进出是全屏
> 硬切」这个最扎眼的问题，代价只有完整转场的两成。

## 轨道配色

**色号绑轨道身份，不绑行号。** 存在 `EditLane.colorIndex` 里，
`assignMissingTrackColors()` 在读盘和每次状态提交后补齐（幂等）。

- 补号规则：同类里取**最小未占用号**。删掉中间一条轨，活着的轨**不换色**；
  新开的轨捡回刚空出来的号，而不是一路往后漂到色相表尽头去撞色。
- 主轨恒定占用视频色号 0（它不是 `EditLane`，没地方存；而「最底下那条轨永远
  是这个颜色」本身可预期）。上层视频轨因此从 1 起补。
- 视频轨和音频轨**各占一段互不重叠的色相带**：先让人分清「这是画面还是声音」，
  再分清「第几条」。
- 色相表的顺序按「先分得最开」排，不是按色相递增 —— 常见工程只有两三条轨，
  前几个色号必须一眼分得清。
- 用在两处：时间线上块的填充、轨道头的色条。**色条不能省** —— 空轨在时间线上
  一个块都没有，只有它能说明那是哪条轨。预览里的选中框保持统一的青色，不跟
  轨道走（混在一起反而更难读）。

补号必须在**读盘**那一步做，不能等第一次编辑：`perform` 里的补号会和用户那次
改动一起进撤销栈，撤一下颜色就没了。

## 上层轨盖住主轨：正常语义，以及它的代价

上层段满幅不透明时，那段时间主轨就是看不见 —— 这是标准 NLE 的 V2 语义，不是
bug。连带一个必须补的洞：

**预览里点画面只会命中最上面那一段。** 所以 `ClipTransformCanvas.selectClip`
提供 **⌥ 点击在命中的那一摞里轮换**（到底再绕回最上面）。没有它，被盖住的主轨
在预览里**选不中**。做成轮换而不是「只往下一层」：三层以上照样够得着，也不用
记按了几次。提示只在真有东西叠着（`visibleClips.count > 1`）时才挂 —— 平时在
预览里拖框的人不需要每次悬停都弹一条。

## 没有迁移

这是一次**语义换代**，工程格式升到 v10，**不做向下兼容的迁移**（用户明确选的
「干净改」）。`placement == nil` 的含义从「角落小框」变成「铺满画布」，
`overlayFraction`/`overlayAnchor`/`OverlayAnchor` 连同导出的九宫格表达式全部
删除。老工程读得进来（`decodeIfPresent` 会忽略多出来的键），但里面没手动摆过
的上层段会**变成铺满** —— 这是决策本身，不是缺陷。

反过来的方向由版本闸门挡住：只认 v9 的旧版打开新工程会把上层轨画回角落小窗，
成片当场不一样，所以 `requiresFormatVersion10` 无条件为真。
