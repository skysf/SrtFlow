# 轨道块标记（Clip Markers）

轨道上的每一段素材都能打标记：标一个时间点，可换色，可写备注。备注默认没有，
鼠标悬到标记上才弹出来，移开就消失。快捷键 **M** 打，**⌫** 删。

本文只写**长期约束**——这些地方只能这么做，改动前先读完。数据模型在
`Sources/SrtFlow/VideoEditClipMarker.swift`，画法与交互在
`Sources/SrtFlow/VideoEditTimelineMarkers.swift`，生产入口在
`Sources/SrtFlow/VideoEditProject+Markers.swift`。

## 一、标记锚在源时间上，不锚时间线

`ClipMarker.sourceTime` 记的是**素材自己时间轴**上的位置，和关键帧同一套锚定
（见 [关键帧动画](keyframe-animation.md)）。换算靠 `EditClip.timelineTime(atSource:)`。

理由：标记标的是「画面里的这一帧」，不是「时间线上的这一刻」。整段挪窝、变速、
裁头尾之后，标记必须还贴在同一帧画面上。锚时间线绝对时间的话，随手把素材拖一下，
所有标记就跟内容脱节了，用户得重标一遍。

由此推出的三条，都在 `checks/ProjectFile` 第 22 节有守卫：

1. **挪窝 / 变速不改 `sourceTime`**，只改换算关系。
2. **裁到窗口外的标记不画但不删。** `visibleMarkers` 只返回落在
   `sourceStart ..< sourceStart + sourceDuration` 里的；`markers` 保留全部。
   裁切随时会被撤销或再拉回来，顺手删掉的话用户只能重标。
3. **分割时两半各带一份完整标记表**（`TimelineState.split` 里的
   `right.markers = left.markers`），各自只画自己窗口里的那些。少了这一行，
   切一刀就丢标记。

代价（和关键帧完全相同，接受）：两半都留着完整表，所以把左半的右边界重新拉长、
盖回右半的地盘时，同一枚标记会在两段上各画一次。

## 二、标记不进合成，也不进导出

标记是编辑期的标注，`VideoEditCompositionBuilder` / `VideoEditExporter` 一律不
读它（`scripts/check-project-file.sh` 有 forbid 守卫钉着）。因此：

- 所有写入走 `perform(rebuildsPreview: false)`。改标记会重建一次 AVComposition
  的话，就是拿几百毫秒换画面一帧不变。
- 但它**仍然是要存盘的用户数据**，见下一节。

## 三、格式版本 v8，按需写入

`EditClip.markers` 是 v8-only 数据，登记在
`TimelineState.requiresFormatVersion8`（判据 = 工程里存在任何标记）。

成片一帧都不会变，为什么还要升版本：版本闸门问的从来不是「成片会不会变」，而是
**「旧版拿到新文件会不会毁数据」**。只认 v7 的旧版照常打开，用户随手编辑触发
自动保存，整份标记连同备注文字一起被抹掉——那是纯手工输入、丢了只能重标的数据。
判断标准见 [Transform 复审](../bugfixes/2026-08-04-transform-review.md)。

没有标记的段不写 `markers` 键（绝大多数工程一枚都没有），空备注不写 `text` 键。
颜色存名字不存 RGB，不认识的值退回 `.red`（`LenientCodableEnum`），以后改配色
老工程会跟着变。

## 四、选择是四类互斥的第四类

`EditSelection` 里标记和剪辑、形状、字幕 cue **互斥**。加进去的理由不是画框，
是删除键：`VideoEditProject.deleteSelected` 是 ⌫ 和工具栏垃圾桶的唯一入口，
"选中的是标记" 和 "选中的是整段" 同时成立的话，点了段上的标记再按 ⌫，删掉的会是
整段素材。

失效清理收在 `state.didSet` 的 `pruneMarkerSelection()` 这一个点上（判据是
`isMarkerSelectable`：标记还在、且还落在窗口里）。别指望每个会动到剪辑的操作
各自记得清一次——这正是 PR#22 复审 P2 的病根。

## 五、命中区只有帽子，且必须排在裁切把手之前

标记画成「一道贯穿块的竖线 + 顶上一顶小帽子」。**只有帽子吃事件**，竖线一律
`allowsHitTesting(false)`：

- 竖线若整条吃事件，一段素材上打几枚标记就等于在块上凿出几道拖不动的死缝——
  从那儿按下去既拖不走整段，也扫不了帧。
- `markerStrip` 的 overlay 必须挂在**裁切把手之前**。排在把手后面的话，贴着块
  两端的标记会盖住 8pt 的把手，那一端就再也裁不动了。
- 刀片模式下整条 `allowsHitTesting(false)`：点在标记上也该落下那一刀。

## 六、悬停 peek 的交接

块自己有一圈 `.onContinuousHover` 做扫帧 peek（鼠标扫过就把画面滚到指的那一帧，
见 [悬停影子播放头](../bugfixes/2026-08-08-hover-ghost-playhead-and-delete-key.md)）。
标记的帽子是**可命中的子视图**，指针一进去，块那圈 hover 立刻收到 `.ended`。

所以必须有 `markerHoverTime` 这个仲裁位（`scripts/check-project-file.sh` 有
require 守卫）：

- 指针进帽子 → 标记把 peek 顶到它自己那一帧，块那边的 `.ended` **让位**，
  不许 `endPeek`。没有这道让位，鼠标一碰标记画面就弹回播放头。
- 指针离开帽子 → **照常 endPeek**。指针要是还在块上，下一次鼠标移动会立刻把
  扫帧接回去；指针要是已经走了，画面也不会僵死在标记那一帧。

旁边的关键帧菱形是整条 `allowsHitTesting(false)` 绕开这个问题的，标记绕不开
（它必须能点）。

## 七、备注气泡画在帽子下方，且不吃事件

- 画在**下方**：上方会被轨道行的上边界切掉半截。
- `fixedSize` 让它按文字自然宽度铺开，可以盖到邻块上；对应地，悬着标记的剪辑块
  要把 `zIndex` 抬起来，否则气泡会被后画的块盖住。
- 必须 `allowsHitTesting(false)`。气泡一旦吃事件，它一出现就把指针从帽子上抢走，
  于是 `onHover(false)` → 气泡消失 → 指针回到帽子 → 再出现，肉眼看到的是闪烁。
- 悬停即时显示，不用系统 `.help()`：那有约 1 秒延迟，而且块上已经挂了一个显示
  素材名的 `.help`，两个会互相抢。

## 八、备注文字一次提交一步撤销

编辑框里的中间值不进 `state`。回车、或者气泡被点外面关掉（`onDisappear`）时才调
`setMarkerText` 提交一次。每敲一个字提交一次的话，撤销栈会被一串单字符状态塞满。
只认回车不认 `onDisappear` 的话，用户写完直接点开别处就白写了。

## 九、M 的落点规则

1. 选中的段里，凡是被播放头穿过的都各打一枚（多选 = 批量打）。
2. 一个都没选中（或选中的都不在播放头下）时，退回主轨播放头下那一段。

不跟随鼠标位置：鼠标不在时间线上时 M 会变成哑键，而播放头永远有确定的位置。
同一帧上已有标记时 `addMarker` 自己会挡掉（容差 = 半帧，跟关键帧同一把尺子），
连按 M 不会叠出一摞互相压住、点都点不开的标记。

**链接组不跟着一起打。** 标记是给人看的标注，不是剪辑结构；分离出来的音频段
自动多一枚标记只会让人莫名其妙。这一点和分割/删除的链接语义**故意不同**。

## 十、人工回归清单（自动化够不着，发版前实机过）

按 [GUI 冒烟流程](../testing/gui-smoke-testing.md) 起真窗口验：

1. 播放头停在某段上按 M：块上出现红色标记；再按一次 M 不叠第二枚。
2. 鼠标悬到标记帽子上：画面 peek 到标记那一帧且**不弹回播放头**；移开后继续
   在块上移动，扫帧正常接回。
3. 点标记：弹出小面板；换色即时生效；写一段备注，点面板外面关掉，文字要存住。
4. 悬到有备注的标记上：气泡**即时**出现（不是等一秒），移开即消失，不闪烁。
5. 选中标记按 ⌫：删掉的是标记，**不是整段素材**；⌘Z 能撤回来。
6. 从块上任意非帽子处按下拖动：整段照常跟手，标记不构成死缝。
7. 贴着块两端的标记附近：裁切把手仍然拉得动。
8. 刀片工具（B）点在标记上：落下的是一刀，不是弹面板。
9. 切一刀之后两半的标记各就各位，一枚不丢；⌘Z 撤销后合回原样。
10. 存盘重开：标记的位置、颜色、备注全部还在。
