# 声音：音量、渐入渐出与两条管线的同账

> 2026-08-11 落地渐入渐出，2026-08-12 补 dB 显示与「只换 audioMix」快路径。
> 改 `VideoEditAudioFade.swift`、`addVolumeRamps`、`makeAudioMix`、导出图里
> 任何音频滤镜链之前必读。

## 长期约束

1. **时长的单位是「时间线秒」，不是源秒。** `EditClip.fadeInDuration` /
   `fadeOutDuration` 存的是用户在时间线上看到的长度。变速只改源与时间线的
   换算关系，不该逼用户重算渐变 —— 2 倍速的段设 1 秒渐入，就是时间线上的 1 秒。

2. **生效值只有一个夹紧点：`EditClip.audioFades`。** 预览
   （`AVMutableAudioMixInputParameters.setVolumeRamp`）和导出（ffmpeg `afade`）
   都必须从它取，任何一侧都不许再自己夹一遍。三重收口缺一不可：

   - 非有限值和负数归零（数值框和工程文件都可能喂进 NaN）；
   - 各自不超过段长；
   - **两者之和超过段长时按比例同时收**。只夹单边的话，「渐入 3s + 渐出 3s」
     放在 4s 的段上会算出负长度的中段：`setVolumeRamp` 收到反向 `timeRange`
     直接不生效（整段回到原音量），ffmpeg 那边则是两条 `afade` 重叠、尾巴被
     提前拉到 0。两条管线的坏法还不一样，正是「各夹各的」会掉进去的坑。

3. **存的是意图，夹紧只在读侧。** `VideoEditProject.setAudioFade` 只挡负数和
   NaN，不按当时的段长截断。写入时就截短的话，用户把段拉短再拉长，渐变再也
   回不来了 —— 而这一步在用户眼里只是「撤销了裁剪」。

4. **曲线两边都必须是线性。** `afade` 的默认 `curve=tri` 就是线性，与
   `setVolumeRamp` 的线性斜坡逐样本一致。任何一侧改成等功率/对数曲线，
   立刻就是「预览听着对、成片不对」。`check-audio-fade.sh` 的「渐入中点 =
   半音量」那条断言钉的就是这个。

5. **转场那条边归转场管。** 主轨接缝上有转场时，转场自己就在做交叉淡变，
   用户设的渐变在那一边**不生效**：

   - 不叠加：两段衰减相乘会在接缝处把音量压出一个坑，听感是「转场的地方
     声音断了一下」。
   - 不取较长者：那会静默改写用户设的值，而转场时长本来就是他另外调过的。

   仲裁写在 `AudioFadeWindow.previewMainTrack` / `exportMainTrack` 两个函数里，
   **两者的差别是这块最容易写错的地方**：

   | | 转场那条边 | 为什么 |
   | --- | --- | --- |
   | 预览 | 换成**转场时长本身** | 预览没有 `acrossfade`，交叉淡变就是靠这条斜坡实现的 |
   | 导出 | 换成 **0** | 导出的交叉淡变由段与段之间的 `acrossfade` 做，段内再加一条就是衰减两遍 |

6. **`afade` 必须插在 `atempo` 之后**，且 `st` 用**时间线长度**算。`afade` 读的
   是它在滤镜链上看到的时间轴，而链上 `atempo` 已经跑过。拿源长度算淡出起点，
   2 倍速的段会在一半处就开始淡出，甚至整个落到段外（尾巴根本不淡）。

7. **预览侧：斜坡之前必须先把音量钉住。**
   `AVMutableAudioMixInputParameters` 的第一条斜坡之前音量默认是 **1.0**，而
   AVFoundation 的混音器不硬切增益 —— 它把跳变按一个缓冲区（实测约 17ms）
   平滑过去。所以「起点 0」的渐入会被拉成一条从满音量降到 0 的下坡贴在渐入
   最前面，听感是「砰」的一下（见
   [2026-08-12-audio-fade-in-pop](../bugfixes/2026-08-12-audio-fade-in-pop.md)）。

   `addVolumeRamps` 因此在段起点前一个平滑窗口（`gainSmoothingGuard`，50ms）
   先 `setVolume`。两条不能改的细节：

   - **钉的值分两种**：有渐入钉 0，没渐入钉 body 音量本身。一律钉 0 会让所有
     不从 0 开始的段平白多一个 17ms 软起音。
   - **钉点不能越过上一段**（`previousEnd`，取**同一条合成轨**上的上一段），
     否则会啃掉上一段的尾巴。主轨声音走 A/B 交替两条轨，各自算各自的。

   **ffmpeg 那侧没有这个问题**（`afade` 逐样本算增益），所以这条修复只在预览
   管线里。两条管线在增益语义上不等价，别拿一侧的结论推另一侧。

8. **界面必须说出被抑制的那条边。** 主轨接缝上有转场时，检查器要显示一行说明
   （`VideoEditInspector.fadeNote`），判据与合成/导出同一个来源
   `transitionOverlap`。用户设了却听不出差别，不解释就是「功能坏了」。

## 音量：存线性，显示 dB

**`EditClip.volume` 的语义没变，一直是线性幅度 0…2（1.0 = 原样）。**
dB 只是界面换算，换算只有 `AudioGain` 一份。这样老工程照读，格式也不用升版。

- 界面用 dB 的理由是听感：线性刻度上 −20dB 只占滑杆的 5%，根本没法调；
  dB 是等比刻度，每一段的手感才一致。滑杆因此按 **dB 线性**取值。
- **上限从线性上限反算**（`20·log10(2)` ≈ +6.02 dB），不许写死成整数 6.0 ——
  写死的话线性 2.0 换成 dB 再换回来会掉到 1.995，用户把滑杆推到顶、松手音量
  自己缩一点点。`check-project-file.sh` 里有往返断言钉着。
- **下限 −60 dB 就是真静音**（线性 0），显示成 `−∞ dB`。返回 0.001 之类的
  「近似静音」是错的：用户拉到底就是要没声音。

## 预览：只改音量/渐变时不要重建合成

音量和渐入渐出只进 `audioMix`，**不改合成结构**。走完整重建的话要
`replaceCurrentItem`，画面会闪一下（2026-08-12 用户报告）。所以：

- `VideoEditCompositionBuilder.build()` 顺手记下 `AudioMixPlan`
  （哪些段的声音落在哪条合成音轨上），`VideoEditProject` 留着它。
- 改音量/渐变时走 `refreshAudioMix()`：拿 plan 重算一份 mix 直接赋给正在播的
  `AVPlayerItem`，画面完全不动。三个入口都接了 —— `perform`、`endLiveEdit`
  （拖滑块松手）、`applySnapshot`（撤销/重做）。
- **`makeAudioMix` 必须是两条路唯一的实现**。分开写就会出现「拖完滑块的音量」
  和「下次重建之后的音量」不一样，而这种偶发差异用户几乎描述不清。
  `check-audio-fade.sh` 有一条等价性守卫：同一份改动，快路径的 mix 与整条重建
  出来的包络必须逐点一致。
- 判据是 `TimelineState.differsOnlyInAudioMix`，写法是**「把这几个字段抹平后
  两边完全相等」**，不是枚举「哪些字段算变了」—— 枚举法每加一个新字段就漏
  一次，而漏的方向是「本该重建却没重建」，表现为改了东西预览不更新，
  比闪一下难查得多。
- **静音（Mute）不在快路径里**：主轨和画中画的静音段压根不会被插进合成音轨，
  改它会改结构。

## 时间线上的波形画的是「听到的声音」

`WaveformView` 把 `volume` 和渐变包络乘进柱高，所以拉音量、改淡变时轨道上当场
跟着变。增益**不进** `.task` 的 id —— 改音量不该让它重读一遍 PCM。
音量能推到 +6dB（线性 2.0），柱高要夹住，否则柱子冲出轨道。

## 工程文件

`fadeInDuration` / `fadeOutDuration` 是 **v9** 字段，**按需写入**（值为 0 的段
不写键，缺键按 0 解码 = 关）。登记清单在
`VideoEditFormatVersion.requiresFormatVersion9`，版本表见
[video-edit-project-file](video-edit-project-file.md)。

升版本的理由是标准的那一条：只认 v8 的旧版照常打开，用户随手编辑触发自动保存
就把两个键删光 —— 调好的渐入渐出没了，**成片的声音跟着变**。

## 回归清单

| 检查 | 守什么 |
| --- | --- |
| `scripts/check-audio-fade.sh` | **两条生产管线的真实音量包络**：导出走真实 `plan()` + 真跑 ffmpeg + 解码量 RMS；预览走真实 `build()` + `AVAssetReaderAudioMixOutput` 量 RMS。含变速用例、转场仲裁用例、**段从非零位置起的渐入起点峰值**用例，每组都带「同一时间线去掉渐变」的反例对照 |
| `scripts/check-project-file.sh` | 夹紧规则（含按比例收、NaN、变速）、`afadeSegments` 参数、存盘往返、v9 登记与按需写键、v8 老文件缺键按 0 读、**dB 换算的往返与边界** |
| `scripts/check-audio-fade.sh`（第 5 组） | **快路径与整条重建等价**：同一份音量/渐变改动，`makeAudioMix` 出来的包络与重建出来的逐点一致；以及 `differsOnlyInAudioMix` 对挪位置/裁剪/静音都要判否 |

反例对照不是可选的：只断言「开头很轻」的话，素材本身若是静音起头，断言照样绿。
对照组要求同一条时间线在**去掉渐变后开头就是满音量**。

两条量纲/取样纪律，都是踩出来的：

- **瞬态看峰值，不看 RMS。** 2ms 的满幅爆音只把 100ms 窗口的 RMS 抬到 0.14，
  藏得住。
- **段起点必须有一组落在非零、非 600 时基整格的位置上**（用例里是 1.3337s）。
  全从 0 开始的用例恰好避开了唯一会触发增益跳变的场景。

三次反向验证（2026-08-11 落地时做的，各自确认守卫真的变红）：

1. 导出的 `afadeSteps` 返回空串 → 12 项红（全部导出断言 + 接缝计数）。
2. `addVolumeRamps` 忽略 `fades` → 10 项红（全部预览断言）。
3. `exportMainTrack` 去掉 `suppressing` → 2 项红（接缝处出现两条 `afade`）。

## 人工回归（自动化够不着）

- 在时间线上给一段音乐设 2 秒渐入，**播放预览**确认听感是渐起而不是硬切；
  导出同一条时间线，用播放器听成片的开头 —— 两者应当一致。
- 段被静音（Mute）时音量滑杆和两个数值框应当置灰。
- **改音量或渐变时预览画面不许闪一下**（这是快路径存在的全部理由）。
  正着改、拖滑块松手、⌘Z 撤销，三条都要过。改**位置或裁剪**时闪一下是正常的
  （那是真的在重建）。
- 数值框的三条输入路径（打字回车、上下箭头、按住横向拖）都要能改到值，
  拖调整次只进一步撤销（合同见
  [inspector-scrub-number-field](inspector-scrub-number-field.md)）。
