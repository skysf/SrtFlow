# 生成的字幕长什么样：去标点、断句、一行多长、显示时间、几段素材同时有字

> 2026-09-26 起的长期约束。改 `SrtFlowCore` 里的 `SubtitlePunctuation` / `SubtitleBreaks` /
> `SubtitleLineMeasure` / `SubtitleSegmentationConfig` / `SubtitleCueTiming` / `SubtitleSourceOverlap`，
> 或者改字幕生成面板（`SubtitleTranscriptionSection`）之前必读。
> 为什么这么定、调研了哪些软件和规范：[方案](../plans/2026-09-26-subtitle-generation-style.md)。

用户原话：「正常字幕是没有标点符号的」「像这个是不是拆成三个字幕更好呢，不要全部连在一起」，
长度和时间「用户体验最好的方式来，符合主流字幕的样式」。主流样式以 Netflix 英文 / 简体中文字幕规范为准，
BBC 字幕指南对照。

## 一、流水线：先断句、后去标点、最后排时间

```
词流（素材源时间，识别器原样：英文词带前导空格、标点附着在词尾；中文一个字一个词、逗号是单独的「 ，」）
  → segment：每段素材各自 ⓪估开口（停顿被识别器并进了相邻的词）①成句 ②按逗号分小句、太短的并
             ③放不下的在最好的地方切 ④去标点成字幕
  → assemble：几段素材合成一条轨 ⑤同时有字的只留一条 ⑥统一排显示时间、标阅读速度告警
```

- **断句要看标点，所以标点最后才去。** 缓存里的词流一直带着标点（`TranscriptSidecarStore`），去标点只发生在
  成字幕的那一刻；量一行多宽也按去完标点的字算（`SubtitleBreaks.lineFits`）。
- **显示时间在整条轨上排，不在每段素材里排**：两条之间留多少、说完延多久要看整条轨上的前后邻居。
  `segment` 出来的每条，开始 = 第一个词开口、结束 = 最后一个词说完。
- 参数集版本 `SubtitleSegmentationConfig.version` = 3（进 `GenerationSnapshot`）。改默认值要升版本。

### 估开口：停顿被并进了相邻的词（`SubtitleSpeechOnset`，2026-09-26）

识别器给的词时间把静音也包了进去（ffmpeg `silencedetect` 对照实测，[案例](../bugfixes/2026-09-26-pause-stretches-next-word.md)）：
**句号后面的停顿并进下一个词的开头**（「At」识别成 1.68–2.94，声音 2.83 才有），**句末的词后面的停顿并进它自己的结尾**
（「box.」30.00–30.90，声音 30.35 就停了）。直接拿识别器的开头当字幕起点会早出来，拿整段中点判归属会把
片段边上的词判错（「That's」丢了）。所以分段前先给每个词估两样：

- 只估**被拉长的词**：比宽松词长还长（0.2 秒 + 每个字母 0.06；中日韩每个字 0.15）；
- **停顿在哪边看标点**：前面句号问号 / 列表第一个词 = 重，逗号类 / 中间空 ≥ 0.15 秒 = 轻；它自己（或紧跟的纯标点词）
  收句 = 后面重、逗号类 = 后面轻。前面重 → 开口 = 词尾 − 宽松词长（**宁早勿晚**），归属看词尾那一截的中点；
  后面重 → 开口不动，归属看开头那一截；一样重不估；两边都没标点但比宽松词长多 0.5 秒以上的按前面算。
- `attributeWords` 用估出的中点判归属、开口当起点；**缓存里照旧存识别器原样的时间**。实测误差：多数早 0.1–0.3 秒。

## 二、标点（`SubtitlePunctuation`）

| | 规则 |
| --- | --- |
| 去掉 | 逗号、句号、分号、冒号，全角半角都算（`，。；：, . ; :`） |
| 句中的 | 换成**一个半角空格**；右引号、右括号前面不补；左引号、左括号后面不补；不留两个连着的空格 |
| 行尾的 | 直接删（后面只剩空格、别的停顿标点、右引号右括号也算行尾） |
| 留着 | `？！`、引号、书名号、括号、省略号（半角 `...` 统一成 `…`）、人名间隔号 `·`、**列举中间的顿号 `、`**（行尾的删） |
| 不动 | 数字里的点、逗号、冒号（`89.2`、`1,000`、`10:30`），英文缩写（`U.S.`、`e.g.`、`a.m.`，`SubtitlePunctuation.isAcronym`），网址里的点，撇号（`you're`） |
| 顺手清掉 | 中文转写把 `，？` 吐成带前导空格的词：`越来越多 ，把` → `越来越多 把`，`大小呢 ？` → `大小呢？` |

- 依据：Netflix 简体中文规范第 12 节 "Do not use commas or periods. Use one single space instead."
  （顿号可以用在列举里、不许在行尾；问号叹号要用）。**英文那行也去**是用户拍板（两行看着一致），
  Netflix 英文规范本身是保留标点的 —— 这是我们有意偏离的一条。
- **只在两处去**：生成（`SubtitleSegmenter.appendCue`）和机器翻译落字（`SubtitleRetranslation.apply`）。
  **用户手打的、外挂导入的一律不碰**（改字走 `SubtitleTrackEditing.setText`，不经过这里）。翻回来去完标点是空的，不落空句。
- 不做开关（用户拍板「按你的来」：默认就去）。

## 三、断句（`SubtitleBreaks`）

1. **成句**：词尾是 `. ! ? … 。！？`，或词间停顿超过 0.6 秒。缩写的点不算句号（`in the U.S. today` 是一句）。
2. **句内按逗号分小句**：词尾是 `， , ； ; ： :` 就在它后面分开 —— 一条一个小句，**译文也跟着顺**
   （翻译是一条一条送的，半句送过去会译坏：`…a continent that has` 译成「有一个大陆」，`that has` 丢了）。
3. **太短的小句并到旁边**：**在屏上留不到** `minClauseDuration`（1 秒：到下一个小句开口、最多说完再多停半秒，
   最后一个小句看到下一句开口或素材结尾）、或只有一个词（中文不到三个字）算太短。看的是能留多久、不是说了多久：
   「a car」只说了 0.53 秒但后面是停顿，照样单独一条；「to me」紧接着下一句，只能留 0.4 秒，并到旁边。
   优先并给同样太短的邻居，其次并给更短的那边，一样就给前面那条；并了放不下就不并。
   例：`Even a gym, to me,` → `Even a gym to me`；`Oh,` 并进后面那句；`I walk, I run, I cycle` → `I walk` / `I run I cycle`。
4. **还放不下的**（超字数、超画面宽度、超 7 秒）：先找**最少切几段**能全放下，再在这个段数和多一段之间挑
   **总代价最小**的切法（动态规划，`PieceTable.bestCuts`）；多一段要多付 0.5。**不许贪心先切第一刀**：
   `At the bottom of the world lies a continent`（43 个字符，比一行多半个字）贪心会切成
   `…lies / a continent that has never / belonged to anyone`，现在是 `At the bottom of the world / lies a continent / that has never belonged to anyone`。
   代价 =（各段字数偏离平均）² + 短于最短显示时长的罚分 + 每一刀的代价：

   | 断在这里 | 代价 |
   | --- | --- |
   | 停顿后面（词间空 ≥ 0.25 秒；中文的停顿藏在拖得 ≥ 0.45 秒的那个字里） | −0.35 / −0.25 |
   | 英文连词、关系词、介词前面（`and` `but` `that` `which` `when` `in` `for` `with`…；**`of`、`to` 不算**：`bottom / of the world`、`going / to walk` 反而拆散） | −0.3 |
   | 中文连词、话题转换词前面（如果、因为、所以、但是、然后、于是、最后、现在…） | −0.3 |
   | 中文句末语气词后面（呢、吗、吧、啊、呀、嘛 —— 转写常常不给标点，这里就是句号该在的地方） | −0.35 |
   | 英文一条以冠词、限定词、介词、连词（含从句连词 `until` `because` `when` `if`…）、物主代词、助动词、主语代词结尾（`a` `the` `all` `to` `of` `my` `has` `I`…） | +1 |
   | 英文句中两个大写开头的词连着（专有名词：`South / Pole`、`New / York`；`I` 不算） | +0.5 |
   | 中文一条以连词、介词、代词结尾（如果、在、把、和、我、这个、一个…；**只认整词**：「现在」不算「在」） | +1 |
   | 中文一条以助词开头（的、了、吗、呢、着、过、们…） | +1 |
   | 中文一条以「的」结尾 | +0.4 |

5. **中文只在词边界上切**：转写出来一个字一个词，用系统自带的分词（`NLTokenizer`，`wordBoundaries`）找词边界，
   不会切出「如 / 果」「大 / 幅度」。**中文还是英文按整句判**，不按一刀两边的字判（「电脑 MC | 的芯片」两边
   字母比汉字多，按两边判会当成英文、漏罚「的」起头 —— 实测踩过）。

## 四、一行多长（`SubtitleLineMeasure` + `SubtitleSegmentationConfig`）

- 生成的字幕**一律单行**（2026-08-09 的决定没变），放不下就拆成下一条。
- **两把尺子，两个都得放得下**：
  - 规范的字数 `units`：全角算 1、半角（字母、数字、空格、半角标点）算 0.5。英文每行 42 个字符（空格也算）= 21，
    中文每行 16 个字（Netflix）。按**转写实际用的语言**选档（`generation(languageCode:)`：zh / yue / wuu / ja / ko 走 16，
    其余走 21；日韩没单独核对过）。
  - 画面放得下的宽度 `ems`：全角 1、半角约 0.6、空格约 0.3（按字号的倍数估）。App 那边按**原文轨当前的字号和边距**、
    画面宽高比算出一行放得下几个字号宽（`SubtitleLineFit`，可用宽度只从 `SubtitleFrameGeometry` 取，
    不另算第二份），留 5% 余量。**竖屏自动更短**（默认样式下竖屏一行只放得下约 8 个汉字）。
- 生成之后再改字号、边距，已生成的不重排 —— 放不下时由渲染自动折行。

## 五、显示时间（`SubtitleCueTiming`）

| | 规则 |
| --- | --- |
| 最短 | 5/6 秒（Netflix：24 帧的 20 帧），往后有空档就借 |
| 最长 | 7 秒，超过就在断句那一步拆 |
| 说完多停 | 0.5 秒（后面没有紧跟着的下一条时） |
| 两条之间 | **至少 2 帧**（按工程帧率，`frameDuration` 生产上来自 `TimelineState.frameRate`）；空档不到 0.5 秒就把前一条延到只剩 2 帧（Netflix 的 chaining）—— 两条之间要么只差 2 帧、要么至少半秒，不闪 |
| 最晚 | 收在它那段素材在时间线上的结尾（素材切走了，字幕不跟过去） |
| 阅读速度 | 按最终显示时长算：英文 20 字符/秒（= 10 units/秒）、中文 9 字/秒；超了打 `readingSpeedWarning`，不假装满足 |

## 六、几段素材同时有字：只留一条（`SubtitleSourceOverlap`）

以前（原生字幕生成方案 §5.4）是「V1 全部保留」，同一时刻几段素材的字叠在一起显示。用户说「生成的字幕有时候会有重叠」，
工程里实测：录屏自带的声音转出来的「我」「you」压在旁白上、录屏里放的歌转出来的歌词压在旁白上。
主流剪辑软件出来的都是**一条不重叠的字幕**，现在也一样：

1. **零碎杂音不要**：一两个词（中文两个字以内）、识别置信度低于 0.3 的。实测录屏杂音 0.07–0.27，正常旁白 0.8 以上。
2. **谁识别得更清楚留谁**：置信度高的先占位；后来的跟**别的素材**已经占住的撞上了（前后各让 2 帧），只留它没被占的
   最长一段，剩下不到原来一半就整条不要（字没法跟着截，只截时间的话一句话挤在半截时间里读不完）。
   置信度一样看轨道秩（主轨在前）。**不按轨道先后定**（Premiere 是按轨道先后）：我们的主轨是视频自带的声音，
   旁白多半在音频轨上，按轨道定会让录屏杂音压过旁白。
3. **同一段素材里前后相接的两条不算撞上**，它们之间的 2 帧归显示时间那一步。
4. 不和旁白重叠的歌词会留下（语音识别分不出唱和说；剪映是单独的「识别歌词」，Descript 干脆不转歌词）——
   用「只用选中的片段」排除，或生成后手删。
5. 手打、导入的字幕不走这里；它们要是叠在一起，画面上照旧按排序合同（方案 §9）叠着显示。

## 七、转写哪些声音

- **按 V 藏起来的段不转写**（[段的显隐](clip-visibility.md)的落点表里有这一行，
  [案例](../bugfixes/2026-09-26-subtitle-generation-transcribes-hidden-clips.md)）；链接关着、只藏了视频时，
  分离出来还显示着的音频听得见，照样转写。生成之后再藏的段，已有的字幕不动。
- **只用选中的片段**：面板上选中的片段里有听得见的，就出现「只用选中的片段（N 段）」，**默认不勾**
  （随手点过一段不该让生成只转写那一段）。勾上就只转写、只分段这几段（`SubtitleAudibleClips.selectedSoundClipIDs`
  → `soundClips(in:only:)`，转写和分段认同一份范围，扫描守卫钉着）；链接开着时连带链接组。整条字幕照旧整体替换，替换前照样先问。

## 八、已知不足（有意没做的）

- **生成之后挪、裁、删素材，字幕不跟着走**（方案 §5.4 的老限制）。用户这次说「先不用」。南极工程里 122 秒以后的字幕
  全晚了 2.5 秒就是这个原因，重新生成就对上了（重新生成会覆盖手改过的字幕）。
- **转写没给标点的中文长句**，只能靠停顿、语气词、连词和系统分词来断；分词把「大容量」「四分多钟」切开的地方
  （`把大 / 容量`、`四分多 / 钟`）还会断在那里。
- 双语上下顺序（字幕组的主流是中文在上、英文小一号）：用户拍板**不改**，仍是原文在上。
- 开口时间是估的（第一节「估开口」）：没有真去读音频，多数早 0.1–0.3 秒；要做到逐帧准得读音频能量找开口，没做。
