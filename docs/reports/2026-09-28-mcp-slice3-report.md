## 怎么验的

1. **CI**：49e6c1e、592f756、4332091、315daab、0b48fe9、b82f659、f45032c、6cdaf66 各轮五组全绿。884f3b1 那轮红在预览性能 ratchet 的内存峰值上
   （busy 286.4 → 321 MB，已知的虚拟机波动，[ratchet 文档](../architecture/preview-perf-ratchet.md)第六节），下一轮绿；
   0994af1 那轮红在 audio-fade 第 8b 组「换了源格式…60 秒没读完」（那次改动不编译声音代码，下一轮 b82f659 同一份代码全绿；
   这条 9-24 也红过一次，记进了 [推子与电平表](../architecture/audio-mixer.md)「已知的偶发」）。
2. **本机**（照「重的交给 CI」）：增量 `swift build`、`checks/` 下全部扫描守卫；新加的纯值自检编成只跑这几组的小二进制跑过：
   转写的分页与格式、句子怎么拆（`SpeechTranscript`）、鼓点（合成的 120 / 90 BPM 点击、128 和 92 BPM 带摇摆的鼓组、一直响的
   单音 —— 最后这个必须回「没有拍子」）、cut_speech 与 cut_to_beat 共 46 项、链接组与 new_audio 各自的回归。每条修复都做了反向验证。

## 撞上的事

- [切开一对链接的段，四块连成一串](../bugfixes/2026-09-28-split-links-every-piece-together.md)：写 cut_speech 时读分割发现。
  右半段原样抄了组号，切几刀之后链接开着删一块 / 拖一块，整串都跟着走 —— 手动的播放头分割、刀片、AI 的 split_clip 都中。
  改成切完按时间重叠重新分组（`LinkRegrouping`，这三处和 cut_speech 都走它）。
- [一次放两首配乐，第二首点名要新开一条轨，却接在了 A1 后面](../bugfixes/2026-09-28-new-audio-lands-on-a1.md)：第一块起就有。
  「这一批开过的轨」记的是副作用（第一首只是因为没有音频轨才开了 A1），改成只记自己要了新开的。
- cut_speech 把两句话之间的「this. This」当成说重了（冒烟抓到的，上面）：前一遍以句号、问号、叹号收尾的不算。
- cut_to_beat 每段 4 拍时第一段回 `beats: 5`：音乐自己第一拍前有 0.24 秒的引子，按「段里有几个拍点」数就多数了一个，AI 会以为
  没照它说的做。改成数头一拍到切口之间的拍子间隔（f45032c，`AIBeatCuts.beatCount`，自检钉着；反向验证 3 项红）。
- 鼓点第一版的三个坑（都在写自检时撞上，没上线）：一直响的单音被当成有拍子（加了「峰值要明显高过中位数」的门）、
  带摇摆的鼓组锁在反拍上（分频带各自归一化）、速度偶尔算到 200 以上（抛物线插值夹在范围里）。
- 转写和生成字幕不能同时跑：临时目录每次开工都整个清掉，所以 transcribe 和生成字幕共用一个任务槽，忙的时候照实说。
- CI 上两次和改动无关的红（上面「怎么验的」第 1 条），都记进了对应文档的「已知的偶发」，认法写清楚了。
- 冒烟时我自己的失误：调用表里在一次**失败的** `cut_to_beat` 后面接了 `undo`，撤掉的是再前一步的放素材，后面几步找不到片段。
  工具失败不登记撤销，是对的；调用表以后在失败之后不接 undo。

## 还差什么 / 已知不足

- **音频库里没有鼓点清楚的音乐**（79 首都是氛围 / 古典），`cut_to_beat` 目前要用户自己的音乐。工具说明叫 AI 先 `listen beats=true`
  看一眼，没有拍子就换一首或手剪。
- transcribe（和靠它的按文字剪、口头禅、说重了）要 macOS 26（SpeechAnalyzer）；macOS 15 上 transcribe 回「要 macOS 26」，
  cut_speech 只剩给时间的 remove / keep（切口不挪进空隙）和删停顿。
- cut_speech 只剪 V1 上的片段，后面的 V1 片段往前补；音乐、文字、字幕不跟着挪 —— 结果里写明了，字幕要重新生成（转写有缓存，很快）。
- 鼓点只认一个稳定的速度（50–200 BPM），中途变速的曲子拍子会漂；一次最多分析 15 分钟。
- cut_to_beat 只改每段的出点、不挑「哪一截最好看」（挑镜头是第四块的画面识别）。

## 之后的调整（2026-09-28，第三块做完后的讨论）

工具到了 40 个之后和用户讨论上限，顺带定了问不问、客户端的权限弹窗（方案第 33–36 条）：

- **不按个数卡，守三条**：不许有两个长得像的工具、只读的和写文件的不放进同一个工具、说明总长度有上限。实测 40 个工具的
  说明是 5.4 万字符（约 1.5 万 token），合并工具省不了多少上下文；上限定在 7.2 万字符（约 2 万 token），`ProtocolChecks` 钉着。
- **只有删文件才问**：导出、新建、另存撞名改成加编号（以前问「替换吗」）；AI 要打开 / 新建别的工程时，手动剪过、没存过的
  那个先存进 `SrtFlow/工程` 再换（以前问「丢掉吗」）；读点名文件夹以外的文件问一次，同意了就记住那个文件夹（`AIReadGrants`，
  重启也记得，设置 → AI 里能删）。会回 `needs_confirmation` 的只剩删文件和读别处的文件两处，扫描钉着。
- **「连接」顺带放行客户端那层**：Claude Code 写 `mcp__srtflow` 进 `~/.claude/settings.json`，Codex 写
  `default_tools_approval_mode = "approve"`；Claude 桌面版写不进去，连上之后提示用户在它的连接器设置里一次设好。
  以前连过、还没放行的显示「已连接 · 每次都会问」。
- skystudioai.com 的功能以后另做一个 MCP，现在不做；fal.ai 的生成工具做成提供方可换、没配就不列出来（第六块）。

验证：扫描段、配置 / 记住文件夹 / 协议三组自检（224 项）在本机跑过；反向验证（把导出改回会问、去掉记住那一行、把总长度上限
压到 5 万、加规则时不加、「太大的文件夹」判断失效）各自当场变红，恢复后全绿。
