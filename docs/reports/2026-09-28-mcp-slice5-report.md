## 探针定下的口径（第 ② 刀）

- **词的标记只从代理方法来**：`AVSpeechSynthesizer.write(_:toBufferCallback:toMarkerCallback:)` 的标记回调在 macOS 26 上一次都没叫过；
  `speechSynthesizer(_:willSpeak:utterance:)` 在 `write` 时照样叫，`byteSampleOffset` 除以 4（单声道 Float32）就是第几帧 ——
  停顿后第一个词的标记正好落在静音结束处（英文「This」0.882 秒、静音 0.66–0.89；中文「这」1.080 秒、静音 0.76–1.06）。
- 标点也会被报成一个「词」（「，」「。」），并进前一个词。
- 回调都在主线程上；标记全在最后那个空缓冲之前；空缓冲来两次，didFinish 在它后面。
- **语速不是线性的**：rate 0.5 = 正常，0.55 已经 1.29 倍、0.6 是 1.59 倍，0.3 只慢到 0.77 倍，0.40–0.45 之间是平的；中文、英文一样。
  改成按实测的表反查之后，要 1.1 倍实测 1.12 倍。

## 第 ③ 刀的探针：Kokoro-82M 和 Qwen3-TTS 0.6B（都走 CoreML，2026-09-28，M1）

用 speech-swift（Apache 2.0）里的 `KokoroTTS`、`Qwen3TTSCoreML` 和它们依赖的 `AudioCommon` 三个模块，拷到临时目录编一个小程序，
**没进仓库**；模型从 Hugging Face 下（它自带的下载器拒绝带子文件夹的文件名，改用自己写的脚本下）。同样四句（中文带货、中文纪录片、
英文带货、英文纪录片），样音放在 `~/Downloads/SrtFlow-TTS样音/`，另有系统的婷婷 / Samantha 当对照。

| | Kokoro-82M（aufklarer/Kokoro-82M-CoreML） | Qwen3-TTS 0.6B（aufklarer/Qwen3-TTS-CoreML） |
| --- | --- | --- |
| 下载 | 333 MB | 1733 MB |
| 加载 | 2.8 秒 | 9–11 秒 |
| 速度 | 一句约 0.4 秒，**实时的约 10 倍**（第一句 1–12 秒：神经网络引擎第一次编译） | 5 秒的声音要 25–38 秒，**实时的 0.15–0.2 倍**；改走 GPU、全部计算单元都一样（每帧 0.1 秒以上，实时要一秒 12.5 帧） |
| 内存 | 常驻约 230–390 MB，加载时峰值约 1 GB | 常驻涨到约 3 GB |

| 克隆 | 不能（固定音色） | 模型能（按说话人向量），但**说话人编码器没有 CoreML 版**，要自己转 |

撞上的一件事：探针第一版把长句按逗号切开分别读，**段尾留着逗号时 Kokoro 读完那个字后又冒出约 80 毫秒的杂音**（用户一听就听出来：
「学完这门课」后面有明显的卡顿声，每个声音都在同一处）。改成放得下 5 秒就整句读、非切不可时先去掉段尾的标点再按标点补停顿，
杂音没了（扫描所有样音的结尾确认）。接进 App 时同样照这个做。

### 撞上的事

- **Hugging Face 的下载器拒绝带子文件夹的文件名**（speech-swift 自带的那个）：探针改用自己写的脚本下。
- **标点贴到了下一个词的开头**（「，你」「. Don't」）：Kokoro 不把标点报成单位，夹在两个词中间的那一截原来整个算给了后一个词；
  改成贴在前一个词后面（和 macOS 那边标点被报成一个词时同一个结果），断句、去标点都认这个写法。
- **句末的词被算到了下一句**：下一段开头 0.05 秒的余量里有一点底噪，按「往回收静音」算词尾时把「minutes.」拉到了 3.50 秒；
  改成每个词带着自己的结束格，词尾不越过它。
- **声音和时长之间差一两格、第一个字偶尔晚 0.1–0.2 秒**：按窗口相关估出来大多差一格（25 毫秒）；所以句尾不按时长硬切，改成在
  最后一个字之后找第一段安静。
- **上传脚本最后一步报 403**：Cloudflare 拦了 Python 默认的 User-Agent，上传本身是成功的；核对时带自己的 User-Agent，加了 `--verify-only`。

## 扫画面里的字（方案第 55 条，第 ④ 刀之后）

- `look text_scan=true`（`AILookText` + 纯值 `AITextRegions`）：字幕带、固定的字、满屏的字；每帧描述里的字带框；`edit_clip focus=text`，
  自动模式里没有人、字多时按字对准（`AISubjectFocus` 加了字这一档），字比窗宽时报 `text_cut`。「看哪个视频」和分镜头共用 `AILookTarget`。
- **拿用户的课程素材校准**（L16 / L19 / L21，复制到 scratchpad 跑真代码）：第一版把居中的幻灯片标题当成顶上的字幕、把幻灯片下半截的字
  算进字幕带、台标因为 OCR 只认出 3–17 / 24 帧而漏掉。改成字幕带只认下面正中、先拿掉固定的字、固定的门槛三成、会动的报几处之后：
  三个文件都报出底部的中文字幕带（y 0.82–0.96 一带，`crop bottom 0.19`），L21 的「Studio」报成在左下和右下之间跳，满屏的字 92–100%。
  全分辨率裁四个角再认并不更好（试过，没采用）。24 帧约 12 秒。
- 自检（`TextScanChecks`）：字幕带 / 固定的字 / 满屏的字互不混、不变的一行不算字幕、顶上的标题不算字幕、跳角的水印、叠两行的台标按读的
  顺序并、没人字多对准字、脸优先、角落一小块字不算字多、focus=text、宽出去多少。
