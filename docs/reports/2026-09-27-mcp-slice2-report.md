   新加的纯值自检（铺满 / 黑边 / 主体 / 看 / 听，共 129 项）编成一个只跑这几组的小二进制跑过，全过。

   各 140 像素黑边的遮幅船，没动用户的文件夹）：

     文字（`image=false`），黑边上下各 0.125，还读出了船上的「SKY EXPLORER」。

## 撞上的事

- [拼图函数叫 `sheet(`，被 sheet 语言守卫当成了 SwiftUI 的 `.sheet`](../bugfixes/2026-09-27-contact-sheet-name-trips-sheet-guard.md)：
  按调用名扫的守卫误报，改名 `draw`。
- 「听」的窗最初按 50ms 切：跨在「响 / 静」交界上的均方桶会把能量按帧数摊进隔壁的静音窗，算出来的静音段两头各缩
  一截（纯值自检写到一半时按数算出来的，没上线）。改成窗和均方桶对齐（两桶一窗，约 43ms）。
- Vision 的 `perform` 同步卡线程、等 Vision 自己队列上的活，照「阻塞的媒体读取」的规矩放进新开的
  `MediaReadQueue.analysis`，没进 Swift 并发的线程池。
- [GBK 字幕被当成 UTF-16 读成乱码](../bugfixes/2026-09-27-gbk-subtitles-read-as-utf16.md)：写 read_document 的自检时
  撞上的老 bug（剪辑页、字幕编辑、烧录、批量转换都中），编码识别收成 `TextDecoding` 一处。
- [段上画了音量曲线时，AI 调 volume_db 听不出变化](../bugfixes/2026-09-27-ai-volume-ignored-on-curved-clips.md)：
  第一块就有，写 edit_clip 的音量曲线参数时发现；改成和检查器一样整条平移。
- [烧录页存好的字幕样式，要先去烧录页转一圈，剪辑页才用得上](../bugfixes/2026-09-27-remembered-subtitle-style-waits-for-burn-in-page.md)：
  做 AI 的压缩 / 烧录（要以用户记住的设置为底）时发现的老 bug，改成队列创建时读回来。
- 「读点名文件夹以外的文件要先问」在 read_document、look、listen、add_clips 里各抄了一份，压缩 / 烧录 / 转换还要再用
  三次：抽成 `AIWorkspace.confirmReading`，七处都调它。

## 还差什么 / 已知不足

- 9526b2e 之后的工具还没在测试版上实测过（后台模式、读文稿、整理文件、访达选中、其余设置、推子关键帧、形状、复制、
  定格、音乐库、压缩烧录转换）：要出新的测试版再走一遍；访达选中第一次要用户自己点系统框。
- 音效库 App 里还没有，AI 只能找音乐（工具说明照实说，并叫它别去网上下载）。
- 压缩 / 烧录的进度只在侧边栏角标上，AI 起的任务不把主窗口切到那一页。
- 铺满是一个**固定的窗**：主体在一段里走动大时只提醒、不跟拍（要跟拍得用关键帧，第四块画面识别再说）。
- look 的时间线画面是 App 里重新合成的一份：和预览同一套函数，但没有逐像素对账的自检（要真 App，靠人工回归清单）。
- listen 的电平是 RMS（dBFS），不是 LUFS（没做 K 加权）；说明里写的是 RMS。
